Build a Custom AI Feature

Build one product recommendation feature from start to finish: input and output types, prompt templates, a Lab, a Strategy, an optional retriever and a controller, in that order. The code works for both a standard call that returns a result object and a streaming call that sends text to the screen as it is written.

A Strategy here is the part that picks your application feature. It has nothing to do with the Layer 1 and Layer 2 strategies of the security decision. Decisions are made separately by the decision engine.

What you will build

  • POST /api/recommend: takes a product, a category and the user's preferences, and returns a result object (JSON) with a list of recommendations, a confidence and a reason.
  • POST /api/recommend/stream: for the same input, sends the model's analysis as sentence-by-sentence SSE events, then a JSON result of the same shape at the end.

The example is product recommendation, but the same order applies to any AI feature, such as summaries, classification or code review.

Before you start

  • You need @EnableAISecurity on the application class, contexa.datasource.url in the settings, and one Spring AI chat model. Why, and what happens without them, is in the AI Engine overview.
  • Model connection (provider, key, model name) follows AI model configuration; this page does not cover it.
  • To use step 5 (RAG), you need a vector store (a VectorStore bean, for example PGVector).

Step 1: Input and output types

Input: the context

Extend DomainContext to hold the input data. The only method to implement is getDomainType(), which returns the domain name.

@Getter
public class ProductContext extends DomainContext {

    private final String productId;
    private final String category;
    private final List<String> userPreferences;

    public ProductContext(String productId, String category, List<String> userPreferences) {
        this.productId = productId;
        this.category = category;
        this.userPreferences = userPreferences;
    }

    @Override
    public String getDomainType() {
        return "PRODUCT_RECOMMENDATION";
    }
}

DomainContext already has contextId (a generated UUID), createdAt, userId, sessionId and organizationId (with setters), and a metadata map. Use addMetadata(key, value) to attach more values and getMetadata(key, Class) to read one back with a type. When you fill in the user and session, different users sending the same input do not hit a lock conflict (Checking it), and the default retriever picks only the documents that user is allowed to see.

Output: the response type

Extend AIResponse to define the result the model fills in. The pipeline puts this class's JSON schema into the prompt and converts the model's answer into this class.

@Getter @Setter
@NoArgsConstructor
public class ProductRecommendationResponse extends AIResponse {

    private List<Recommendation> recommendations;
    private double confidence;
    private String reasoning;

    @Getter @Setter
    @NoArgsConstructor
    public static class Recommendation {
        private String productName;
        private String reason;
        private double score;
    }
}
A no-argument constructor and setters are required. The no-argument constructor is used both when the model's answer is converted into this class and when a fallback response is created after a failure. Also, AIResponse.withMetadata() and AIRequest.withParameter() do not accept null values (they are concurrent maps and throw an exception).

Two name tags

A request carries two name tags. The template type (TemplateType) decides which prompt template is used, and the diagnosis type (DiagnosisType) decides which Strategy handles it. Both are simple classes wrapping one name, and they match only when the names are spelled the same.

// Name that picks the prompt template: same text as the template's getSupportedType()
new TemplateType("PRODUCT_RECOMMENDATION")

// Name that picks the Strategy: same text as the Strategy's getSupportedType()
new DiagnosisType("PRODUCT_RECOMMENDATION")

Step 2: Prompt templates

A prompt template builds the text the model sees: the system prompt (role, rules, result format) and the user prompt (this question and its data). A template must be a Spring bean, and if no template has the same name as the request's template type, the call fails with Template matching failed. If you use both standard and streaming, you need two templates.

Standard template

Extend AbstractStandardPromptTemplate<response type>. JSON format instructions made from the response type are added automatically in an <output_format> block at the end of the system prompt, and the system metadata made by the preprocessing step in a <context> block.

@Component
public class ProductPromptTemplate
        extends AbstractStandardPromptTemplate<ProductRecommendationResponse> {

    public ProductPromptTemplate() {
        super(ProductRecommendationResponse.class);
    }

    @Override
    public TemplateType getSupportedType() {
        return new TemplateType("PRODUCT_RECOMMENDATION");
    }

    @Override
    protected String generateDomainSystemPrompt(
            AIRequest<? extends DomainContext> request, String systemMetadata) {
        return """
            You are a product recommendation assistant.
            Analyze the user's preferences and the product category
            and recommend 3-5 products ranked by relevance.
            Give each recommendation a reason and a score from 0.0 to 1.0.
            """;
    }

    @Override
    public String generateUserPrompt(
            AIRequest<? extends DomainContext> request, String contextInfo) {
        ProductContext ctx = (ProductContext) request.getContext();
        StringBuilder prompt = new StringBuilder();
        prompt.append("[Query]\n");
        prompt.append("Product ID: ").append(ctx.getProductId()).append("\n");
        prompt.append("Category: ").append(ctx.getCategory()).append("\n");
        prompt.append("User preferences: ")
              .append(String.join(", ", ctx.getUserPreferences())).append("\n");

        // A value added by the Lab reaches the prompt only if the template reads it (step 3)
        String details = request.getParameter("productDetails", String.class);
        if (details != null) {
            prompt.append("\n[Product details]\n").append(details).append("\n");
        }
        // Documents found by the retrieval step (an empty string if none)
        if (contextInfo != null && !contextInfo.isEmpty()) {
            prompt.append("\n[Context]\n").append(contextInfo);
        }
        return prompt.toString();
    }
}

To leave out the format instructions or the metadata, override shouldIncludeFormatInstructions(request) or shouldIncludeSystemMetadata(request) to return false. To add the format instructions at the end of the user prompt, use appendFormatInstructions(prompt).

Streaming template

Extend AbstractStreamingPromptTemplate and give an example of the result JSON (getJsonSchemaExample()). If you want the schema built from your response type instead, make getOutputConverter() return a BeanOutputConverter (the example is then not used).

@Component
public class ProductStreamingPromptTemplate extends AbstractStreamingPromptTemplate {

    @Override
    public TemplateType getSupportedType() {
        return new TemplateType("PRODUCT_RECOMMENDATION_STREAMING");
    }

    @Override
    protected String generateDomainSystemPrompt(
            AIRequest<? extends DomainContext> request, String systemMetadata) {
        return """
            You are a product recommendation assistant.
            First explain your analysis of the user's preferences,
            then give structured recommendations.
            """;
    }

    @Override
    protected String getJsonSchemaExample() {
        return """
            {
              "recommendations": [
                { "productName": "Example Product", "reason": "Matches ...", "score": 0.95 }
              ],
              "confidence": 0.88,
              "reasoning": "Based on the user's preferences ..."
            }
            """;
    }

    @Override
    public String generateUserPrompt(
            AIRequest<? extends DomainContext> request, String contextInfo) {
        ProductContext ctx = (ProductContext) request.getContext();
        return "Recommend products for category '" + ctx.getCategory()
                + "' based on preferences: " + String.join(", ", ctx.getUserPreferences())
                + buildUserPromptExecutionInstructions();
    }
}
What a streaming template tells the model. Contexa adds rules to the system prompt: explain the analysis step by step in Korean only, and when finished write a single JSON object between ===JSON_START=== and ===JSON_END===. buildUserPromptExecutionInstructions() repeats the same instruction at the end of the user prompt. Contexa handles the markers, and the browser receives plain sentences and the final JSON (The events that arrive). generateSystemPrompt(), which builds the system prompt, cannot be overridden.

Shared helpers

Helpers provided by the common parent of both templates:

  • extractNaturalQuery(request): returns the request's natural-language question, in this order: the value set with setNaturalLanguageQuery() → the parameter naturalLanguageQuery → a default phrase.
  • extractContextInfo(request, contextInfo): if the parameter iamDataContext exists, returns it placed before the retrieval result.
  • isContextType(request, context class): tells whether the request's context is of that type.

Step 3: The Lab

A Lab is the unit of work that gathers domain data and calls the pipeline. Make it a Spring bean extending AbstractAILab<Lab request, response type>, because the Strategy looks the Lab up by class.

@Component
public class ProductRecommendationLab
        extends AbstractAILab<AIRequest<ProductContext>, ProductRecommendationResponse> {

    private final PipelineOrchestrator orchestrator;

    public ProductRecommendationLab(PipelineOrchestrator orchestrator) {
        super("ProductRecommendation");
        this.orchestrator = orchestrator;
    }

    @Override
    public boolean supportsStreaming() {
        return true;   // without this, processStream() fails immediately
    }

    @Override
    protected ProductRecommendationResponse doProcess(AIRequest<ProductContext> request) {
        return doProcessAsync(request).block();
    }

    @Override
    protected Mono<ProductRecommendationResponse> doProcessAsync(AIRequest<ProductContext> request) {
        // standard: six steps
        return orchestrator.execute(request,
                PipelineConfiguration.createPipelineConfig(),
                ProductRecommendationResponse.class);
    }

    @Override
    protected Flux<String> doProcessStream(AIRequest<ProductContext> request) {
        // streaming: four steps
        return orchestrator.executeStream(request,
                PipelineConfiguration.createStreamPipelineConfig());
    }
}

The Lab's request type is up to you. Taking the AIRequest itself, as here, carries the template type, parameters and user information chosen by the controller unchanged all the way to the pipeline (Contexa IAM's policy generation works this way). You can also define a separate Lab request object (DTO), but then the Lab has to build an AIRequest again and copy the parameters over.

Adding data

You can add values from a database or an external API as request parameters. Parameters do not go into the prompt on their own; the template must read them with request.getParameter(name, type), as the step 2 template does.

// productCatalog is a bean of your application (example). Change doProcessAsync like this.
@Override
protected Mono<ProductRecommendationResponse> doProcessAsync(AIRequest<ProductContext> request) {
    String details = productCatalog.describe(request.getContext().getProductId());
    if (details != null) {                       // null cannot be put in
        request.withParameter("productDetails", details);
    }
    return orchestrator.execute(request,
            PipelineConfiguration.createPipelineConfig(),
            ProductRecommendationResponse.class);
}

The order in which a Lab is called

Entry methodOrder
process(), processAsync()validateRequest() (default: rejects null) → preProcess() → doProcess() or doProcessAsync() (default: wraps doProcess()) → postProcess(). Errors are wrapped in LabProcessingException.
processStream()Fails immediately if supportsStreaming() is false → validateRequest() → preProcess() → doProcessStream(). postProcess() is not called.

Step 4: The Strategy

A Strategy is picked by the name of the diagnosis type; it checks the input, finds the Lab, converts the request into the Lab request and hands it over. Extend AbstractAIStrategy<context, response type> and implement seven methods: getSupportedType(), getPriority(), getLabType(), validateRequest(), convertLabRequest(), processLabExecution(), processLabExecutionAsync(). For streaming, also override supportsStreaming() and processLabExecutionStream().

@Component
public class ProductRecommendationStrategy
        extends AbstractAIStrategy<ProductContext, ProductRecommendationResponse> {

    public ProductRecommendationStrategy(AILabFactory labFactory) {
        super(labFactory);
    }

    @Override
    public DiagnosisType getSupportedType() {
        return new DiagnosisType("PRODUCT_RECOMMENDATION");
    }

    @Override
    public int getPriority() {
        return 100;   // if two Strategies share a diagnosis type, the lower value wins
    }

    @Override
    public boolean supportsStreaming() {
        return true;
    }

    @Override
    protected Class<?> getLabType() {
        return ProductRecommendationLab.class;
    }

    @Override
    protected void validateRequest(AIRequest<ProductContext> request) throws DiagnosisException {
        if (request.getContext().getCategory() == null) {
            throw new DiagnosisException(getSupportedType().name(),
                    "INVALID_REQUEST", "Product category is required");
        }
    }

    @Override
    protected Object convertLabRequest(AIRequest<ProductContext> request) {
        return request;   // pass the AIRequest to the Lab as is
    }

    @Override
    protected ProductRecommendationResponse processLabExecution(
            Object lab, Object labRequest, AIRequest<ProductContext> request) {
        return ((ProductRecommendationLab) lab).process(request);
    }

    @Override
    protected Mono<ProductRecommendationResponse> processLabExecutionAsync(
            Object lab, Object labRequest, AIRequest<ProductContext> originRequest) {
        return ((ProductRecommendationLab) lab).processAsync(originRequest);
    }

    @Override
    protected Flux<String> processLabExecutionStream(
            Object lab, Object labRequest, AIRequest<ProductContext> request) {
        return ((ProductRecommendationLab) lab).processStream(request);
    }
}

Execution order and error codes

  1. (Streaming only) If supportsStreaming() is false, STREAMING_NOT_SUPPORTED right away.
  2. validateRequest() checks the input.
  3. The Lab bean is found by the class from getLabType() (AILabFactory).
  4. convertLabRequest() builds the Lab request.
  5. The processLabExecution*() method that matches the entry method is called.
Error codeWhen
STRATEGY_NOT_FOUNDNo Strategy bean handles the request's diagnosis type
STREAMING_NOT_SUPPORTEDStreaming was called but the Strategy's supportsStreaming() is false
INVALID_LAB_TYPEgetLabType() returns a class that is not a Lab
LAB_NOT_FOUNDThere is no Lab bean of that class
EXECUTION_ERROR, ASYNC_EXECUTION_ERROR, STREAM_EXECUTION_ERRORAny other exception during synchronous, asynchronous or streaming execution

On the Strategy path these errors do not reach the caller as they are. A standard call turns any cause into AIOperationException("Pipeline returned unexpected response type"), streaming turns it into an AI_OPERATION_ERROR event, and the cause is in the server log (Checking it).

Step 5 (optional): Adding RAG

The retrieval step calls the retriever registered for the context type, or the default retriever if there is none. The default retriever searches the vector store with the request parameter naturalLanguageQuery (contexa.rag.defaults.top-k, similarity-threshold) and keeps only documents that fit the user, organization, tenant and purpose. For many features, putting this parameter in the controller is enough. Without the parameter it searches with the context's toString() (class name, ID and domain name) instead of a question, and the result is useless.

To change retrieval for your domain, extend ContextRetriever. Making it a bean is not enough for it to be called. You must register it yourself in the registry (ContextRetrieverRegistry) together with the context type.

@Component
public class ProductContextRetriever extends ContextRetriever {

    private final ContextRetrieverRegistry registry;

    public ProductContextRetriever(VectorStore vectorStore,
                                   ContexaRagProperties ragProperties,
                                   ContextRetrieverRegistry registry) {
        super(vectorStore, ragProperties);
        this.registry = registry;
    }

    // Registration makes the retrieval step use this retriever for ProductContext requests
    @EventListener
    public void onApplicationEvent(ContextRefreshedEvent event) {
        registry.registerRetriever(ProductContext.class, this);
    }

    @Override
    public ContextRetrievalResult retrieveContext(AIRequest<? extends DomainContext> request) {
        if (!(request.getContext() instanceof ProductContext ctx)) {
            return super.retrieveContext(request);
        }
        String query = ctx.getCategory() + " " + String.join(" ", ctx.getUserPreferences());
        SearchRequest search = SearchRequest.builder()
                .query(query)
                .topK(ragProperties.getDefaults().getTopK())
                .similarityThreshold(ragProperties.getDefaults().getSimilarityThreshold())
                .build();
        List<Document> docs = vectorOperations.searchSimilar(search);
        String contextInfo = docs.stream()
                .map(doc -> "- " + doc.getText())
                .collect(Collectors.joining("\n"));
        return new ContextRetrievalResult(contextInfo, docs,
                Map.of("retrieverType", "product", "documentsFound", docs.size()));
    }
}

The returned contextInfo is passed unchanged to the template's generateUserPrompt(request, contextInfo) in the prompt step. vectorOperations.searchSimilar(query) with a single string searches 5 documents with no threshold, so pass a SearchRequest as above to use the settings.

Your own retriever does not filter by authorization. Requests with the registered context type skip the default retriever's user, organization, tenant and purpose filtering and its prompt-injection check. If users may see different documents, put that into the search condition yourself. Also, this retriever cannot be created without a VectorStore bean, so the application does not start. The detailed retrieval rules are in RAG and vector store.

Step 6: Opening it with a controller

The controller builds an AIRequest and hands it to StandardStreamingService. Inject the AI entry point as AICoreOperations<context>, the type the bean is declared with (Contexa IAM does the same).

public record RecommendInput(String productId, String category, List<String> preferences) {
}

@RestController
@RequestMapping("/api/recommend")
@RequiredArgsConstructor
public class ProductRecommendationController {

    private final AICoreOperations<ProductContext> aiProcessor;
    private final StandardStreamingService streamingService;

    @PostMapping
    public Mono<ProductRecommendationResponse> recommend(
            @RequestBody RecommendInput body, Principal principal) {
        AIRequest<ProductContext> request = buildRequest(body, principal, "PRODUCT_RECOMMENDATION");
        return streamingService.process(request, aiProcessor, ProductRecommendationResponse.class);
    }

    @PostMapping(value = "/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    public Flux<ServerSentEvent<String>> recommendStream(
            @RequestBody RecommendInput body, Principal principal) {
        if (body.category() == null) {
            return streamingService.errorStream("VALIDATION_ERROR", "category is required");
        }
        AIRequest<ProductContext> request =
                buildRequest(body, principal, "PRODUCT_RECOMMENDATION_STREAMING");
        return streamingService.stream(request, aiProcessor);
    }

    private AIRequest<ProductContext> buildRequest(
            RecommendInput body, Principal principal, String templateName) {
        ProductContext context = new ProductContext(
                body.productId(), body.category(), body.preferences());
        if (principal != null) {
            context.setUserId(principal.getName());
        }
        AIRequest<ProductContext> request = new AIRequest<>(
                context,
                new TemplateType(templateName),
                new DiagnosisType("PRODUCT_RECOMMENDATION"));
        // The question the default retriever searches with
        request.withParameter("naturalLanguageQuery",
                body.category() + " " + String.join(" ", body.preferences()));
        return request;
    }
}
@SpringBootApplication
@EnableAISecurity   // io.contexa.contexacommon.annotation.EnableAISecurity
public class MyAiApplication {
    public static void main(String[] args) {
        SpringApplication.run(MyAiApplication.class, args);
    }
}
  • Strategy path (the example above): AICoreOperations finds the Strategy by diagnosis type, locks so the same request does not run twice at once, and writes the audit start line.
  • Direct Lab path: inject the Lab bean and call processAsync(request) or processStream(request). It skips the Strategy, the lock and the audit line. processStream() is a flow of raw chunks (Flux<String>) not packaged as SSE, so if the screen needs SSE, use the Strategy path or the direct pipeline path.

Choosing the model and generation options

The model and generation options are set with request parameters. Without them, the default chat model and its default options are used.

request.withParameter("preferredModel", "gpt-4o-mini")   // a model name in your model connection settings
       .withParameter("temperature", 0.2)
       .withParameter("maxTokens", 1200);
ParameterMeaning
preferredModelThe model name to use (requestedModelId and runtimeModelId mean the same). If it is not found, a warning is logged and the default chat model is used.
temperature, topP, seedGeneration options (a number or a numeric string)
maxTokensThe maximum number of tokens in the answer
disableRetriesWith true, a temporary failure is not sent again (by default, up to 4 times with backoff)
  • These parameters apply only to standard calls. Streaming always uses the default chat model and its default options.
  • The rules that turn a model name into a real model (a connection with the same name, a copy with only the name changed) and the order in which a model is picked are in Model providers. For connection settings, see AI model configuration.
  • Layer 1 and Layer 2 model settings (contexa.security.tiered.llm.layer1.model and so on) are for the decision engine and are not used for this request (the order in which each request's model is decided).
  • The other parameters for result parsing, failure handling and retrieval are collected in the pipeline's request parameters.

Checking it

Start the application and call both endpoints. If your application's security requires login for this path, send the session cookie or token along.

POST /api/recommend
Content-Type: application/json

{"productId":"P-100","category":"laptop","preferences":["light","long battery"]}
