Streaming: AI Answers on the Screen as They Are Written

How to send the text an AI model writes to the browser sentence by sentence over SSE (Server-Sent Events), followed by a structured JSON result at the end. Covers the server code, the events that really arrive, client code, time limits and troubleshooting.

This has nothing to do with the security decision. Streaming is a way of answering of the general-purpose AI engine that application features call. The security decision (Layer 1 and Layer 2 analysis) is not streamed; the decision engine makes it separately.

What you get

While the model analyzes, sentences appear on the screen one by one, and when the analysis ends the result JSON arrives in one piece. On the server, the controller only has to return the Flux<ServerSentEvent<String>> that StandardStreamingService gives back.

  • Both paths need the StandardStreamingService bean (contexa.streaming.enabled, on by default) and a Spring AI chat model.
  • Both paths use the same streaming pipeline (retrieval → preprocessing → prompt → model call) and the same event format.
  • Calling a Lab's processStream() or PipelineOrchestrator.executeStream() directly gives a flow of raw chunks (Flux<String>) not packaged as SSE. Grouping into sentences, [DONE] and the 5-minute limit are done by StandardStreamingService.

Server code

Controller (Strategy path)

Use the streaming template's name as the template type when you build the request. The full example (context, response type, templates, Lab, Strategy) is in Build a Custom AI Feature.

@PostMapping(value = "/api/recommend/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public Flux<ServerSentEvent<String>> recommendStream(@RequestBody RecommendInput body) {
    AIRequest<ProductContext> request = new AIRequest<>(
            new ProductContext(body.productId(), body.category(), body.preferences()),
            new TemplateType("PRODUCT_RECOMMENDATION_STREAMING"),
            new DiagnosisType("PRODUCT_RECOMMENDATION"));
    return streamingService.stream(request, aiProcessor);   // aiProcessor: AICoreOperations<ProductContext>
}

Direct pipeline

For a feature that one template can answer without a Strategy or Lab. It runs with the default streaming configuration (four steps). The diagnosis type is not used, but AIRequest does not accept null, so put in any name.

@PostMapping(value = "/api/chat/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public Flux<ServerSentEvent<String>> chatStream(@RequestBody ChatInput body) {
    AIRequest<ChatContext> request = new AIRequest<>(
            new ChatContext(body.message()),
            new TemplateType("CHAT_STREAMING"),   // a streaming template bean with this name must exist
            new DiagnosisType("CHAT"));           // not used, but must not be null
    request.withParameter("naturalLanguageQuery", body.message());
    return streamingService.stream(request, pipelineOrchestrator);
}

Streaming in the Lab

On the Strategy path, the Lab must turn streaming on and call the pipeline with a streaming configuration. Without overriding supportsStreaming(), processStream() fails immediately.

@Override
public boolean supportsStreaming() {
    return true;
}

@Override
protected Flux<String> doProcessStream(AIRequest<ProductContext> request) {
    return orchestrator.executeStream(request, PipelineConfiguration.createStreamPipelineConfig());
}

In the Strategy too, override supportsStreaming() to return true and make processLabExecutionStream() call the Lab's processStream() (Building the Strategy).

Reporting an input error right away

If the input is wrong before you call the pipeline, you can return a stream made of one error event.

if (body.category() == null) {
    return streamingService.errorStream("VALIDATION_ERROR", "category is required");
}

The browser receives one event, ERROR: {"error":{"code":"VALIDATION_ERROR","message":"category is required"}}, with no [DONE] after it.

The events that really arrive

Received as is, the product recommendation stream looks like this (a blank line between events).

data:사용자는 가볍고 배터리가 오래가는 노트북을 찾고 있습니다.

data:무게와 배터리 시간을 기준으로 노트북 후보를 비교했습니다.

data:###GENERATING_RESULT###

data:###FINAL_RESPONSE###{ "recommendations": [ { "productName": "…", "reason": "…", "score": 0.92 } ], "confidence": 0.88, "reasoning": "…" }

data:[DONE]
DataMeaningWhat the client does
Text without a markerThe model's analysis, grouped into sentencesAppend it to the screen
###GENERATING_RESULT###The narration ended and the model started writing the result JSONShow "making the result"
###FINAL_RESPONSE### + JSONThe final result. Arrives in one piece after the model's stream endsRemove the marker and read it as JSON
[DONE]Normal endFinish the screen
Starts with ERROR:An error (formats in Troubleshooting)Show the error and stop
  • Line breaks inside the data become spaces. So one event is always a single data: line. Line breaks in the final JSON also become spaces, which does not affect reading it as JSON.
  • The narration is in Korean. A streaming template tells the model to write its narration in Korean only (Streaming template).
  • If the model ends without ===JSON_END===, the collected JSON has its brackets balanced and is sent as the final result.
  • Text after the final result marker is not sent. Narration still waiting in the buffer is dropped too.

The five markers

The markers are constants in StreamingProtocol. Three are used only inside the server and never reach the browser.

ConstantValueWhere it is usedReaches the browser
JSON_START_MARKER===JSON_START===The model writes it before the result JSON (the template tells it to)No
JSON_END_MARKER===JSON_END===The model writes it after the result JSONNo
STREAMING_MARKER###STREAMING###Added to narration chunks inside the server and removed before sendingNo
GENERATING_RESULT_MARKER###GENERATING_RESULT###Emitted when ===JSON_START=== is found in the model's textYes
FINAL_RESPONSE_MARKER###FINAL_RESPONSE###Put in front of the final JSONYes

Client code

To receive a stream from a POST, read the response body with the browser's fetch. The key point is that data without a marker is a body sentence. Check in this order: [DONE] → ERROR: → final result → result-generation notice → sentence.

Reading the stream

const FINAL = '###FINAL_RESPONSE###';
const GENERATING = '###GENERATING_RESULT###';

async function streamRequest(url, body, callbacks) {
  const response = await fetch(url, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', 'Accept': 'text/event-stream' },
    body: JSON.stringify(body)
  });
  if (!response.ok) {
    callbacks.onError?.('HTTP ' + response.status);
    return;
  }
  const reader = response.body.getReader();
  const decoder = new TextDecoder();
  let buffer = '';
  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });
    const lines = buffer.split('\n');
    buffer = lines.pop();                      // the last line may not have fully arrived yet
    for (const line of lines) {
      if (!line.startsWith('data:')) continue;
      const data = line.substring(5).trim();
      if (data && handleEvent(data, callbacks)) return;   // stop at [DONE] or an error
    }
  }
  callbacks.onComplete?.();
}

// Returns true when the stream has ended
function handleEvent(data, callbacks) {
  if (data === '[DONE]') {
    callbacks.onComplete?.();
    return true;
  }
  if (data.startsWith('ERROR:')) {
    callbacks.onError?.(data.substring(6).trim());
    return true;
  }
  if (data.startsWith(FINAL)) {
    callbacks.onFinalResponse?.(data.substring(FINAL.length));
    return false;
  }
  if (data === GENERATING) {
    callbacks.onGenerating?.();
    return false;
  }
  callbacks.onChunk?.(data);                   // data without a marker = a body sentence
  return false;
}

Putting it on the screen

const output = document.getElementById('output');
let text = '';

streamRequest('/api/recommend/stream',
  { productId: 'P-100', category: 'laptop', preferences: ['light', 'long battery'] },
  {
    onChunk: (sentence) => { text += sentence + ' '; output.textContent = text; },
    onGenerating: () => { output.textContent = text + '\nMaking the result…'; },
    onFinalResponse: (json) => {
      try { renderResult(JSON.parse(json)); }    // renderResult is your screen code (example)
      catch (e) { output.textContent = text; }   // keep only the narration if the JSON is broken
    },
    onComplete: () => setBusy(false),           // setBusy is your screen code (example)
    onError: (message) => { output.textContent = 'Error: ' + message; setBusy(false); }
  });
The OSS core does not ship a browser streaming client. Read the stream in your own screens as above. The Contexa IAM admin console contains a client for its own screens (contexa-llm.bundle.js), but it is not a public API. That client also treats data without a marker as body text.

How it flows inside

The registered advisors (BaseAdvisor beans) are attached to the model call. In streaming, a blocking error raised by an advisor before the model call does not stop it; only that advisor is skipped (advisor error handling).

The rules of sentence grouping (SentenceBuffer):

  • When a line ends with a period, exclamation mark, question mark or a Korean sentence ending (습니다., 입니다., 다., 요. and so on), it is sent as one sentence.
  • If no sentence end is found and the text passes 200 characters, what has been collected so far is sent. Text left at the end of the stream is sent too.
  • Chunks that look like JSON (containing ```json or ===JSON, or starting with {") are not sent.
  • The # sign (markdown headings) and control characters are removed, and pieces shorter than 3 characters or made only of punctuation are dropped.

Time limits

  • 5 minutes between events: if no event leaves for the browser within 5 minutes of the previous one (for the first event, of the start), StandardStreamingService ends the stream and sends ERROR: {"error":{"code":"TIMEOUT","message":"Request timed out"}}. This also applies when finishing the result JSON after the narration takes more than 5 minutes.
  • No setting changes it. These 5 minutes are a constant fixed in code (contexa.streaming.timeout is not read).
  • The model stream itself has no limit and no retry. The 60-second per-call limit and the up-to-4 retries of a standard call (Retries) are not used for streaming. If you call executeStream() directly, there is no 5-minute limit either.

Some settings appear in auto-completion but have no effect. contexa.streaming.timeout, contexa.streaming.streaming-marker, contexa.streaming.json-start-marker, contexa.streaming.json-end-marker, contexa.streaming.max-retries, contexa.streaming.retry-delay, contexa.streaming.retry-multiplier and contexa.streaming.sentence-buffering-enabled exist only in the settings class; no code reads them. The time limit is fixed at 5 minutes, the markers are constants, sentence grouping is always on, and streaming does not retry.

Other AI settings, such as model connection, are in AI model configuration.

Checks and troubleshooting

To watch the events without buffering, use curl -N (adjust the address to your application).

curl -N -X POST http://localhost:8080/api/recommend/stream \
  -H "Content-Type: application/json" \
  -d '{"productId":"P-100","category":"laptop","preferences":["light","long battery"]}'
What you seeCauseWhat to do
ERROR: {"error":{"code":"AI_OPERATION_ERROR","message":"Streaming strategic operation failed: …"}}, no [DONE]An error outside the pipeline on the Strategy path: no Strategy found, the Strategy's or Lab's supportsStreaming() is false, an input check failed, and so onFind the cause in the server log
ERROR: {"error":{"code":"AI_OPERATION_ERROR","message":"Strategic streaming operation conflict: …"}}Exactly the same request is already streaming (the Strategy path's lock)Fill in the user and session in the context, or send again after the earlier stream ends
ERROR: Template matching failed followed by [DONE]An error inside the pipeline arrives as text ERROR: cause followed by [DONE]. This one means no streaming template bean has the same name as the template typeMatch the template's getSupportedType() name
ERROR: {"error":{"code":"TIMEOUT","message":"Request timed out"}}More than 5 minutes passed between eventsUse a faster model or a smaller result JSON
Only sentences arrive, no final resultThe model did not write the JSON markersCheck the streaming template's JSON example and the model
The model or temperature put in the request is not appliedStreaming does not use request parameters and uses the default chat modelUse a standard call when you need to choose the model

The error code follows the causing exception: AI_OPERATION_ERROR (AI processing error), TIMEOUT (timed out), INVALID_REQUEST (invalid argument), and INTERNAL_ERROR for anything else (message "An unexpected error occurred"). When the browser disconnects, the server's pipeline subscription is cancelled too.

Changing it yourself

  • Replacing the streaming service: provide your own StandardStreamingService bean and it is used instead of the default implementation.
  • Building your own SSE: create a StreamingContext with the injected StreamingProperties, collect chunks with appendChunk(), and use isFinalResponseStarted(), getSentenceBuffer() and extractJsonPart() to do what the default service does.
