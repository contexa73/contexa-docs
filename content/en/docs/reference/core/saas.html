Connecting Contexa SaaS (Optional)

An optional feature with which a Contexa application sends decision results and statistics to Contexa SaaS and receives threat signals, detection strategies and baseline seeds to use in decisions. It is off by default; every decision feature of Contexa works without it.

Know this first. The sending side (client) of this feature is all in the OSS, but the receiving server is not. The default target is https://saas.ctxa.ai, run by Contexa, and you need OAuth2 client credentials issued by that service to actually send.

At a glance

Turning it on

contexa:
  saas:
    enabled: true
    pseudonymization-secret: ${CONTEXA_SAAS_PSEUDONYM_SECRET}     # at least 32 bytes
    global-correlation-secret: ${CONTEXA_SAAS_CORRELATION_SECRET} # at least 32 bytes
    oauth2:
      client-id: ${CONTEXA_SAAS_CLIENT_ID}
      client-secret: ${CONTEXA_SAAS_CLIENT_SECRET}
  • When on, the endpoint, secrets, OAuth2 settings and scopes are checked at startup; the application does not start if they are wrong. The two secrets are refused when empty, left at the development defaults, or shorter than 32 bytes.
  • Decision forwarding first stores to the outbox table of the Contexa database, then sends. Without the outbox repository nothing is sent.
  • A failed send never stops decision processing.

What leaves the application

  • Pseudonymization: user, session and IP are replaced by tenant-scoped HMAC-SHA256 pseudonyms. For the IP a global correlation key is also made so the same IP can be linked across tenants.
  • Sent as is: the request path, country and city, new-device and impossible-travel flags, Layer 1 and Layer 2 evaluations, the resource ID, user roles, prompt hashes and token counts, and so on.
  • Left out by default: the reasoning text (include-reasoning, default false) and the raw analysis data (include-raw-analysis-data, default false). The prompt context audit sends hashes only, never the prompt text.

Delivery and retries

Decision forwarding prevents duplicates by correlation ID, stores the item as pending in the outbox and sends it after the transaction ends (POST {endpoint}/api/saas/runtime/xai/decision-ingestions, Bearer token).

ResultHandling
SuccessDelivered
429 · 5xx · connection failureSent again with exponential backoff (from 1 second up to retry-max-backoff-ms 60000)
A 4xx other than 429DEAD_LETTER (not sent again)
Attempts reach max-retry-attempts (10)DEAD_LETTER

Retries run every dispatch-interval-ms (30 seconds) for outbox-batch-size (50) items, and only one server runs them in a cluster.

Aggregation and sending run every contexa.saas.baseline-signal.publish-interval-ms, which is 1 day when you do not set it (the 7-day default shown in the Settings Index is not used for this schedule). Seeds received hourly

A limit of the current version. Receiving threat knowledge (contexa.saas.threat-knowledge.enabled) does not pull anything even when on, because the setting is not passed to the decision engine.
