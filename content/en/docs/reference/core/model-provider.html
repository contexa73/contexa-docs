Connecting and Choosing Models

How to connect the AI model providers Contexa uses (OpenAI, Anthropic, Ollama and others) and how to set the primary model and the model of each layer (Layer 1, Layer 2). It also covers how to see which model a request used and how the embedding model is chosen.

At a glance

The words used on this page:

  • Provider: where a model comes from, named openai, anthropic, ollama and so on.
  • Binding: one chat or embedding model created as a Spring bean, together with the names it can be found by (bean name, runtime ID, model ID, aliases). The list of bindings is the catalog (LlmRuntimeCatalog).
  • Primary chat model: the chat model always used when no other model was chosen (bean name primaryChatModel).
  • Layer model: the model set for layer 1 or layer 2. The security decision engine's Layer 1 and Layer 2 and calls that name a layer use it.

Connecting a provider

Spring AI makes the connection. Add the provider starter and set spring.ai.<provider>.*; the provider's model beans are created and Contexa finds and uses them. Contexa has no provider keys of its own such as contexa.llm.openai.*.

# Dependency: org.springframework.ai:spring-ai-starter-model-openai
# Other required settings (contexa.datasource.url and so on) follow the quick start.
spring:
  ai:
    openai:
      api-key: ${OPENAI_API_KEY}
      chat:
        options:
          model: gpt-4o-mini
  • Without any chat model, Contexa's LLM beans (primary chat model, orchestrator) are not created.
  • When contexa.llm.selection.chat.priority names exactly one provider (openai, anthropic or ollama), Contexa sets spring.ai.model.chat to it by default so that Spring AI creates only that provider's chat model. The first provider of contexa.llm.selection.embedding.priority (openai or ollama) becomes spring.ai.model.embedding. A value you set yourself always wins.
  • With contexa.llm.enabled=false the whole LLM auto-configuration of Contexa is off.

Contexa's own Ollama connection

An Ollama chat model can be created from Contexa settings alone, without Spring AI starter settings. The Spring AI Ollama library (OllamaChatModel) must be on the classpath.

contexa:
  llm:
    chat:
      ollama:
        base-url: http://localhost:11434   # setting it turns this on
        model: qwen2.5:7b                  # empty: qwen3:8b
        keep-alive: 10m                    # empty: Ollama's default
  • Setting base-url is the switch. It creates the chat model bean contexaOllamaChatModel and the embedding model bean contexaSharedOllamaEmbeddingModel on the same server.
  • The embedding model name is contexa.llm.embedding.ollama.model (empty: mxbai-embed-large). To run embeddings on another server, set contexa.llm.embedding.ollama.dedicated-runtime-enabled=true and contexa.llm.embedding.ollama.base-url.
  • Note: the binding's model ID of this bean comes from spring.ai.ollama.chat.options.model (otherwise the bean name), not from contexa.llm.chat.ollama.model. To point a layer model name at this bean, write the model ID with Naming bindings.

Choosing the primary chat model

With several providers present, contexa.llm.selection.chat.mode decides which model becomes the primary chat model.

mode valueHow it choosesWhen to use it
dynamic-priority (default)The model of the first provider in priority (default openai,anthropic,ollama) whose bean is ready. When no provider in the list is ready, any binding is used.Several providers, only the order matters
fixedOnly the model of the one provider in priority. With two or more listed the application does not start, and if that provider is not ready no other provider is used and start fails.Exactly one provider must be used
spring-primaryThe binding marked Spring @Primary; with a single binding, that one. With two or more @Primary, or several bindings and none marked, the application does not start.The application already marks a chat model @Primary
Write the value in lower case with hyphens. The conditions that create the primary chat model bean compare with dynamic-priority, fixed and spring-primary. Written as the upper-case enum name (DYNAMIC_PRIORITY, SPRING_PRIMARY), the setting is accepted but no condition matches, and no primary chat model bean is created. 
contexa:
  llm:
    selection:
      chat:
        mode: fixed
        priority: anthropic

The old setting contexa.llm.chat-model-priority is read only when priority is empty (to be removed).

Naming bindings (bindings)

At start Contexa makes one binding for each chat and embedding model bean. Without any setting it finds out the following.

  • Provider: from words in the bean class and bean name. ollama → ollama, anthropic · claude → anthropic, openai · azureopenai → openai, gemini · vertex → gemini, mistral → mistral, bedrock → bedrock, huggingface · hf → huggingface, otherwise spring.
  • Model ID: for chat, spring.ai.openai.chat.options.model (Azure: spring.ai.azure.openai.chat.options.deployment-name · .model), spring.ai.anthropic.chat.options.model, spring.ai.ollama.chat.options.model. For embedding, spring.ai.openai.embedding.options.model (Azure included) and spring.ai.ollama.embedding.options.model. Without a value, the bean name.
  • A binding can be found by its bean name, runtime ID, model ID or any alias.

To change or add names, use contexa.llm.bindings.chat.<ID> (.embedding.<ID> for embedding). When <ID> equals a bean name, or bean-name equals it, the entry becomes that bean's binding and <ID> becomes the runtime ID.

contexa:
  llm:
    bindings:
      chat:
        contexaOllamaChatModel:        # key = bean name
          model-id: qwen2.5:7b         # found by this name
          aliases: [local-small]       # more names
          # provider: ollama             # empty: decided by the rules above
          # primary: true                # chosen by spring-primary selection
          # enabled: false               # this entry is not used
  • When one name (selector) belongs to two bindings, the application does not start (Duplicate chat runtime selector '…'). Keep bean names, runtime IDs, model IDs and aliases unique.
  • When the bean a bean-name points to does not exist, a WARN line is logged and the entry is skipped.

Setting the layer models (Layer 1, Layer 2)

Layer models are set with contexa.security.tiered.llm.layer1.model · layer2.model; left empty, the primary chat model is used. Each layer can also have a backup.model. How the security decision engine uses them is in Decision Engine: a different model for each layer; this section explains how a name becomes an actual model.

To mix providers, make each layer model name the same as a binding's model ID. Below, layer 1 is Ollama while layer 2 and the primary chat model are OpenAI (with both starters, spring-ai-starter-model-openai and spring-ai-starter-model-ollama).

spring:
  ai:
    openai:
      api-key: ${OPENAI_API_KEY}
      chat:
        options:
          model: gpt-4o-mini        # model ID of the OpenAI binding
    ollama:
      base-url: http://localhost:11434
      chat:
        options:
          model: qwen2.5:7b         # model ID of the Ollama binding
contexa:
  llm:
    selection:
      chat:
        priority: openai,ollama     # the primary chat model is OpenAI
  security:
    tiered:
      llm:
        layer1:
          model: qwen2.5:7b         # same name as the Ollama binding → Ollama
        layer2:
          model: gpt-4o-mini        # same name as the OpenAI binding → OpenAI
  • When a name matches no binding, a copy of the primary chat model sends that name to its own provider. For example, with an OpenAI primary chat model and a layer model qwen2.5:7b but no matching binding, OpenAI is asked for qwen2.5:7b.
  • Checked at start. When a layer model (layer1.model · layer2.model) cannot be made, start stops with … cannot be used: no chat runtime binding has this model id and the primary chat model cannot be copied with it …. Backup models are not checked at start.
  • contexa.security.tiered.llm.tiered.layer1.timeout-ms · layer2.timeout-ms are used only as the layer time limit of stream() (Calling an LLM). The time limits of the security decision layers are other settings (Decision Engine settings).

How the model is chosen for each request

For every call, the selection strategy (DynamicModelSelectionStrategy) decides in the order below.

  1. Requested model: ExecutionContext.preferredModel, otherwise the metadata requestedModelId → preferredModel → modelId. The metadata runtimeModelId is cleared before selection, so it is not an input. A model that cannot be made is recorded as a failure and selection moves on.
  2. Layer model: the layer comes from analysisLevel → securityTaskType → tier; 1 or less is layer 1, 2 or more is layer 2. With no model set for that layer, go to 4.
  3. Backup model: the layer's backup.model, when the layer model cannot be made
  4. Primary chat model: always the last candidate. With no model at all, null is returned and the call ends with an error. An exception during selection is a ModelSelectionException.
modelSelectionSource valueMeaning
explicit_modelThe requested model
analysis_level:NORMAL and so onThe layer model chosen by analysisLevel
security_task_type:FORENSIC_ANALYSIS and so onThe layer model chosen by the task type
tier:2 and so onThe layer model chosen by tier
One of the above followed by :backupThat layer's backup model
primary_chat_modelThe primary chat model

  • Seeing the bindings: LlmRuntimeCatalog.getChatBindings(); registered models with DynamicModelRegistry.getAllModels() · getModelsByProvider("openai"); one model with DynamicModelSelectionStrategy.getModelCapabilities(name).
  • Logs: a binding that is not ready logs WARN LLM runtime provider '…' binding '…' is not ready; a requested model that cannot be used logs WARN Requested model … not available.

Choosing the embedding model

The embedding model turns documents into vectors (RAG). Because the vector store's dimension is bound to one embedding model, embeddings are fixed to one provider.

contexa.llm.selection.embedding.modeHow it chooses
fixed (default)The one provider in priority (default openai). With two or more listed the application does not start. When that provider's binding is not ready, another embedding binding is used.
spring-primaryThe @Primary embedding binding (same rules as chat)
dynamic-priorityNot supported; choosing it fails at start.

How to match the dimension, and the dimension check at start, are in RAG: before you start.

Provider capability settings

Models take different options. You can change the model lists Contexa uses when it fits the options (provider options). A list is regular expressions joined with commas, and the whole model ID must match.

  • contexa.llm.model-capabilities.openai.max-completion-token-patterns: OpenAI models whose output length is sent as max_completion_tokens. Default gpt-5(?:[.-].*)?,o\d+(?:[.-].*)?.
  • contexa.llm.model-capabilities.openai.default-sampling-only-patterns: OpenAI models sent without temperature · topP. Default: the same list as above.
  • contexa.llm.model-capabilities.anthropic.default-sampling-only-patterns: Claude models sent without sampling values. Default: the list of Claude models fixed in the code.
  • contexa.llm.model-capabilities.anthropic.thinking: the table of thinking and effort each Claude model takes. A list set here replaces the default table.
  • contexa.llm.model-capabilities.anthropic.system-prompt-cache (default true): whether the system prompt is cached when no cache strategy is configured.
  • contexa.llm.model-capabilities.ollama.disable-thinking-patterns: Ollama models sent with thinking off (no default).

For the OpenAI and Ollama lists and the Anthropic sampling list, a JVM system property of the same name or an environment variable (for example CONTEXA_LLM_MODEL_CAPABILITIES_OPENAI_MAX_COMPLETION_TOKEN_PATTERNS) is used first when present.

DynamicModelRegistry — model registration and cache

At start (@PostConstruct) it registers every chat binding of the catalog, then the layer and backup model names under their layer. A layer model name without a binding gets a provider guessed from words in the name (llama, qwen, gemma, mistral, phi, exaone, codellama, deepseek → ollama; claude → anthropic; gpt, o1, davinci → openai; gemini, vertex → gemini; bedrock → bedrock; otherwise spring). The ApplicationContext it receives in the constructor is not used, and the catalog is optional.
