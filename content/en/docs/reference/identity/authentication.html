Login Methods

How to turn on, re-address and check the four single login methods Contexa offers when it owns login: form, REST, one-time code and passkey. It also covers who handles login success and failure, and where the login is kept.

This is a feature for when Contexa owns login (CONTEXA_OWNED). With the default HOST_OWNED, your application's Spring Security handles login and the flows on this page are not built. To keep your application's existing login, see Connecting Your Existing Login. How to write flows and the shared options are in Identity DSL.

Which method when

MethodWhere it fitsDefault orderDefault login processing path
Form .form()Server-rendered login page100POST /login
REST .rest()SPAs, mobile apps, API clients (JSON)200POST /api/login
One-time code .ott()Logging in with a code received by email300Issue POST /ott/generate, login POST /login/ott

Each method becomes its own chain, and the chain with the lower order compares the request first. Shared options such as order, rawHttp and disableCsrf are in Flow options.

Form login

registry
        .form(form -> form.defaultSuccessUrl("/home"))
        .session(Customizer.withDefaults())
        .build();

Without loginPage, Spring's default login page appears at GET /login and posts to POST /login.

OptionDefaultWhen to change
loginPage(String)none (Spring's default page /login)To use a login page the application makes. The processing path does not change
loginProcessingUrl(String)/loginWhen the page posts elsewhere, or the chain scope does not include /login
usernameParameter(String) · passwordParameter(String)username · passwordWhen the page's input names differ
defaultSuccessUrl(String), defaultSuccessUrl(String, boolean)noneWhere to go after login. With true, always there instead of the originally requested address
failureUrl(String)none (Spring's default /login?error)Where to go after a failure
permitAll()offWhen the login page and processing path must be open without authentication
rawFormLogin(...)noneTo work on Spring's FormLoginConfigurer directly. Called several times, only the last one remains
Changing only the login page leaves the processing path at /login. In Spring Security loginPage also sets the processing path, but a Contexa form flow sets the processing path first from contexa.auth.urls.single.form-login-processing (default /login). If you narrowed the chain scope, change loginProcessingUrl as well. 
registry
        .form(form -> form
                .loginPage("/admin/login")
                .loginProcessingUrl("/admin/login")
                .permitAll()
                .rawHttp(http -> http.securityMatcher("/admin/**"))
                .rawFormLogin(login -> login.usernameParameter("email")))
        .session(Customizer.withDefaults())
        .build();

Here the application makes the /admin/login page. To write the response yourself, give successHandler(...) and failureHandler(...) (Success and failure handling).

Checking it

  • Opening a protected address goes to the login page.
  • A successful login goes to defaultSuccessUrl (or the originally requested address), a failure to /login?error.

REST login

Logs in with a JSON body. It is mostly used with the token state, but the session state works too.

registry
        .rest(rest -> rest.defaultSuccessUrl("/app"))
        .oauth2(Customizer.withDefaults())
        .build();
POST /api/login
Content-Type: application/json

{"username": "alice", "password": "s3cret"}
StateSuccess response (200, JSON)
.oauth2(), HEADER transport (default)accessToken, tokenType (Bearer), expiresIn, refreshToken, refreshExpiresIn, tokenTransportMethod, authenticated, redirectUrl, message, username
.session()authenticated, redirectUrl, message, username, stateType (SESSION) + session cookie
  • The login processing path takes POST only. GET /api/login at the same path shows a default login page. When loginProcessingUrl changes the path, the page is at the new path.
  • With .session(), redirectUrl is the page the browser asked for before it was sent to log in (its path and query), when there is one.
  • A failure returns 401 JSON, and the failure response leaves no sooner than contexa.auth.mfa.minimum-delay-ms (default 500 ms), to slow down password guessing.
  • .oauth2() already configures the stateless policy (STATELESS), so you do not set it again with rawHttp. With .oauth2(), contexa.auth.oauth2.client-secret is required (What the token state needs).
OptionDefaultWhen to change
loginProcessingUrl(String)/api/loginWhen your API path rules differ
defaultSuccessUrl(...) · failureUrl(String)noneThe response's redirectUrl and where to go after a failure
securityContextRepository(...)noneA REST flow changes the login repository only when this option is set

Checking it

GET /api/orders
Authorization: Bearer <accessToken>

With the received accessToken the protected API answers; without it you get 401.

One-time code (OTT)

Takes a user name, sends a one-time code by email, and logs in with that code.

registry
        .ott(Customizer.withDefaults())
        .session(Customizer.withDefaults())
        .build();
  • Sending service: the default OneTimeTokenService bean is EmailOneTimeTokenService. It keeps the code in the ctxa_one_time_tokens table of the Contexa database and sends it with Spring mail (spring.mail.*).
  • Recipient: the email address in the user table (users). Without one, the user name is used as the address. A request email that differs from the registered address is refused.
  • When mail cannot be sent: with contexa.auth.ott.fail-on-email-error (default true) issuing fails. With false the code is still created and a warning is logged.
  • Sending limits: at most contexa.auth.ott.email-max-concurrent-sends (default 64) mails are sent at one time. A request waits up to contexa.auth.ott.email-send-wait-seconds (default 5) for a place, and then fails as an undelivered mail does. contexa.auth.ott.email-smtp-timeout-seconds (default 0, not set) limits the connect, read and write of the SMTP conversation; a value is written into the application's mail sender where spring.mail.properties.mail.smtp.*timeout sets none, so it also applies to the application's other mail sent with that sender.
  • Validity: a code is valid for 5 minutes after it is created (Spring's default). contexa.auth.mfa.otp-token-validity-seconds (default 300) is used only for the number of minutes in the email text.
OptionDefaultWhen to change
tokenGeneratingUrl(String)/ott/generateTo change the code issuing path
defaultSubmitPageUrl(String)/login/ott/verifyTo change the code entry page path
showDefaultSubmitPage(boolean)truefalse when the application makes the code entry page
loginProcessingUrl(String)/login/ottTo change the code check path
tokenGenerationSuccessHandler(...)oneTimeTokenCreationSuccessHandler beanTo change the response after a code is created. The default handler moves to the code entry page (defaultSubmitPageUrl). Only when contexa.auth.urls.factors.ott.code-sent is set to an address other than its default (/mfa/ott/code-sent) does it move there, with email, type=code_sent, flow=ott_single and repository in the query
tokenService(...)OneTimeTokenService beanSee the warning below

The request parameter names are fixed: username and token.

To change the sending service, register a bean, not the option. The DSL's tokenService(...) is used only to issue codes; codes are checked with the OneTimeTokenService bean. Giving another service through the option makes the check fail. A registered bean is used for both issuing and checking. 
@Bean
public OneTimeTokenService oneTimeTokenService() {
    // For example, in-memory storage for tests. This service sends no email, so the application delivers the code.
    return new InMemoryOneTimeTokenService();
}

Passkey

Logs in without a password using a WebAuthn passkey. The browser checks the service name (rpId) and the origin it connected to, so both must match the production address.

registry
        .passkey(Customizer.withDefaults())
        .session(Customizer.withDefaults())
        .build();
contexa:
  auth:
    urls:
      factors:
        passkey:
          rp-id: example.com
          rp-name: Example
          allowed-origins: https://app.example.com
OptionDefaultWhen to change
rpId(String)localhostTo the production domain. The setting contexa.auth.urls.factors.passkey.rp-id is where the default comes from
rpName(String)contexa-identityThe service name users see
allowedOrigins(...)http://localhost: + server.port (8080 when unset)The origins browsers connect from. The setting allowed-origins (comma-separated) wins when present
assertionOptionsEndpoint(String) · loginProcessingUrl(String)/webauthn/authenticate/options · /login/webauthnNo effect on a single passkey flow, which uses Spring's default paths
  • Passkey flows do not use the successHandler and failureHandler options (Success and failure handling).
  • With an empty rpId a validator logs an error at startup but does not stop it.
  • With the Contexa database (a contexaJdbcTemplate bean), Spring's JDBC repositories that keep passkey data (JdbcUserCredentialRepository, JdbcPublicKeyCredentialUserEntityRepository) are registered automatically.

Registering a passkey

A logged-in user registers a passkey. The registration page GET /webauthn/register is replaced by Contexa's page.

AddressWhat it does
POST /webauthn/register/optionsCreates registration options
POST /webauthn/registerRegisters a passkey (200)
POST /webauthn/authenticate/optionsCreates login options
POST /login/webauthnPasskey login
DELETE /webauthn/register/{id}Deletes a registered passkey (204)

Success and failure handling

Without successHandler and failureHandler, Contexa picks handlers for the flow type and state. Here single means a non-MFA flow, MFA primary the first login of MFA, and MFA second factor the one-time code or passkey after it.

FlowStateSuccessFailure
Single form, one-time codeSessionSpring's default (moves to defaultSuccessUrl)Spring's default (moves to failureUrl)
Single RESTSessionSessionSingleAuthSuccessHandlerSessionSingleAuthFailureHandler
Single passkeySessionSpring's default JSON response (with the login facts recorded)Spring's default
Single, every methodTokenOAuth2SingleAuthSuccessHandler (issues tokens)OAuth2SingleAuthFailureHandler
MFA primaryBothPrimaryAuthenticationSuccessHandlerUnifiedAuthenticationFailureHandler
MFA second factorBothMfaFactorProcessingSuccessHandlerUnifiedAuthenticationFailureHandler
  • Contexa's handlers answer with JSON when the request's Accept or Content-Type carries JSON or its path contains /api/, and with a redirect otherwise.
  • In a form or REST flow, a given successHandler is attached directly in place of the automatic one. Even in the token state Contexa then issues no token, so that handler owns the response.
  • In a one-time code flow the automatic handler, when there is one, comes first. In the token state the given handler is called first after the tokens are issued, and Contexa writes the response only if that handler did not.
  • For MFA results see MFA result handling.

Where the login is kept

StateRepositoryMeaning
SessionAISessionSecurityContextRepository (always present with @EnableAISecurity). Otherwise the repository given in the option, otherwise HttpSessionSecurityContextRepositoryKept in the HTTP session. Contexa's repository applies the decision when the login is read
TokenRequestAttributeSecurityContextRepository. A form flow uses the repository given in the option when there is oneKept only within the request. The next request authenticates again with the token

The MFA primary login is the same: in the session state it is kept in the session, in the token state only within the request, and during MFA the primary login proof is restored from the MFA session.
