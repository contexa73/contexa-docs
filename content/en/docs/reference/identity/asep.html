ASEP Security Exception Handling

ASEP is the name of a Contexa feature meant to let handler methods the application writes (@SecurityExceptionHandler) handle exceptions raised in the security filter chain. It does not work in the current version. This page says what does not work and lists the annotations and settings in the code for reference.

ASEP does not work in the current version. The ASEP configurer (AsepConfigurer) creates an ASEP filter (ASEPFilter) for each flow but never adds it to the security chain. So @SecurityExceptionHandler methods of @SecurityControllerAdvice classes are never called, and the handler parameter annotations and the flow option asep(...) have no effect. Security exceptions are handled by the default responses of Contexa and Spring Security.
ASEP targets the chains Contexa builds when it owns login (CONTEXA_OWNED). With the default HOST_OWNED, your application's chain and exception handling are used as they are. How to keep your application's existing login is in Connecting Your Existing Login.

What does not work now

  • Handlers made with @SecurityControllerAdvice and @SecurityExceptionHandler
  • Handler parameter annotations (@SecurityPrincipal, @AuthenticationObject and so on) and return handling (@SecurityResponseBody and so on)
  • The flow option asep(...) of every authentication method and of .mfa()
  • The ASEP default error response meant for when no handler matches

The ASEP auto-configuration itself turns on in a servlet web application that has a PlatformConfig bean (IdentityAsepAutoConfiguration) and creates the handler registry, default resolver and return handler beans. Those beans exist but are unused because there is no filter.

The design in the code (reference)

The following is what the code defines. It is not called in the current version; it is how the ASEP filter is built to behave once it is in the chain.

  • When a later step throws, a response that has already started is not handled and the exception is thrown again.
  • Otherwise, among the registered handlers the method whose exception type is closest is chosen, and on a tie the one with the smaller priority.
  • With no matching handler the default error response is used: 401 UNAUTHENTICATED for authentication exceptions, 403 ACCESS_DENIED for access denied, 500 INTERNAL_SERVER_ERROR otherwise. The body is timestamp, status, error, message, path.

The flow option asep(...)

Adds parameter resolvers and return handlers for one flow. Default resolvers and handlers of the same class are replaced by the added ones. The methods are exceptionArgumentResolver(...), exceptionArgumentResolvers(List), exceptionReturnValueHandler(...) and exceptionReturnValueHandlers(List). The attribute classes per method are FormAsepAttributes, RestAsepAttributes, OttAsepAttributes, PasskeyAsepAttributes and MfaAsepAttributes; MfaOttAsepAttributes and MfaPasskeyAsepAttributes are not used anywhere.

Definition example (not called now)

// In the current version this handler is never called (the ASEP filter is not in the chain).
@Component
@SecurityControllerAdvice
public class SecurityErrorAdvice {

    @SecurityExceptionHandler(value = AccessDeniedException.class, priority = 10)
    @SecurityResponseBody
    public Map<String, Object> handleAccessDenied(@CaughtException AccessDeniedException ex,
                                                  @SecurityPrincipal Object principal,
                                                  @SecurityRequestHeader(value = "X-Request-Id", required = false) String requestId) {
        return Map.of("error", "ACCESS_DENIED", "requestId", String.valueOf(requestId));
    }
}
