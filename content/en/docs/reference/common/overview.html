Common Contracts: Contexa Types in Your Code

The Contexa annotations, decision values, mode enums and extension interfaces that you write in application code, in one place. Find the type for what you want to do, when to use it, and what actually happens with the OSS modules.

At a glance

All the types below live in the contexa-common module (only the enforcement mode enum is in contexa-core). The single starter (spring-boot-starter-contexa) brings them in.

Turning Contexa on: @EnableAISecurity

The switch you put on the main class (package io.contexa.contexacommon.annotation). It imports the selector AiSecurityImportSelector (@Import), which loads the Contexa configuration. Without attributes the security mode is SANDBOX (your application owns login).

@EnableAISecurity
@SpringBootApplication
public class Application {
    public static void main(String[] args) {
        SpringApplication.run(Application.class, args);
    }
}
  • It is the "on" marker. The annotation puts a property source, contexaAiSecurityAnnotation, that carries the setting keys, and Contexa counts itself on only while that property source exists (writing the same keys in your application settings does not turn it on). Without the annotation every Contexa auto-configuration is left out, even with the starter on the classpath.
  • A dedicated database is required. Startup stops when contexa.datasource.url is empty.
  • The attributes (mode, authObjectLocation, authObjectAttribute, authObjectType) and what happens when you turn it on are in Turning Contexa On and Choosing a Security Mode.

Choosing the methods to analyze and enforce: @Protectable

When a method with this annotation is called, Contexa intercepts the call (AuthorizationManagerMethodInterceptor), evaluates the method authorization policies (ProtectableMethodAuthorizationManager), and the decision engine analyzes the call. This protected method is the unit a decision is made about.

  • Where it goes: a method or a class of a Spring bean. On a class it covers every method of the class. It does not have to be a controller.
  • Login is required: if the SecurityContext holds no authenticated Authentication at call time, or only an anonymous one, the call is refused.
  • Analysis runs only in the SHADOW and ENFORCE enforcement modes: under DISABLED and OBSERVE only the authorization policies are evaluated; nothing is analyzed and no event is published.

An agent request with no decision on record is decided on the spot even on a default method (Agent security). How a decision is made is described in Decision Engine.

import io.contexa.contexacommon.annotation.Protectable;
import io.contexa.contexacommon.annotation.ResourceImportance;
import org.springframework.stereotype.Service;

@Service
public class ReportService {

    @Protectable(category = "REPORT", actions = {"EXPORT"},
                 importance = ResourceImportance.SENSITIVE, sync = true)
    public String exportMonthlyReport(String month) {
        return "report-" + month;
    }
}

Decision values: ZeroTrustAction

The value the decision engine makes and stores. Each value carries an HTTP status, a lifetime and a granted authority fixed in code.

ValueIn plain wordsHTTP status valueLifetimeGranted authority
ALLOWAllow20015 minutesNone
CHALLENGEStep-up authentication4011,800 s (30 min)ROLE_MFA_REQUIRED
ESCALATEHeld for review (analysis not finished)423300 s (5 min)ROLE_REVIEW_REQUIRED
BLOCKBlock403No expiry (until released)ROLE_BLOCKED
PENDING_ANALYSISPending analysis (no decision stored)5030ROLE_PENDING_ANALYSIS

When a value is read from a string (ZeroTrustAction.fromString), case does not matter and the one-letter forms (A, B, C, E) are accepted. No value reads as pending analysis and an unknown string reads as held for review. How a stored decision applies to the next request is in Request-time enforcement; where it is stored is in Decision Engine.

Three modes with similar names

There are two enums named SecurityMode, in different packages. Check the package when you import one.

In plain wordsType (package)ValuesWhere you set it
Security modeSecurityMode
(io.contexa.contexacommon.security.bridge)		SANDBOX (default), FULL@EnableAISecurity(mode = ...)
Authentication ownershipSecurityOwnershipMode
(io.contexa.contexacommon.security.bridge)		HOST_OWNED, CONTEXA_OWNEDcontexa.bridge.ownership (when not set: SANDBOX → HOST_OWNED, FULL → CONTEXA_OWNED)
Enforcement modeSecurityZeroTrustProperties.SecurityMode
(io.contexa.contexacore.properties)		DISABLED, OBSERVE, SHADOW, ENFORCE (default)contexa.security.zerotrust.mode or the admin console's system settings

Under HOST_OWNED Contexa builds no authentication chain, so your application must declare its own Spring Security configuration to keep its existing behavior. Without one, Spring Boot's default security applies (every request needs authentication). What each mode changes and how to choose is in Turning Contexa On and Choosing a Security Mode. The authentication object location hint AuthObjectLocation (AUTO, SESSION, REQUEST_ATTRIBUTE, HEADER) is in the same io.contexa.contexacommon.security.bridge package.

Extension interfaces

When the application declares a bean of one of these interfaces, Contexa's default steps aside or the bean is added to the defaults.

InterfaceWhen you implement itWith your bean
AuthBridgeTo take the signed-in user from a request in your own wayIt replaces the default composite bridge (session, request attributes, headers) (bridge extension points).
ContexaAuthBridge (static method handoff)To tell Contexa about a user directly from your login codeYou call it rather than implement it. IllegalStateException if Contexa is not on (Direct handoff).
CapabilityContributorTo add your own check to the startup capability diagnosticsThe results of every contributor are gathered with the default checker (Startup diagnostics).
ContexaCacheServiceTo replace Contexa's internal cacheThe default (in memory in standalone mode, Redis in distributed mode) steps aside.

How to replace the beans the auto-configuration makes, such as the decision store, event publishing and data beans, is in Auto-configuration: replacing beans.

Module boundaries

  • The default configuration that @EnableAISecurity imports (io.contexa.autoconfigure.ai.AiSecurityConfiguration) is named by a class-name string, so contexa-common does not know the implementation modules at compile time.
  • contexa-common also holds the SOAR contracts (@SoarTool, SecurityActionEvent, tool policy interfaces) and the MCP tool-call contracts. The OSS has no implementation that runs these contracts. For SOAR see SOAR extension points; for MCP see Agent security.
