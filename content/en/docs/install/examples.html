Examples

How to get and run the 18 examples in the Contexa examples repository, the full list, the four examples to look at first, and the examples that go well with the installation and enforcement mode pages.

Get and run the examples

Each example is a separate Spring Boot application, gathered in one Gradle project.

git clone https://github.com/contexa73/contexa-examples.git
cd contexa-examples
./gradlew :contexa-example-quickstart:bootRun
  • Prerequisites (from the examples README): Java 21 or later (the examples build with the Java 21 toolchain), PostgreSQL with the vector extension, and the Ollama models qwen2.5:7b and mxbai-embed-large.
  • Addresses: on bootRun the root build.gradle sets the environment variables DB_URL, DB_USERNAME and DB_PASSWORD and the Redis and Kafka addresses to the values of the CLI's isolated environment (ctxa-sim: PostgreSQL 25432, Redis 26379, Kafka 29092), which are used where the example settings read them. That environment is created with contexa init --simulate (CLI). To use another database, change those values in the root build.gradle or the example's application.yml.
  • Setting names: the examples' application*.yml files were written before the current Contexa code, so settings that are no longer used or were renamed may remain. Watch for the old-name ERROR in the startup log (Old setting names) and switch to the names in these docs. The required settings and their meaning follow Minimal settings.

1. The first example: Quickstart

contexa-example-quickstart

  • What it shows: the smallest setup, where putting only @EnableAISecurity on the main class creates the default PlatformConfig automatically.
  • Settings: the setting that is really required is the dedicated database address (contexa.datasource.url). The infrastructure mode (contexa.infrastructure.mode) is optional and defaults to standalone. This example's settings are an application owned by Contexa (contexa.datasource.isolation.contexa-owned-application: true) in distributed mode, so it needs Redis and Kafka.
  • Read with: Installation guide

2. AI engine: AI Pipeline

contexa-example-ai-pipeline

  • What it shows: code security analysis built on Contexa's general AI pipeline (PipelineOrchestrator), with a custom step (PipelineStep), a response processor (DomainResponseProcessor), prompt templates and SSE streaming.
  • Relation to security decisions: this example is not the decision engine; it shows how to build application features on the same AI foundation. How security decisions are made by Layer 1 and Layer 2 analysis is in Decision engine.
  • Read with: AI pipeline

3. Identity: Identity MFA

contexa-example-identity-mfa

  • What it shows: MFA when Contexa owns sign-in. It uses a one-time token (OTT, a token sent by mail) and a passkey as second factors and sets the MFA page addresses itself (mfaPage). The authentication factors are form, REST, passkey, one-time token and recovery code; there is no authenticator-app one-time password (TOTP).
  • Adaptive MFA: the setup that asks for step-up authentication according to a request's risk (AIAdaptiveMfaPolicyProvider) is in Adaptive MFA.

4. Existing systems: Legacy System

contexa-example-legacy-system

  • What it shows: adding Contexa with @EnableAISecurity(mode = SecurityMode.SANDBOX) to a legacy application with its own session sign-in. The application owns sign-in (HOST_OWNED) and Contexa builds no security chain.
  • Connecting sign-in: a filter puts the user authenticated by the legacy session into Spring's SecurityContext on each request (item 4 of Connect your existing sign-in). The authentication bridge reads it, and Contexa uses its dedicated database separately from the application database. The bridge syncs externally signed-in users into the Contexa database as mirror rows (User mirror).

Examples that go well with these pages

  • contexa-example-shadow-enforce — switch the enforcement mode with --spring.profiles.active=shadow and enforce. Follow Start safely with enforcement modes for the mode names and behavior (the example settings still contain old setting names).
  • contexa-example-legacy-dependency-only — confirm that Contexa turns nothing on with only the starter and no @EnableAISecurity (With the dependency only).
  • contexa-example-protectable — see the difference between asynchronous and sync = true @Protectable (Put @Protectable on methods).
