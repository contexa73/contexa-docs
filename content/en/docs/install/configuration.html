Configuration Guide

Find the settings page for what you want to do, and start from a minimal configuration that boots as written. The tables at the end of this page tell you what a setting name you saw in older documents or examples is called today.

Find settings by task

Every Contexa setting goes where Spring Boot reads settings (application.yml, environment variables and so on). Pick the page below for what you want to change. Each setting is explained in detail on one page only; other pages link to it.

Where settings act

Contexa works in two streams. When a request comes in, it applies the decision already stored (request time). After the response has left, it analyzes that request and makes the decision for the next request (asynchronous decision). The two streams meet at the decision store. Each box names the settings page that controls that point.

Minimal configuration that boots

The smallest setup that adds Contexa to a Spring Boot application with sign-in of its own and runs decisions. It uses one OpenAI model and one PostgreSQL database that can use the pgvector extension. For other models (Anthropic · Ollama), see Connecting AI Models.

dependencies {
    implementation 'ai.ctxa:spring-boot-starter-contexa:0.1.1'
    implementation 'org.springframework.boot:spring-boot-starter-security'
    implementation platform('org.springframework.ai:spring-ai-bom:1.1.8')
    implementation 'org.springframework.ai:spring-ai-starter-model-openai'
    implementation 'org.springframework.ai:spring-ai-starter-vector-store-pgvector'
}
import io.contexa.contexacommon.annotation.EnableAISecurity;

@SpringBootApplication
@EnableAISecurity
public class MyApplication {
    public static void main(String[] args) {
        SpringApplication.run(MyApplication.class, args);
    }
}
contexa:
  datasource:
    url: jdbc:postgresql://localhost:5432/contexa
    username: contexa
    password: ${CONTEXA_DB_PASSWORD}
    isolation:
      contexa-owned-application: true   # only when the application has no database of its own; see the box below

spring:
  ai:
    openai:
      api-key: ${OPENAI_API_KEY}

Starting with this configuration settles the following.

  • On the first start Contexa creates its tables and default data in the dedicated database (contexa.iam.seed.enabled, default true), and the pgvector extension and vector table (the default Contexa adds, spring.ai.vectorstore.pgvector.initialize-schema=true).
  • The decision model is the OpenAI chat model; embeddings use OpenAI text-embedding-ada-002 (1536 dimensions), Spring AI's default when no model is named. Contexa follows your application's embedding model and does not set one.
  • The enforcement mode is ENFORCE (decisions are stored and applied from the next request), the infrastructure mode is standalone (decision and learning state kept in memory).
  • The application owns login (HOST_OWNED). Contexa analyzes calls to methods marked @Protectable, and a decision it stores is enforced on every path, by filters that run right after the application's security chain and again before @Protectable methods. You choose what to protect with @Protectable.
Set contexa-owned-application: true only when the application has no database of its own. It makes the application's default DataSource · JdbcTemplate the Contexa database too. Spring AI's pgvector auto-configuration builds the vector store on the application's default JdbcTemplate, so in a new application this line puts the vector table in the Contexa database. An application with its own database leaves this line out; the vector store then uses the application's default database (which must be able to use pgvector). To keep the vector store in the Contexa database, declare your own VectorStore bean built on contexaDataSource; Spring AI's auto-configuration then backs off. Details are in Dedicated database.
This setup needs a SecurityFilterChain or users of the application's own. With neither, the start is refused and says what to do: declare one of them, or use @EnableAISecurity(mode = SecurityMode.FULL). With users but no chain, Spring Boot's default security turns on, every request requires authentication, and one WARN line appears in the start-up log. For using Contexa with an application's existing security settings, see Adding Contexa to a Spring Boot application.

Which value wins

Most settings use the value written in application.yml. In the cases below a value from somewhere else wins. If you changed a value and nothing changed, check this table first.

CaseThe value that wins
With @EnableAISecurityThe annotation attributes (mode and so on) always replace contexa.ai.security.*. The authentication ownership contexa.bridge.ownership and contexa.datasource.isolation.contexa-owned-application follow the annotation mode only when you did not write them (FULL gives CONTEXA_OWNED · true).
Standalone mode (default)contexa.cache.type is LOCAL whatever you write.
An enforcement mode saved in the admin console's system settings (/contexa/admin/system-settings)The saved mode wins over contexa.security.zerotrust.mode. It applies as soon as it is saved, and at every start-up (Enforcement mode).
Policy decision values stored in the admin console's system settingsThe policy combining algorithm and the decision for a URL · method with no policy win over contexa.policy.*. The default seed writes this row from the start (Authorization Policies).
A legacy prefix and the new name written togetherThe new name's value wins. A legacy prefix is an alias with the lowest priority (Legacy prefixes).
Defaults Contexa addsSpring AI defaults such as the pgvector table name · dimensions · automatic table creation have the lowest priority; a value you write is used instead. These defaults are visible only when Contexa is turned on with @EnableAISecurity.
