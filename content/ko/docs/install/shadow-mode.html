집행 모드로 안전하게 시작하기

AI 판정을 실제로 적용하기 전에 섀도 모드(SHADOW)로 지켜보고, 결과를 확인한 뒤 집행 모드(ENFORCE)로 넘기는 방법입니다. 네 가지 집행 모드의 차이, 모드를 바꾸는 두 방법, 결과를 보는 곳, 되돌리는 법을 다룹니다.

네 가지 집행 모드

집행 모드(contexa.security.zerotrust.mode)는 AI 판정을 만들지, 만든 판정을 적용할지를 정합니다. 기본값은 ENFORCE입니다. 처음 도입할 때는 관찰(SHADOW) → 확인(결과 보는 곳) → 집행(ENFORCE) 순서로 운영합니다.

모드AI 분석판정 기록 · 감사 기록집행(판정 저장 · 차단)학습
DISABLED@Protectable 호출 · 판정 API에서 안 함그 호출로는 안 남김안 함안 함
OBSERVEDISABLED와 같음(다른 점은 모니터링 표시뿐)같음안 함안 함
SHADOW함남김안 함안 함
ENFORCE(기본)함남김함: 판정을 저장해 다음 요청부터 적용실제로 적용된 ALLOW만

로그인 성공 사건(Contexa가 로그인을 맡으면 Contexa MFA 로그인, 앱이 로그인을 맡으면 앱의 폼 · OAuth2 상호작용 로그인)은 발행할 때 집행 모드를 보지 않습니다. 판정 엔진은 집행 단계에서만 모드를 보므로, 이 사건은 DISABLED · OBSERVE에서도 분석 · 기록되고 집행만 되지 않습니다. 분석을 모두 멈추려면 contexa.security.zerotrust.enabled: false를 씁니다.

모드를 바꾸는 두 방법과 우선순위

방법언제 적용되나우선순위
관리 화면 /contexa/admin/system-settings에서 저장바로(재시작 없음). 저장한 값은 Contexa DB(system_settings)에 남고, 앱이 기동을 마칠 때마다 다시 적용됩니다.1(가장 높음)
application.yml의 contexa.security.zerotrust.mode기동할 때 읽으므로 바꾸면 재시작해야 합니다.2: 관리 화면에 저장한 값이 없을 때만
아무것도 적지 않음—3: ENFORCE
 
contexa:
  security:
    zerotrust:
      mode: SHADOW   # DISABLED · OBSERVE · SHADOW · ENFORCE
  • 시스템 설정 화면은 저장된 값이 없으면 지금 모드를 미리 채워 보여 줍니다. 그래서 다른 항목을 바꾸려고 한 번 저장해도 그때부터 DB 값이 YAML을 이깁니다. 모드 칸을 비워 저장하면 SHADOW로 저장됩니다.
  • CLI의 contexa mode --shadow · --enforce는 YAML만 바꿉니다. 관리 화면에 저장한 값이 있으면 효과가 없습니다.
  • 판정 분석 사건은 만들어질 때의 모드를 지니고 다닙니다. SHADOW일 때 만들어진 사건은 판정이 나올 무렵 ENFORCE로 바뀌었어도 집행하지 않습니다.

SHADOW에서 실제로 일어나는 일

  • 분석 대상: 모든 요청이 아니라 @Protectable 메서드 호출과 로그인 성공이 분석됩니다. Contexa가 로그인을 맡으면 Contexa MFA 로그인, 앱이 맡으면 앱의 상호작용 로그인(폼 로그인 · OAuth2 로그인)입니다.
  • 남는 것: 판정 기록 표(ai_security_decision_observation)와 감사 기록(audit_log)에 판정이 남습니다. 로그에만 남는 것이 아닙니다.
  • 하지 않는 것: 사용자 판정 저장, 진행 중인 응답을 끊는 차단 신호, 차단 사용자 기록, 위험 신호 보내기, 학습. 그래서 SHADOW 기간에는 행위 기준선이 쌓이지 않습니다.
  • @Protectable 메서드: 이미 저장된 BLOCK · CHALLENGE · ESCALATE가 있어도 로그만 남기고 실행합니다. sync = true 메서드는 그 요청 안에서 분석하고, 판정이 BLOCK이어도, 분석이 실패해도 실행합니다.
  • 요청 시점 필터(두 소유 방식 모두): 아무것도 막지 않습니다. 앞서 저장된 BLOCK · CHALLENGE · ESCALATE(ENFORCE 기간의 판정, 관리자 차단)는 SHADOW 동안 집행하지 않고, ENFORCE로 돌아오면 만료되지 않은 것이 다시 적용됩니다.
  • 지연: 기본 비동기 메서드는 응답이 나간 뒤 분석하므로 늘어나지 않습니다. sync = true 메서드와 판정이 없는 에이전트 요청은 그 요청 안에서 분석하므로 늘어납니다.
  • 모드와 상관없이 그대로인 것: 인증이 없는 @Protectable 호출의 거부, 정책(XACML) 판정의 거부. 위임 에이전트의 위임자 권한 재평가는 집행이 꺼져 있으면(ENFORCE가 아닌 모드, 또는 enabled: false) 기록만 합니다.
  • 판정 API(AuthZEN): SHADOW에서는 분석하되 답의 decision은 늘 true입니다. DISABLED · OBSERVE에서는 분석 없이 true입니다.
  • 에이전트 관문(두 소유 방식 모두): 집행이 꺼져 있으면(ENFORCE가 아닌 모드) 끝난 위임 · 좁혀진 범위 · 호출 상한을 기록하고 통과시킵니다(에이전트 통제의 SHADOW).

관리 화면은 두 소유 방식 모두 Contexa가 보호합니다. 로그인을 앱이 맡으면 관리 화면에는 앱 계정이 아닌 Contexa 관리자 계정으로 로그인합니다(설치 가이드).

ENFORCE로 넘기기

넘기기 전에 확인할 것:

  • 집행 전환 준비 화면의 권고가 DO_NOT_RECOMMEND가 아니고, 판정이 쌓여 있습니다(판정이 하나도 없으면 INSUFFICIENT_DATA).
  • 판정 종류 분포(ALLOW · BLOCK · CHALLENGE · ESCALATE)에서 정상 요청에 BLOCK · CHALLENGE가 나온 비율(오탐률)이 팀이 정한 기준(예: 1% 미만)보다 낮습니다. 기준은 코드가 정하지 않습니다.
  • 판정 지연이 처리량에 영향을 주지 않습니다(판정 모니터의 지연).
  • BLOCK · ESCALATE가 나올 때 알림을 받을 수 있습니다.
  • 판정 저장소가 운영에 맞습니다. standalone(기본)은 메모리, distributed는 Redis입니다(인프라 모드).
contexa:
  security:
    zerotrust:
      mode: ENFORCE

관리 화면에 모드를 저장한 적이 있으면 YAML 대신 관리 화면에서 바꿉니다. 바뀐 뒤 저장된 판정은 이렇게 적용됩니다.

되돌리기

방법결과
관리 화면에서 SHADOW 저장바로 적용(재시작 없음). 새 판정은 저장 · 적용 · 학습하지 않습니다.
YAML contexa.security.zerotrust.mode: SHADOW재시작 뒤 적용. 관리 화면에 저장한 값이 없을 때만 효과가 있습니다.
contexa.security.zerotrust.enabled: falseAI 분석을 하지 않고 판정 사건 수신기도 멈춥니다(mode: DISABLED는 수신기를 멈추지 않음).
contexa.enabled: falseContexa 전체를 켜지 않습니다. 앱 체인이 없으면 Spring Boot 기본 보안이 적용됩니다.

이미 저장된 판정은 남지만, 되돌린 동안에는 집행되지 않습니다. 두 소유 방식 모두 요청 시점 필터와 @Protectable 메서드 앞의 확인이 집행 모드와 contexa.security.zerotrust.enabled를 따릅니다. 그래서 SHADOW로 바꾸거나 끄면 아무것도 막지 않습니다(@Protectable 메서드 앞의 확인은 기록만 함). 바꾸기 전에 저장된 BLOCK · CHALLENGE · ESCALATE는 관리자 차단까지 포함해 남아 있다가, ENFORCE로 돌아오면 유효 시간이 지나거나 관리자가 풀기 전까지 다시 적용됩니다.

학습 상태는 모드를 바꿔도 지워지지 않습니다. 다만 standalone에서는 메모리에 있으므로 재시작하면 사라집니다. 관리 화면으로 바꾸면 재시작이 필요 없습니다.

참고: 판정 뒤 처리 단계

판정 사건은 아래 순서의 처리기를 지납니다. SHADOW에서 달라지는 곳은 집행(55)뿐입니다. 집행은 contexa.security.zerotrust.enabled가 true이고 모드가 ENFORCE일 때만 합니다(isEnforcementEnabled()).

순서하는 일SHADOW에서
50판정 만들기(ProcessingExecutionHandler)같음
55집행(SecurityDecisionEnforcementHandler): 판정 기록을 쓰고, ENFORCE면 판정 저장(writeFinalAction), BLOCK이면 차단 표시(setBlockedFlag) · 차단 신호(registerBlockAndAwait) · 차단 사용자 기록(recordBlock), 적용된 ALLOW 학습판정 기록만 쓰고 나머지는 건너뜀
56증거 봉인(SealedEvidenceCaptureHandler)같음
60감사 기록(AuditingHandler)같음(남김)
65Contexa SaaS 전달(SaasForwardingHandler, 켰을 때만)같음

각 단계는 판정 엔진에 자세히 있습니다.
