예제

Contexa 예제 저장소의 18개 예제를 받고 돌리는 방법, 전체 목록, 처음 볼 네 가지 예제와 설치 · 집행 모드 문서와 함께 보면 좋은 예제를 안내합니다.

예제 받기와 돌리기

예제는 각각 따로 도는 Spring Boot 앱이고, 한 Gradle 프로젝트에 모여 있습니다.

git clone https://github.com/contexa73/contexa-examples.git
cd contexa-examples
./gradlew :contexa-example-quickstart:bootRun
  • 준비물(예제 README 기준): Java 21 이상(예제 빌드는 Java 21 툴체인), PostgreSQL과 vector 확장, Ollama 모델 qwen2.5:7b · mxbai-embed-large.
  • 접속 주소: 루트 build.gradle은 bootRun할 때 환경 변수 DB_URL · DB_USERNAME · DB_PASSWORD와 Redis · Kafka 주소를 CLI의 격리 환경(ctxa-sim) 값(PostgreSQL 25432, Redis 26379, Kafka 29092)으로 넣고, 예제 설정이 이 값을 읽는 곳에 쓰입니다. 이 환경은 contexa init --simulate로 만듭니다(CLI). 다른 DB를 쓰려면 루트 build.gradle의 그 값이나 예제의 application.yml을 고칩니다.
  • 설정 이름: 예제의 application*.yml은 Contexa 코드보다 먼저 만들어져, 지금은 쓰지 않거나 이름이 바뀐 설정이 남아 있을 수 있습니다. 기동 로그의 옛 이름 ERROR(옛 설정 이름)를 보고 이 문서의 이름으로 바꾸세요. 필수 설정과 그 뜻은 최소 설정을 기준으로 합니다.

1. 처음 볼 예제: Quickstart

contexa-example-quickstart

  • 무엇을 보나: 메인 클래스에 @EnableAISecurity 하나만 붙이면 기본 PlatformConfig가 자동으로 만들어지는 가장 작은 구성입니다.
  • 설정: 진짜 필수인 설정은 전용 DB 주소(contexa.datasource.url)입니다. 인프라 모드(contexa.infrastructure.mode)는 선택이고 기본은 standalone입니다. 이 예제의 설정은 Contexa 소유 앱(contexa.datasource.isolation.contexa-owned-application: true)에 분산 모드라 Redis · Kafka가 필요합니다.
  • 함께 읽기: 설치 가이드

2. AI 엔진: AI Pipeline

contexa-example-ai-pipeline

  • 무엇을 보나: Contexa의 범용 AI 파이프라인(PipelineOrchestrator)으로 코드 보안 분석을 하는 예제입니다. 사용자 정의 단계(PipelineStep), 응답 처리기(DomainResponseProcessor), 프롬프트 템플릿, SSE 스트리밍을 씁니다.
  • 보안 판정과의 관계: 이 예제는 판정 엔진이 아니라 같은 AI 기반 위에 앱 기능을 만드는 방법을 보여 줍니다. 보안 판정이 1차 분석과 2차 분석(Layer 1 · Layer 2)으로 만들어지는 과정은 판정 엔진에 있습니다.
  • 함께 읽기: AI 파이프라인

3. 신원: Identity MFA

contexa-example-identity-mfa

  • 무엇을 보나: Contexa가 로그인을 맡을 때의 MFA입니다. 2차 인증 요소로 일회용 토큰(OTT, 메일로 보내는 토큰)과 패스키를 쓰고, MFA 화면 주소를 직접 정합니다(mfaPage). 인증 요소는 폼 · REST · 패스키 · 일회용 토큰 · 복구 코드이며 앱 일회용 비밀번호(TOTP)는 없습니다.
  • 적응형 MFA: 요청의 위험에 따라 추가 인증을 요구하는 구성(AIAdaptiveMfaPolicyProvider)은 적응형 MFA에 있습니다.

4. 기존 시스템: Legacy System

contexa-example-legacy-system

  • 무엇을 보나: 자체 세션 로그인이 있는 레거시 앱에 @EnableAISecurity(mode = SecurityMode.SANDBOX)로 붙입니다. 로그인은 앱이 맡고(HOST_OWNED) Contexa는 보안 체인을 만들지 않습니다.
  • 로그인 연결: 레거시 세션으로 인증된 사용자를 필터가 요청마다 Spring SecurityContext에 넣습니다(기존 로그인과 연결하기의 4번). 인증 브리지가 이 정보를 읽고, Contexa는 앱 DB와 따로 전용 DB를 씁니다. 브리지는 외부에서 로그인한 사용자를 Contexa DB에 거울 행으로 동기화합니다(사용자 거울).

함께 보면 좋은 예제

  • contexa-example-shadow-enforce — --spring.profiles.active=shadow와 enforce로 집행 모드를 바꿔 봅니다. 모드 이름과 동작은 집행 모드로 안전하게 시작하기를 기준으로 하세요(예제 설정에는 옛 설정 이름이 남아 있습니다).
  • contexa-example-legacy-dependency-only — 스타터만 넣고 @EnableAISecurity를 붙이지 않았을 때 Contexa가 아무것도 켜지 않는 것을 확인합니다(의존성만 넣었을 때).
  • contexa-example-protectable — @Protectable의 비동기 · sync = true 차이를 봅니다(@Protectable 붙이기).
