집행 모드와 판정 조정

Contexa가 판정을 만들고 적용할지(집행 모드)를 고르고, 요청 시점 집행 · 판정 시간과 처리량 · 판정 프롬프트 · 최소 대응 규칙 · 행위 기준선 학습을 설정으로 조정합니다. 판정이 만들어지고 적용되는 과정 자체는 판정 엔진과 요청 시점 집행에 있습니다.

판정 하나가 지나가는 길과, 길목마다 그 자리를 정하는 이 쪽의 절입니다.

집행 모드 고르기

집행 모드(contexa.security.zerotrust.mode)는 AI 모델로 판정을 만들지, 만든 판정을 저장해 다음 요청부터 적용할지를 정합니다.

모드AI 분석판정 저장 · 적용학습쓰는 때
DISABLED(끔)하지 않음하지 않음하지 않음판정을 쓰지 않을 때
OBSERVE(관찰)지금 코드에서는 DISABLED와 같습니다. 관리 화면 모니터의 표시만 다릅니다.—
SHADOW(섀도)함판정을 관찰 기록 · 감사 기록에만 남기고, 저장 · 차단 · 응답 변경은 하지 않음하지 않음도입 첫 단계에서 판정을 지켜볼 때
ENFORCE(집행, 기본)함판정을 저장하고 같은 사용자의 다음 요청부터 적용실제로 적용된 허용 판정만운영

정확히는 AI 분석은 enabled가 켜져 있고 모드가 SHADOW · ENFORCE일 때, 판정 저장 · 적용은 enabled가 켜져 있고 모드가 ENFORCE일 때만 일어납니다.

  • 섀도 모드에서도 기다림이 생기는 요청이 있습니다. 즉시 판정 메서드(@Protectable(sync = true))와 판정 기록이 없는 에이전트 요청은 그 요청 안에서 분석합니다. 결과가 허용이 아니어도 막지 않고 진행합니다.
  • contexa.security.zerotrust.enabled: false는 DISABLED보다 넓게 끕니다. 분석을 하지 않는 것에 더해, 분석 사건을 받는 수신기와 로그인 맥락에 판정을 적용하는 단계까지 멈춥니다.
  • 단계를 올려 가며 도입하는 순서는 집행 모드로 안전하게 시작하기에 있습니다.
contexa:
  security:
    zerotrust:
      mode: SHADOW     # 지켜본 뒤 ENFORCE로
설정기본값뜻언제 바꾸나
contexa.security.zerotrust.enabledtrue제로 트러스트 판정 전체 켜기Contexa 판정을 통째로 멈출 때
contexa.security.zerotrust.modeENFORCEDISABLED · OBSERVE · SHADOW · ENFORCE도입 단계에 맞춰

관리 화면에서 바꾸기

관리 화면 시스템 설정(/contexa/admin/system-settings)에서도 집행 모드를 바꿀 수 있습니다. 재시작 없이 저장하는 즉시 적용됩니다.

  • 한 번 저장하면 그 뒤로는 저장한 값이 YAML을 이깁니다. 기동할 때마다 저장한 값으로 contexa.security.zerotrust.mode를 덮어씁니다. YAML만 바꿔서는 모드가 바뀌지 않으니, 화면에서 바꾸세요.
  • 아직 저장한 적이 없으면 화면에는 지금 모드가 미리 채워져 있습니다. 모드 칸을 비워 저장하면 SHADOW가 됩니다.
모드를 낮추면 이미 저장된 제한은 멈출 뿐 지워지지 않습니다. @Protectable 메서드는 모드를 따릅니다(섀도에서는 저장된 제한을 기록만 하고, 끔 · 관찰에서는 보지 않음). 요청 시점 필터 두 개(추가 인증 · 접근 제어)도 두 소유 방식 모두에서 모드를 따라, enabled가 켜져 있고 모드가 ENFORCE일 때만 막습니다. 이미 저장된 BLOCK · CHALLENGE · ESCALATE는 남아 있다가 모드가 ENFORCE로 돌아오면 다시 적용되고, 관리자가 해제하거나 판정의 유효 시간이 지나야 없어집니다.

요청 시점 집행 다듬기

요청 시점 필터는 두 소유 방식 모두에서 돕니다. Contexa가 로그인을 맡을 때(CONTEXA_OWNED)는 Contexa가 만든 보안 체인 안에서, 기본(HOST_OWNED)에서는 앱 보안 체인 바로 뒤의 서블릿 필터로 돌고, CHALLENGE는 Contexa MFA 대신 Contexa의 추가 확인으로 갑니다. 그래서 아래 설정 중 Contexa MFA 시작(challenge.* 잠금)과 Contexa 자체 로그인 맥락에 관한 것은 CONTEXA_OWNED에서만 동작합니다. @Protectable 메서드 앞에서도 집행합니다. 판정별 응답과 해제 방법은 요청 시점 집행에 있습니다.
설정기본값뜻언제 바꾸나
contexa.security.zerotrust.max-block-mfa-attempts2차단(BLOCK)된 사용자가 해제 요청 전에 거치는 MFA의 시도 한도. 접근 제어 필터 · 해제 API · 안내 화면이 이 값을 씁니다. MFA 실패 처리기는 이 값과 상관없이 실패 2번째에 해제 대기를 지웁니다해제 MFA를 더 허용할 때(실패 처리기 쪽 한도는 2로 남음)
contexa.security.zerotrust.challenge.lock-wait-time0추가 인증(MFA)을 시작할 때 사용자별 잠금을 기다리는 시간. 0이면 바로 포기동시에 들어온 요청이 같은 MFA를 기다리게 할 때
contexa.security.zerotrust.challenge.lock-lease-time30s그 잠금을 쥐고 있는 최대 시간드물게
contexa.security.zerotrust.challenge.busy-retry-after-seconds3잠금을 못 잡았을 때 503 MFA_BUSY_RETRY에 싣는 Retry-After(초)클라이언트 재시도 간격을 맞출 때
contexa.security.zerotrust.threat.initial0.3위협 점수가 아직 없는 사용자의 위협 점수(신뢰 점수 = 1 − 위협 점수)드물게
contexa.security.zerotrust.cache.ttl-hours24강제 로그아웃 등으로 무효화한 세션 · 토큰 기록의 유지 시간(시). 판정 캐시가 아닙니다무효화를 더 오래 기억해야 할 때
contexa.security.zerotrust.cache.session-ttl-minutes30로그아웃을 알아채려고 세션마다 기억하는 "직전 로그인 사용자"의 유지 시간(분, 마지막 접근 기준)드물게
contexa.security.zerotrust.cache.invalidated-ttl-minutes60무효화된 세션을 이 JVM에서 기억하는 시간(분)드물게
contexa.security.zerotrust.session.tracking-enabledtrue로그인 맥락을 저장할 때 사용자의 세션을 기록해, 강제 로그아웃이 그 사용자의 모든 세션에 닿게 함세션 추적을 하지 않을 때
contexa.security.zerotrust.redis.update-interval-seconds30같은 세션의 추적 기록을 다시 쓰는 최소 간격(초). 이름과 달리 단독 모드에도 적용저장소 쓰기를 줄일 때
contexa.security.zerotrust.session-tracking.max-untimed-sessions-per-user64만료 시각을 알 수 없는 세션 식별자를 사용자당 몇 개까지 추적할지. 넘으면 가장 오래 안 보인 것부터 추적에서 빠짐. 0 이하는 무제한한 사용자가 세션을 아주 많이 쓸 때
contexa.security.zerotrust.analysis.max-age-ms3600000로그인 MFA 정책이 저장된 분석 결과를 믿는 최대 나이(ms). 더 오래된 분석은 추가 인증으로 봅니다로그인 때 더 새로운 분석을 요구할 때

설정이 아닌 고정값도 있습니다: 판정을 읽은 뒤 5초 동안 캐시, 검토 보류(ESCALATE) 응답의 Retry-After 30초, 판정별 유효 시간(허용 15초 · 추가 인증 1,800초 · 검토 보류 300초 · 차단은 해제까지, 판정 엔진).

세션을 알아보는 이름

Contexa가 요청의 세션을 알아볼 때는 JWT의 jti, 그다음 HTTP 세션을 먼저 봅니다. 둘 다 없으면 아래 이름으로 쿠키 → 헤더 → Bearer 토큰 순서로 찾습니다. 이 식별자로 무효화된 세션을 거르고 세션을 추적합니다(CONTEXA_OWNED).

설정기본값뜻언제 바꾸나

판정 시간 제한

1차 분석이 정하지 못하면(ESCALATE) 2차 분석이 다시 판정합니다(판정 엔진). 시간 제한은 모두 밀리초입니다.

상황별 예

도입 첫 주: 판정만 지켜보기

contexa:
  security:
    zerotrust:
      mode: SHADOW

느린 모델(로컬 모델 등): 시간 제한 늘리기 — 1차 · 2차 제한과 호출 하나의 제한, 사건 전체 예산을 함께 늘립니다.

contexa:
  security:
    tiered:
      layer1:
        timeout:
          llm-ms: 120000
      layer2:
        timeout-ms: 90000
    plane:
      llm-timeout:
        provider-call-timeout-ms: 120000
      agent:
        event-timeout-ms: 300000

유료 API 한도 지키기(OpenAI)

contexa:

        enabled: true
