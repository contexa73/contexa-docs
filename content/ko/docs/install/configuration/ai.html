AI 모델 연결

Contexa가 판정과 AI 파이프라인에 쓸 채팅 모델 · 임베딩 모델을 붙이는 방법입니다. 공급자를 연결하고, 기본 채팅 모델과 1차 · 2차 분석 모델을 고르고, 임베딩 모델 · 벡터 저장소 · 과거 기록 검색을 설정할 수 있습니다.

한눈에 보기

Contexa는 모델 공급자에 직접 접속하지 않습니다. 앱에 있는 Spring AI 채팅 모델 · 임베딩 모델 빈을 모아 이름을 붙이고, 기동할 때 기본 채팅 모델 하나와 임베딩 모델 하나를 고릅니다. 판정을 만들 때는 1차 · 2차 분석에 지정한 모델을 쓰고, 지정이 없으면 기본 채팅 모델을 씁니다. 이 페이지는 설정을 중심으로 설명하고, 모델이 정해지는 동작의 자세한 내용은 모델 공급자 참조(요청마다 모델이 정해지는 순서)에 있습니다.

모델이 없어도 앱은 시작합니다. 채팅 모델이 하나도 없으면 Contexa는 기동하지만 판정을 만들지 못하고, 사용자는 분석 대기로 남습니다. 기동 로그의 기능 진단([ContexaCapability] llm-runtime · embedding-runtime)이 빠진 모델 빈을 알려 줍니다.

공급자 붙이기

Contexa 스타터에는 모델 공급자가 들어 있지 않습니다. 쓸 공급자의 Spring AI 스타터를 앱 의존성에 더하고, API 키와 모델 이름은 Spring AI 설정(spring.ai.*)에 적습니다. Contexa에는 contexa.llm.openai.* 같은 공급자 키가 없습니다. Contexa는 Spring AI 1.1.8로 빌드됩니다.

공급자앱에 더할 의존성Contexa가 모델 이름으로 읽는 키
OpenAIorg.springframework.ai:spring-ai-starter-model-openai채팅 spring.ai.openai.chat.options.model, 임베딩 spring.ai.openai.embedding.options.model
Anthropicorg.springframework.ai:spring-ai-starter-model-anthropic채팅 spring.ai.anthropic.chat.options.model
Ollamaorg.springframework.ai:spring-ai-starter-model-ollama, 또는 Contexa 전용 연결채팅 spring.ai.ollama.chat.options.model, 임베딩 spring.ai.ollama.embedding.options.model

OpenAI 하나로 시작하는 예입니다. contexa.datasource.url은 모델과 상관없이 늘 필요한 Contexa 전용 DB 주소입니다.

spring:
  ai:
    openai:
      api-key: ${OPENAI_API_KEY}
      chat:
        options:
          model: gpt-4o-mini

contexa:
  datasource:
    url: jdbc:postgresql://localhost:5432/contexa
    username: contexa
    password: ${CONTEXA_DB_PASSWORD}
  • 공급자를 여러 개 넣으면 모두 목록에 오르고, 기본 채팅 모델은 다음 절의 규칙으로 하나만 고릅니다.
  • Spring AI 모델 자동 구성 고르기. contexa.llm.selection.chat.priority에 공급자를 하나만 적으면(openai · anthropic · ollama) Contexa는 spring.ai.model.chat의 기본값을 그 공급자로 넣어, 다른 공급자의 Spring AI 채팅 자동 구성이 켜지지 않게 합니다. 임베딩도 contexa.llm.selection.embedding.priority의 첫 공급자로 spring.ai.model.embedding을 넣습니다. 둘 중 하나라도 적으면 이미지 · 음성 · 검열 모델 자동 구성은 none으로 끕니다. 앱이 spring.ai.model.*를 직접 적으면 그 값이 이깁니다.
  • 판정 호출의 온도(temperature)와 seed는 Spring AI 설정이 정하지 않습니다. 판정 호출은 contexa.security.tiered.determinism.temperature(기본 0.0) · seed(기본 1)를 호출마다 넣습니다. 집행 모드와 판정 조정에서 바꿉니다.
  • contexa.llm.enabled: false면 Contexa의 LLM 자동 구성 전체가 꺼집니다.

기본 채팅 모델 고르기

Contexa는 기동할 때 채팅 모델 하나를 기본 채팅 모델(빈 이름 primaryChatModel)로 정합니다. 층 모델을 지정하지 않은 판정과 Contexa의 AI 파이프라인 호출이 이 모델을 씁니다. 고르는 방법은 contexa.llm.selection.chat.mode로 정합니다.

값고르는 방법기동이 멈추는 경우
dynamic-priority(기본)priority 목록의 공급자 순서대로, 그 공급자의 모델 빈을 만들 수 있는 첫 모델을 고릅니다. 목록의 공급자 모델이 하나도 없으면 다른 공급자의 모델도 차례로 시도합니다.모델 빈이 있는데 하나도 만들 수 없을 때
fixedpriority에 적은 공급자 하나의 모델만 씁니다. 다른 공급자로 넘어가지 않습니다.priority에 공급자를 둘 이상 적었거나, 그 공급자의 모델이 없을 때
spring-primaryprimary로 표시된 모델 하나(바인딩의 primary: true 또는 @Primary 빈). 모델이 하나뿐이면 그것을 씁니다.primary가 둘 이상이거나, 모델이 여럿인데 primary가 없을 때

같은 공급자의 모델이 여럿이면 primary로 표시된 모델이 먼저이고, 그다음은 이름 순서입니다.

mode 값은 소문자와 하이픈으로 적습니다. dynamic-priority · fixed · spring-primary로 적으십시오. Contexa는 이 글자를 그대로 비교해 기본 채팅 모델 빈을 만들기 때문에, DYNAMIC_PRIORITY처럼 밑줄을 쓴 이름으로 적으면 오류 없이 기본 채팅 모델이 만들어지지 않습니다.
  • 고르는 일은 기동할 때 한 번입니다. 운영 중 공급자 호출이 실패해도 다른 모델로 바꿔 부르지 않습니다. 연결 끊김 · 429 · 503 같은 일시 오류는 같은 모델로 최대 4번 다시 시도합니다. 끝내 답을 받지 못한 판정이 어떻게 되는지는 판정 엔진에 있습니다.
  • 예전 설정 contexa.llm.chat-model-priority는 priority를 빈 값으로 적었을 때만 쓰입니다.
# Anthropic 모델만 쓰기(기존 설정에 더하는 부분)
contexa:
  llm:
    selection:
      chat:
        mode: fixed
        priority: anthropic
설정기본값뜻
contexa.llm.enabledtrueContexa LLM 자동 구성 전체
contexa.llm.selection.chat.modedynamic-priority기본 채팅 모델을 고르는 방법(위 표)
contexa.llm.selection.chat.priorityopenai,anthropic,ollama공급자 순서. fixed에서는 공급자 하나만 적습니다

1차 · 2차 분석 모델

판정은 대부분 1차 분석에서 끝나고, 1차가 ESCALATE를 고른 요청만 2차 분석으로 갑니다(판정 엔진). 층마다 다른 모델을 쓸 수 있습니다. 예를 들어 1차는 빠르고 싼 모델, 2차는 더 신중한 모델로 둡니다.

# 기본 채팅 모델이 OpenAI일 때(기존 설정에 더하는 부분)
contexa:
  security:
    tiered:
      llm:
        layer1:
          model: gpt-4o-mini
        layer2:
          model: gpt-4o
          backup:
            model: gpt-4o-mini
  • 모델 이름이 연결되는 방법. 적은 이름이 목록의 어떤 모델의 이름(빈 이름 · 바인딩 키 · 모델 이름 · 별칭)과 같으면 그 모델을 씁니다.
  • 같은 이름이 없으면 기본 채팅 모델을 복사해 모델 이름만 바꿔 씁니다. 이 복사는 모델이 mutate()를 지원할 때만 됩니다. Spring AI 1.1.8에서는 OpenAI 채팅 모델만 지원하고, Anthropic · Ollama 채팅 모델은 지원하지 않습니다. 그런 모델을 층마다 바꾸려면 바인딩으로 이름을 붙입니다(Ollama는 아래 방법).
  • 층 모델을 만들 수 없으면 기동이 멈춥니다. 잘못 적은 이름이 운영 중에 조용히 다른 모델로 바뀌지 않게 하기 위해서입니다. 이 검사는 기본 채팅 모델이 있을 때 합니다.
  • 백업 모델은 층 모델을 적었을 때만 쓰이고, 기동 때 검사하지 않습니다. 호출할 때 백업도 만들 수 없으면 기본 채팅 모델을 씁니다.
설정기본값뜻
contexa.security.tiered.llm.layer1.model없음1차 분석 모델. 비우면 기본 채팅 모델
contexa.security.tiered.llm.layer2.model없음2차 분석 모델. 비우면 기본 채팅 모델
contexa.security.tiered.llm.layer1.backup.model없음1차 분석 모델을 쓸 수 없을 때 대신 쓸 모델
contexa.security.tiered.llm.layer2.backup.model없음2차 분석 모델을 쓸 수 없을 때 대신 쓸 모델
contexa.security.tiered.llm.tiered.layer1.timeout-ms없음1차 층 스트리밍 호출의 제한 시간(ms). 비우면 30000, 120000을 넘으면 120000
contexa.security.tiered.llm.tiered.layer2.timeout-ms없음2차 층 스트리밍 호출의 제한 시간(ms). 비우면 60000, 120000을 넘으면 120000

마지막 두 설정은 스트리밍 호출에만 쓰이고 판정 시간에는 영향이 없습니다. 1차 · 2차 분석의 제한 시간, 모델 호출 하나의 제한 시간은 집행 모드와 판정 조정에서 정합니다.

모델에 이름 붙이기(bindings)

Contexa는 앱에 있는 모든 채팅 모델 · 임베딩 모델 빈을 스스로 목록에 올립니다. 설정하지 않아도 빈 이름, 공급자(빈 클래스 · 이름에서 추정), 모델 이름(공급자의 spring.ai.…options.model, 없으면 빈 이름)으로 찾을 수 있습니다. contexa.llm.bindings는 이 목록의 항목을 고치거나 별칭을 더할 때 씁니다.

설정기본값뜻
contexa.llm.bindings.chat.<이름>.bean-name없음붙일 모델 빈 이름. 비우면 <이름>이 빈 이름과 같을 때 그 빈에 붙습니다
contexa.llm.bindings.chat.<이름>.provider없음공급자. 비우면 빈 클래스 · 이름에서 추정합니다(ollama · anthropic · openai · gemini · mistral · bedrock · huggingface, 그 밖은 spring)
contexa.llm.bindings.chat.<이름>.model-id없음모델 이름. 비우면 위 공급자 표의 키, 그것도 없으면 빈 이름
contexa.llm.bindings.chat.<이름>.aliases[]더 붙일 이름. 층 모델 설정에 이 이름을 적을 수 있습니다
contexa.llm.bindings.chat.<이름>.enabledtruefalse면 이 설정을 쓰지 않습니다. 빈은 자기 이름으로 목록에 그대로 남습니다
contexa.llm.bindings.chat.<이름>.primaryfalse같은 공급자 안에서 먼저 고르고, spring-primary 모드의 기준이 됩니다

임베딩 모델은 같은 필드를 contexa.llm.bindings.embedding.<이름>.…에 적습니다. 임베딩의 모델 이름을 키에서 추정하는 공급자는 OpenAI · Ollama뿐입니다.

  • 이름이 겹치면 기동이 멈춥니다. 빈 이름 · 바인딩 키 · 모델 이름 · 별칭 가운데 하나라도 서로 다른 두 모델에 겹치면 안 됩니다. 같은 공급자 모델 빈이 둘이고 둘 다 모델 이름을 같은 키에서 얻으면 겹칠 수 있으니, 그때는 model-id를 서로 다르게 적습니다.
  • 별칭은 고르는 데 쓰는 이름입니다. OpenAI · Anthropic 모델은 별칭으로 골라도 그 빈에 설정된 모델로 호출합니다. 호출 모델이 별칭이 되는 것은 Ollama뿐입니다(아래).
  • bean-name이 가리키는 빈이 없으면 경고 로그만 남기고 그 설정을 건너뜁니다.

예: 기본 채팅 모델은 OpenAI 그대로 두고, 2차 분석만 Anthropic 모델로 돌립니다. anthropicChatModel은 Spring AI Anthropic 스타터가 만드는 빈 이름입니다.

# 기존 설정에 더하는 부분
spring:
  ai:
    anthropic:
      api-key: ${ANTHROPIC_API_KEY}

contexa:
  llm:
    bindings:
      chat:
        anthropicChatModel:
          aliases: [expert]
  security:
    tiered:
      llm:
        layer2:
          model: expert

로컬 Ollama 쓰기

Ollama는 두 가지 방법으로 붙일 수 있습니다. 하나만 고르십시오.

Contexa 전용 연결은 contexa.llm.chat.ollama.base-url을 적으면 켜집니다(앱에 Ollama 라이브러리가 있을 때). 채팅과 임베딩이 같은 Ollama 서버를 씁니다. Ollama 하나로 시작하는 예입니다.

contexa:
  datasource:
    url: jdbc:postgresql://localhost:5432/contexa
    username: contexa
    password: ${CONTEXA_DB_PASSWORD}
  llm:
    chat:
      ollama:
        base-url: http://localhost:11434
        model: qwen3:8b
        keep-alive: 30m
    selection:
      chat:
        priority: ollama
      embedding:
        priority: ollama
설정기본값뜻
contexa.llm.chat.ollama.base-url없음Ollama 서버 주소. 적으면 Contexa가 Ollama 연결과 위 두 빈을 만듭니다
contexa.llm.chat.ollama.model없음채팅 모델. 비우면 qwen3:8b
contexa.llm.chat.ollama.keep-alive없음호출 뒤 모델을 메모리에 남겨 둘 시간(Ollama keep_alive, 예 30m). 비우면 Ollama 기본
contexa.llm.embedding.ollama.model없음임베딩 모델. 비우면 mxbai-embed-large
contexa.llm.embedding.ollama.dedicated-runtime-enabledfalsetrue면 임베딩만 다른 Ollama 서버로 보냅니다(빈 contexaDedicatedOllamaEmbeddingModel)
contexa.llm.embedding.ollama.base-url없음임베딩 전용 서버 주소. 전용 서버를 켰는데 비우면 기동이 멈춥니다
contexa.llm.model-capabilities.ollama.disable-thinking-patterns없음사고(thinking)를 끌 Ollama 모델 이름 패턴(정규식, 쉼표로 구분). 이름이 맞는 모델은 호출할 때 thinking을 끕니다

채팅 서버 주소와 전용 임베딩 서버를 함께 쓰면 임베딩 빈이 둘(공유 · 전용) 생기고, 이름 순서로 전용 빈이 먼저 골라집니다.

Ollama 서버 하나에서 층마다 다른 모델 쓰기

Ollama 채팅 모델은 복사할 수 없으므로, 층 모델 이름을 Ollama 채팅 빈의 별칭으로 붙입니다. Ollama 호출은 고른 이름을 그대로 모델로 보내므로 같은 서버의 다른 모델이 쓰입니다. 그 모델은 Ollama 서버에 미리 받아 두어야 합니다.

# 위 Ollama 예에 더하는 부분
contexa:
  llm:
    bindings:
      chat:
        contexaOllamaChatModel:
          aliases: [qwen3:8b, qwen3:14b]
  security:
    tiered:
      llm:
        layer1:
          model: qwen3:8b
        layer2:
          model: qwen3:14b

임베딩 모델과 벡터 차원

임베딩 모델은 과거 판정 기록 같은 문서를 벡터로 바꿔 저장 · 검색할 때 씁니다. 저장된 벡터의 차원이 모델과 같아야 하므로 임베딩은 공급자 하나로 고정합니다.

설정기본값뜻
contexa.llm.selection.embedding.modefixedfixed: priority의 공급자 모델을 먼저 쓰고, 없으면 다른 임베딩 모델을 씁니다. spring-primary: primary 표시 모델. dynamic-priority는 쓸 수 없습니다(기동이 멈춤)
contexa.llm.selection.embedding.priorityopenai임베딩 공급자 하나. 둘 이상 적으면 기동이 멈춥니다
contexa.llm.embedding.dimensions1024임베딩 차원. 직접 적었을 때만 차원을 정하는 데 쓰입니다(아래 순서 2)
contexa.llm.embedding.ollama.dimensions1024Ollama 임베딩 차원. 직접 적었을 때만 쓰입니다(아래 순서 3)

차원이 정해지는 순서

  1. contexa.vectorstore.pgvector.dimensions를 직접 적었으면 그 값
  2. contexa.llm.embedding.dimensions를 적었으면 그 값
  3. 공급자의 차원 키: OpenAI는 spring.ai.openai.embedding.options.dimensions, Ollama는 contexa.llm.embedding.ollama.dimensions(또는 spring.ai.ollama.embedding.options.dimensions)
  4. Contexa가 아는 모델이면 그 모델의 값: OpenAI text-embedding-3-small · text-embedding-3-large 등 text-embedding-3 계열은 1024, text-embedding-ada-002는 1536, Ollama mxbai-embed-large · bge-m3는 1024
  5. 모르는 모델인데 위 값이 하나도 없으면 기동이 멈춥니다. 그 모델의 차원을 contexa.llm.embedding.dimensions와 contexa.vectorstore.pgvector.dimensions에 함께 적으십시오.

OpenAI 임베딩을 쓸 때 Contexa는 spring.ai.openai.embedding.options.model의 기본값을 text-embedding-3-small로, dimensions를 위에서 정한 차원으로 넣습니다. 그래서 기본으로는 1024차원 벡터를 받습니다.

차원을 바꾸면 이미 저장된 벡터와 맞지 않습니다. 기동할 때 Contexa는 쓰는 임베딩 모델의 차원, 설정된 벡터 저장소 차원, 이미 있는 vector_store 표의 차원을 비교하고 하나라도 다르면 기동을 멈춥니다. 차원을 바꾸려면 표를 새로 만들거나 문서를 다시 임베딩하십시오. 맞으면 기동 로그에 Embedding vector dimension verified: provider=…, model=…, dimension=…이 남습니다.

벡터 저장소(pgvector)

벡터는 Spring AI pgvector 자동 구성이 만드는 벡터 저장소 빈에 저장됩니다(의존성은 설치 준비). 설정은 contexa.vectorstore.pgvector.*로 적습니다. 여기에 적은 값은 같은 이름의 Spring AI 키로도 넘어가므로(그 Spring AI 키를 따로 적지 않았을 때) 저장소가 같은 값을 씁니다. 반대로 Spring AI 키(spring.ai.vectorstore.pgvector.*)에만 적으면 Contexa는 그것을 예전 키로 보고 기동 때 ERROR 로그를 남기므로, Contexa 키로 적으십시오.

설정기본값뜻
contexa.vectorstore.pgvector.dimensions1024벡터 차원(128~3072). 적지 않으면 위 순서로 정해집니다
contexa.vectorstore.pgvector.index-typeHNSW색인 종류(HNSW · IVFFLAT). Spring AI 저장소가 표를 만들 때 씁니다
contexa.vectorstore.pgvector.distance-typeCOSINE_DISTANCE거리 계산(COSINE_DISTANCE · EUCLIDEAN_DISTANCE · NEGATIVE_INNER_PRODUCT)
contexa.vectorstore.pgvector.batch-size100한 번에 저장하는 문서 수
contexa.vectorstore.pgvector.parallel-threads16벡터 검색 · 저장을 함께 돌리는 스레드 수(1~32)
contexa.vectorstore.pgvector.top-k100건수를 정하지 않은 유사도 검색이 돌려주는 최대 건수
contexa.vectorstore.pgvector.similarity-threshold0.5건수를 정하지 않은 유사도 검색의 최소 유사도
contexa.vectorstore.pgvector.search-timeout-ms15000검색 하나를 기다리는 시간(ms)
contexa.vectorstore.pgvector.store-timeout-ms15000저장 하나를 기다리는 시간(ms)
contexa.vectorstore.pgvector.hnsw.ef-search100모든 유사도 검색에 거는 HNSW 검색 폭(hnsw.ef_search). 크면 정확하고 느려집니다

첫 기동 때 표 만들기. Contexa는 Spring AI의 spring.ai.vectorstore.pgvector.initialize-schema 기본값을 true로 넣습니다(Spring AI 자체 기본은 false). 그래서 첫 기동 때 vector 확장, vector_store 표, HNSW 색인, 사용자별 검색용 메타데이터 색인을 만듭니다. 스키마를 마이그레이션으로 관리하는 DB에서는 끄고 표와 두 색인을 직접 만드십시오.

# 기존 설정에 더하는 부분
contexa:
  vectorstore:
    pgvector:
      initialize-schema: false

저장 실패 재시도

벡터 저장이 실패한 문서는 메모리 대기열에 두었다가 뒤에서 다시 저장합니다. 몇 분짜리 장애로 학습 기록을 잃지 않기 위해서입니다. 대기열은 재시작하면 사라지므로, 재시작 뒤에도 남겨야 하면 앱이 FailedDocumentSink 빈을 직접 등록합니다.

설정기본값뜻
contexa.vectorstore.retry.enabledtruefalse면 실패한 저장을 호출한 쪽에 오류로만 돌려줍니다
contexa.vectorstore.retry.queue-size2000기다리는 문서 수 상한. 가득 차면 가장 오래된 문서를 버립니다
contexa.vectorstore.retry.max-attempts20이 횟수를 넘으면 포기합니다
contexa.vectorstore.retry.max-age1h첫 실패부터 이 시간이 지나면 포기합니다
contexa.vectorstore.retry.initial-delay10s첫 재시도까지 기다리는 시간. 실패할 때마다 두 배
contexa.vectorstore.retry.max-delay5m재시도 사이 가장 긴 대기
contexa.vectorstore.retry.batch-size20한 번 재시도에 저장하는 문서 수. 실패하는 동안 반으로 줄고, 성공하면 다시 늘어납니다

과거 기록 · 문맥 검색(RAG)

contexa.rag.*는 AI 파이프라인과 AI Lab 서비스가 벡터 저장소를 검색할 때의 기본값, 과거 판정 기록을 얼마나 보관할지를 정합니다. 판정 엔진의 1차 · 2차 분석이 과거 기록을 몇 건, 어떤 유사도로 찾는지는 집행 모드와 판정 조정에서 정합니다.

설정기본값뜻
contexa.rag.enabledtrueRAG 자동 구성 전체(벡터 서비스, 기록 보관 삭제, 차원 검사)
contexa.rag.defaults.top-k10AI 파이프라인 문맥 검색(ContextRetriever)이 가져오는 문서 수
contexa.rag.defaults.similarity-threshold0.7그 검색의 최소 유사도
contexa.rag.behavior.shared-advisor-enabledfalse모든 사용자의 행동 문서를 읽는 어드바이저 빈(behaviorAnalysisRagAdvisor)을 만듭니다. Contexa는 이 빈을 쓰지 않습니다. 사용자 필터가 없으므로 앱이 직접 쓸 때만 켭니다
contexa.rag.behavior.lookback-days30그 어드바이저가 찾는 기간(일)
contexa.rag.risk.top-k50위험 평가 어드바이저 빈(riskAssessmentRagAdvisor)의 검색 건수. Contexa 안에서는 이 빈을 쓰는 곳이 없습니다
contexa.rag.risk.similarity-threshold0.8그 어드바이저의 최소 유사도
contexa.rag.lab.batch-size50AI Lab 벡터 서비스(행동 분석 · 정책 생성)가 한 번에 저장하는 문서 수
contexa.rag.lab.top-k100AI Lab 검색 건수(요청이 정하지 않았을 때)
contexa.rag.lab.similarity-threshold0.75AI Lab 검색의 최소 유사도
contexa.rag.lab.validation-enabledtrueAI Lab 문서를 저장하기 전에 검사합니다
contexa.rag.lab.enrichment-enabledtrueAI Lab 문서에 메타데이터를 덧붙입니다
contexa.rag.etl.behavior.retention-days90과거 판정 기록 보관 기간(일). 0 이하면 지우지 않습니다
contexa.rag.etl.behavior.retention-cleanup-cron0 45 3 * * *보관 기간이 지난 기록을 지우는 시각(매일 03:45)
contexa.rag.vocabulary-reindex-on-starttrue기동이 끝난 뒤, 예전 분류 이름으로 저장된 과거 기록을 지금 이름으로 옮깁니다(뒤에서 500건씩)

공급자별 판정 호출 옵션

1차 · 2차 분석이 모델을 부를 때 붙이는 옵션입니다. 그 층의 모델이 해당 공급자일 때만 쓰입니다. 2차 분석은 같은 이름을 layer2 아래에 적습니다.

설정기본값뜻
contexa.security.tiered.layer1.max-output-tokens40961차 판정 답의 최대 토큰. 추론 모델은 추론 토큰도 여기에 듭니다
contexa.security.tiered.layer2.max-output-tokens25602차 판정 답의 최대 토큰
contexa.security.tiered.layer1.open-ai-reasoning-effortlowOpenAI 추론 모델의 추론 노력. 이름이 contexa.llm.model-capabilities.openai.max-completion-token-patterns에 맞는 OpenAI 모델에만 보냅니다
contexa.security.tiered.layer1.open-ai-verbositylowOpenAI 추론 모델의 답 길이 정도. 위와 같은 모델에만
contexa.security.tiered.layer1.anthropic-thinkingPROVIDER_DEFAULTAnthropic 모델의 사고(thinking). PROVIDER_DEFAULT: 보내지 않음(모델 · Spring AI 기본), OFF: 끔, BUDGET: 예산을 정해 켬, ADAPTIVE: Spring AI 2.0 이상 필요
contexa.security.tiered.layer1.anthropic-thinking-budget-tokens없음BUDGET일 때 사고 예산(1024 이상 필수). 답 한도는 max-output-tokens + 예산이 됩니다
contexa.security.tiered.layer1.anthropic-thinking-allowance-tokens0예산 없이 생각하는 모델에서 답 한도에 더할 토큰. 0이면 사고와 답이 max-output-tokens를 나눠 씁니다
contexa.security.tiered.layer1.anthropic-effort없음Anthropic effort. Spring AI 1.1은 보낼 수 없어 값을 적으면 기동이 멈춥니다
Anthropic 사고 설정은 기동 때 검사합니다. 앱에 Anthropic 라이브러리가 있으면, 예산이 1024보다 작거나, Spring AI 1.1이 보낼 수 없는 값(ADAPTIVE, anthropic-effort)이거나, 그 층의 Claude 모델이 받지 않는 값이면 기동을 멈추고 이유를 알려 줍니다. 사고를 끄면 모델의 판정도 달라집니다.

모델별 처리 표

모델마다 받는 옵션이 달라 Contexa가 호출 옵션을 고쳐 보냅니다. 기본 표는 코드에 있고, 새 모델에 맞춰 바꿀 때만 적습니다.

설정기본값뜻
contexa.llm.model-capabilities.openai.max-completion-token-patternsgpt-5(?:[.-].*)?,o\d+(?:[.-].*)?이 이름의 OpenAI 모델은 max_tokens 대신 max_completion_tokens를 보내고, 추론 옵션을 붙입니다
contexa.llm.model-capabilities.openai.default-sampling-only-patternsgpt-5(?:[.-].*)?,o\d+(?:[.-].*)?이 이름의 OpenAI 모델에는 temperature · top-p를 보내지 않습니다
contexa.llm.model-capabilities.anthropic.default-sampling-only-patterns코드 표기본값이 아닌 샘플링 값을 거부하는 Claude 모델(Opus 4.7 이후 · Sonnet 5 · Haiku 5 · Fable 5 · Mythos 5 계열). 이 모델에는 샘플링 값을 보내지 않습니다
contexa.llm.model-capabilities.anthropic.thinking코드 표Claude 모델마다 받는 사고 · effort 값의 표. 적으면 표 전체를 바꿉니다
contexa.llm.model-capabilities.anthropic.system-prompt-cachetrue캐시 전략을 따로 두지 않았을 때 시스템 프롬프트를 캐시하도록 표시합니다

어드바이저와 스트리밍

Contexa가 모델을 부를 때 쓰는 ChatClient에는 어드바이저가 붙고, 스트리밍 응답에서는 최종 응답이 시작되는 표지를 찾습니다. 동작은 어드바이저 · 스트리밍 참조에 있습니다.

설정기본값뜻
contexa.advisor.enabledtrue어드바이저 자동 구성 전체
contexa.advisor.security.enabledtrue보안 어드바이저. 호출에 사용자 · 세션 정보를 붙이고, 호출마다 사용자 · 걸린 시간을 로그로 남깁니다
contexa.advisor.security.order50어드바이저 순서(작을수록 먼저)
contexa.advisor.security.require-authenticationfalsetrue면 사용자 ID가 없는 호출을 막습니다
contexa.streaming.final-response-marker###FINAL_RESPONSE###스트림에서 최종 응답이 시작되는 표지. 바꾸지 마십시오: 표지를 붙이는 쪽은 이 설정이 아니라 같은 고정값을 씁니다
contexa.streaming.marker-buffer-size100표지를 찾으려고 붙잡아 두는 글자 수(표지 길이에 더함)

기동이 멈추는 경우

모델 설정이 맞지 않으면 Contexa는 운영 중에 조용히 다른 모델을 쓰는 대신 기동을 멈춥니다. 로그의 메시지로 아래 표에서 원인을 찾으십시오.

상황고치는 방법
채팅 mode: fixed인데 priority에 공급자가 둘 이상이거나, 그 공급자 모델이 없음공급자를 하나만 적고, 그 공급자의 Spring AI 스타터를 넣습니다
임베딩 mode: dynamic-priorityfixed로 바꿉니다
임베딩 priority에 공급자가 둘 이상하나만 적습니다
층 모델(layer1.model · layer2.model)을 만들 수 없음그 이름을 바인딩의 별칭이나 모델 이름으로 붙이거나, 기본 채팅 모델을 OpenAI로 둡니다
모델 이름 · 별칭이 두 모델에 겹침이름을 서로 다르게 적습니다
spring-primary인데 primary가 둘 이상이거나, 모델이 여럿인데 primary가 없음하나만 primary: true로 둡니다
모르는 임베딩 모델인데 차원 설정이 없음contexa.llm.embedding.dimensions와 contexa.vectorstore.pgvector.dimensions를 그 모델의 차원으로 적습니다
차원이 맞지 않음(모델 · 설정 · 이미 있는 표)같은 값으로 맞추고, 표를 새로 만들거나 다시 임베딩합니다
임베딩 전용 Ollama 서버를 켰는데 주소가 없음contexa.llm.embedding.ollama.base-url을 적습니다
Anthropic 사고 설정 거부메시지가 가리키는 설정을 고칩니다(위 표)

반대로 기동은 되지만 판정이 나오지 않는 경우도 있습니다: 채팅 모델이 하나도 없을 때, mode 값을 밑줄 이름으로 적어 기본 채팅 모델이 만들어지지 않았을 때입니다.
