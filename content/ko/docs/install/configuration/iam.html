contexa-iam

인가 정책

URL · 메서드에 맞는 정책이 여럿이거나 하나도 없을 때 어떻게 판정할지, 첫 기동 때 어떤 데이터를 넣을지, 관리 콘솔이 자원을 찾는 방법을 정합니다. 정책 자체는 관리 콘솔에서 만듭니다.

이 페이지로 정하는 것

정책 본문은 application.yml이 아니라 Contexa DB에 있고, 관리 콘솔에서 만들고 고칩니다(정책). 설정은 YAML로 정하는 것과 관리 콘솔의 시스템 설정 화면에서 정하는 것으로 나뉩니다. 정책 판정 방식 세 가지는 양쪽에 다 있고, 저장된 시스템 설정이 이깁니다.

관리 콘솔에 들어가려면 두 소유 방식 모두 Contexa 관리자 계정이 있어야 합니다. 관리 콘솔(/contexa/admin/**)은 Contexa가 직접 지킵니다. CONTEXA_OWNED에서는 Contexa 보안 체인과 메서드 보안으로, 기본 HOST_OWNED에서는 /contexa/admin/login에서 Contexa 관리자를 로그인시키는 자기 체인으로 지킵니다. 앱이 이 주소를 막을 필요는 없고, 앱 사용자는 콘솔에 들어올 수 없습니다. 첫 관리자는 contexa.iam.seed.admin.*로 만듭니다(아래, 예시는 HOST_OWNED 모드에서 보호하기).

첫 기동: 스키마와 기본 데이터

Contexa 전용 DB가 비어 있으면 기동할 때 스키마(db/schema.sql)를 설치하고, 기본 데이터(역할 · 그룹 · 정책 · 조건 템플릿 · 관리 메뉴 · 시스템 설정)를 넣습니다. 모든 삽입은 이미 있는 행을 건너뛰므로 재시작해도 안전합니다. 스키마가 이미 다 있으면 스키마를 정비만 하고, 일부만 있으면 아무것도 바꾸지 않고 기동을 멈춥니다. 시드는 @EnableAISecurity로 Contexa가 켜져 있고 Contexa 전용 DB(contexa.datasource.url)가 있을 때 돕니다.

설정기본값뜻
contexa.iam.seed.enabledtrue기동 때 스키마와 기본 데이터를 설치합니다. 스키마를 직접 관리하는 DB에서만 끕니다
contexa.iam.seed.accounts.enabledfalse예시 계정 다섯과 그 그룹 배정(db/data-accounts.sql)도 넣습니다
contexa.iam.seed.admin.password(없음)값이 있으면 기동 때 관리자 한 명을 만듭니다(ROLE_ADMIN을 가진 시스템관리자 그룹. Contexa가 로그인을 맡으면 2단계 로그인, HOST_OWNED에서는 /contexa/admin/login의 콘솔 자체 로그인). 사용자 이름이나 메일이 같은 사용자가 있으면 아무것도 바꾸지 않으므로 관리 콘솔에서 바꾼 비밀번호가 유지됩니다. contexa init은 이 값을 프로젝트 밖 ~/.contexa/credentials.properties에 둡니다
contexa.iam.seed.admin.usernameadmin그 관리자의 사용자 이름
contexa.iam.seed.admin.emailadmin@localhost그 관리자의 메일. 두 번째 로그인 단계의 일회용 코드가 이 주소로 갑니다(CONTEXA_OWNED)
예시 계정은 배포에서 켜지 마십시오. 예시 계정 다섯(admin · manager · developer · user · finance)은 코드와 함께 공개된 비밀번호 하나를 같이 씁니다. 내 DB에서 로컬로 빠르게 시작할 때만 켜고, 첫 관리자는 ID 공급자나 관리 콘솔에서 만드십시오.

정책이 여럿 맞을 때와 하나도 없을 때

설정기본값뜻
contexa.policy.combining-algorithmFIRST_APPLICABLE요청에 맞는 정책이 여럿일 때 하나의 결정으로 묶는 방법(아래 표)
contexa.policy.no-matching-url-policy-decisionAUTHENTICATED맞는 URL 정책이 하나도 없을 때의 결정. AUTHENTICATED: 로그인한 사용자는 통과하고 로그인하지 않은 요청은 돌려보냅니다(Contexa 자신의 로그인은 열려 있습니다). PERMIT: 누구나 통과. DENY: 아무도 통과하지 못함. 모든 주소에 정책을 두는 운영이면 DENY로 둡니다. 앱이 로그인을 맡는 방식(HOST_OWNED)에서는 앱 체인이 앱의 요청을 정하므로, 이 결정은 앱이 Contexa의 정책 매니저(.access(customDynamicAuthorizationManager))에 넘긴 요청에 적용됩니다
contexa.policy.missing-method-policy-decisionPERMIT@Protectable 메서드에 정책이 하나도 없을 때의 결정(PERMIT · DENY)
저장된 시스템 설정이 YAML을 이깁니다. 기본 시드는 시스템 설정 행(결합 FIRST_APPLICABLE, 정책 없는 메서드 PERMIT, 정책 없는 URL은 값 없음)을 넣습니다. 이 행이 있으면 Contexa는 모든 빈을 만든 뒤 요청을 받기 전에 결합 방법과 메서드의 결정을 행의 값으로 덮으므로, 시드를 켠 설치에서는 YAML의 contexa.policy.combining-algorithm과 contexa.policy.missing-method-policy-decision이 쓰이지 않습니다. 정책 없는 URL의 결정은 운영자가 저장한 뒤에야 행의 값으로 덮이며, 그 전에는 YAML의 contexa.policy.no-matching-url-policy-decision이 적용됩니다(없으면 AUTHENTICATED). 관리 콘솔의 시스템 설정 화면에서 바꾸십시오. 화면은 URL 결정이 저장되기 전까지 지금 적용 중인 값을 선택된 것으로 보여 줍니다. 저장하면 이 인스턴스에 바로 적용되고, 다른 인스턴스에도 다시 읽으라고 알립니다. YAML 값은 시스템 설정 행이 없을 때(URL 결정은 저장되기 전까지) 쓰입니다. 이전 버전에서 만든 설치는 행에 URL 결정으로 PERMIT을 갖고 있고, 업그레이드는 저장된 결정을 바꾸지 않으므로 그 URL은 운영자가 다른 값을 고를 때까지 모두에게 열려 있습니다. Contexa가 로그인을 맡는 방식(CONTEXA_OWNED)에서는 시작할 때 이를 알리는 줄이 한 번 나옵니다.

결합 알고리즘

값맞는 정책이 여럿일 때
FIRST_APPLICABLE(기본)우선순위 순서로 처음 맞는 정책이 정합니다
DENY_OVERRIDES하나라도 거부면 거부합니다. 가장 안전합니다
PERMIT_OVERRIDES하나라도 허용이면 허용합니다
DENY_UNLESS_PERMIT명시적인 허용이 없으면 거부합니다

어디에 적용되나

  • URL 정책은 모든 요청을 Contexa의 동적 인가(CustomDynamicAuthorizationManager)로 판정하는 체인에서 쓰입니다. 기본으로는 @EnableAISecurity(mode = SecurityMode.FULL)의 기본 체인(CONTEXA_OWNED)입니다.
  • 메서드 정책은 @Protectable 메서드를 호출할 때 쓰입니다. 인증 소유권과 상관없이 적용됩니다(@Protectable).

관리 콘솔의 자원 스캔

관리 콘솔은 앱의 컨트롤러 주소를 찾아 정책을 걸 수 있는 자원으로 등록합니다(자원 스캐너). 찾을 패키지는 YAML이 아니라 시스템 설정 화면의 자원 스캐너 패키지(기본 io.contexa.contexaiam.)에 앱 자신의 패키지(Spring Boot가 아는 패키지)를 더한 것입니다. 앱 패키지 밖의 주소를 등록하려면 거기에 그 패키지를 더하십시오.

설정기본값뜻
contexa.iam.admin.rest-docs-path/docs/index.html스캐너가 URL 자원마다 만드는 API 문서 링크(<경로>#<컨트롤러>_<메서드>)의 앞부분. 관리 화면의 자원 정보와 AI 자원 이름 짓기에 쓰입니다. Contexa는 이 문서 페이지를 제공하지 않으므로 앱의 API 문서 주소로 바꿉니다
contexa.iam.admin.condition-templates.enabledfalsetrue면 관리 콘솔에서 자원을 새로 고칠 때(정책 센터 · 자원 관리 화면) 조건 템플릿을 자동으로 만듭니다. 기동 때 만드는 것은 아닙니다. 조건 템플릿을 직접 만드는 기능은 이 값과 상관없습니다

실시간 끝점

설정기본값뜻
contexa.iam.websocket.enabledtrueIAM이 STOMP 끝점 /ws-soar(SockJS, 브로커 /topic · /queue, 앱 접두사 /app)를 등록합니다. 서블릿 웹 앱이고 앱이 자기 STOMP 설정(clientInboundChannel 빈)을 갖고 있지 않을 때만 등록합니다

이 끝점은 모든 출처의 연결을 받습니다. Contexa 안에는 이 끝점으로 메시지를 보내는 코드가 없으므로, 쓰지 않으면 false로 끄십시오.

관련 페이지

  • 정책을 만들고 판정하는 방법: 정책 · 동적 인가 · XACML
  • 관리 콘솔 화면: 관리 콘솔
