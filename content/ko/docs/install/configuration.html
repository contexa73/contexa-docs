설정 길잡이

CONTEXA 설정의 대부분은 기본값으로 동작합니다. 기동하려면 정해야 하는 것은 네 가지(CONTEXA 켜기, 전용 DB, AI 모델과 벡터 저장소, 앱의 로그인)이고, 운영 환경으로 옮기기 전에 몇 가지를 더 정해야 합니다. 이 페이지에서 하려는 일(처음 켜기, 모델 바꾸기, 여러 인스턴스 배포 등)을 고르면 필요한 설정과 그 설정이 설명된 페이지를 찾을 수 있습니다. 옛 문서나 예제에서 본 설정 이름은 이 페이지 뒤쪽의 “옮겨 간 키 · 없어진 키”에서 현재 이름을 확인합니다.

반드시 정할 설정과 기본값으로 충분한 설정

CONTEXA 설정의 대부분은 기본값으로 동작합니다. 기동하려면 아래 네 가지를 갖춰야 합니다. 하나라도 없으면 CONTEXA가 켜지지 않거나, 기동이 멈추거나, 판정이 나오지 않습니다. 판정(Decision)은 AI 모델이 사용자의 요청을 분석해 내리는 결론이며, 허용(ALLOW) · 추가 인증(CHALLENGE) · 검토 보류(ESCALATE) · 차단(BLOCK) 중 하나입니다. 추가 인증은 MFA를 요구하는 판정입니다.

운영 환경으로 옮기기 전에 정할 것

아래 설정은 기본값으로도 기동합니다. 다만 운영 환경(production)에서는 기본값이 요구사항과 맞지 않을 수 있습니다. 배포 전에 값을 정하거나 기본값이 맞는지 확인해야 합니다.

설정기본값정해야 하는 이유설명
contexa.security.zerotrust.modeENFORCE기본값은 판정을 저장하고 다음 요청부터 실제로 적용합니다. 처음 도입할 때는 관찰 모드(SHADOW)로 시작합니다. 관찰 모드는 판정을 기록하지만 요청을 막지 않으므로, 정상 사용자의 요청을 위험으로 판정하는 오탐이 얼마나 나오는지 확인한 뒤 ENFORCE로 바꿀 수 있습니다.운영 모드 고르기 · 관찰 모드로 안전하게 시작하기
contexa.security.evidence.signing.keys없음키가 없으면 CONTEXA는 임시 키로 서명하고, 그 서명은 재시작 뒤 검증할 수 없습니다. 판정 기록과 봉인 증거(판정의 근거를 서명해 저장한 감사 증적)를 재시작 뒤에도 검증하려면 키를 정해야 합니다.봉인 증거 설정
contexa.infrastructure.modestandalone단독 모드는 판정과 학습 상태를 앱 프로세스의 메모리에 둡니다. 재시작하면 행위 기준선(사용자별 접속 시간대 · 네트워크 · 단말 같은 사용 패턴의 기록)이 사라지고, 인스턴스가 여러 개이면 서로 판정을 공유하지 않습니다. 이 둘이 문제가 되면 distributed로 바꿉니다.단독과 분산 고르기
contexa.iam.seed.admin.password없음관리 화면(/contexa/admin)에는 CONTEXA 관리자 계정이 필요합니다. 이 값을 정하면 기동할 때 관리자 한 명을 만듭니다.첫 기동: 스키마와 기본 데이터
contexa.iam.seed.accounts.enabled없음예시 계정 다섯은 공용 비밀번호를 씁니다. 이 값도 관리자 비밀번호도 정하지 않으면, 사용자 계정이 아직 없는 전용 DB에 예시 계정이 만들어집니다. 운영 환경에서는 false를 명시해 만들지 않도록 합니다.첫 기동: 스키마와 기본 데이터

응답이 느릴 때

기본 방식에서는 요청을 응답이 나간 뒤에 분석하므로, 분석 시간이 그 요청의 응답 시간에 더해지지 않습니다. 응답이 느려지는 경우는 요청 안에서 판정을 기다려야 할 때입니다. 아래 순서로 확인합니다.

  1. 느린 요청이 @Protectable(sync = true) 메서드인지 확인합니다. sync = true는 메서드를 실행하기 전에 그 요청 안에서 판정을 기다립니다. 기본값은 false이므로, 즉시 판정이 반드시 필요한 메서드에만 sync = true를 씁니다(@Protectable).
  2. 요청이 새 세션, 새 IP 주소, 새 브라우저에서 왔는지 확인합니다. 사용자의 마지막 판정 뒤에 세션 · 주소 · 브라우저가 바뀐 사람의 요청은 기본(비동기) 메서드에서도 그 요청의 판정을 기다립니다. 이 대기는 contexa.security.zerotrust.agent.flight.wait(기본 40s)를 넘지 않습니다(판정 통합). 같은 세션 · 주소 · 브라우저의 요청에는 허용(ALLOW) 판정이 contexa.security.zerotrust.allow-validity(기본 15m) 동안 새 분석 없이 쓰입니다(운영 모드 고르기).
  3. 분석 자체가 오래 걸리는지 확인합니다. 모델이 느리면 1차 분석 모델을 더 빠른 모델로 지정합니다(contexa.security.tiered.llm.layer1.model, 1차 · 2차 분석 모델). 1차 분석 전체의 제한 시간은 contexa.security.tiered.layer1.timeout.llm-ms(기본 90000 ms)입니다(판정 시간 제한).
  4. 요청 안에서 판정할 때 과거 판정 기록 검색을 기다리는 시간을 확인합니다. 기본은 contexa.security.tiered.layer1.timeout.interactive-rag-wait-ms(600 ms)입니다(판정 시간 제한).
  5. Ollama 같은 자체 호스팅 모델 서버를 쓰면 서버가 한 번에 받는 호출 수가 제한됩니다. 기본은 2(contexa.llm.gate.self-hosted-max-concurrent)이며, 서버가 동시에 처리하는 요청 수에 맞춥니다(모델 서버가 한 번에 받는 호출 수).

설정 페이지 전체 목록

설정은 아래 다섯 개의 설정 페이지와, 기능 페이지의 설정 소절에 나뉘어 있습니다.

설정이 적용되는 지점

CONTEXA는 두 단계로 동작합니다. 첫째, 요청이 들어오면 이미 저장된 판정을 그 요청에 적용합니다(요청 시점). 둘째, 응답이 나간 뒤에 그 요청을 분석해 같은 사용자의 다음 요청에 쓸 판정을 만듭니다(비동기 판정). 두 단계는 판정 저장소를 통해 이어집니다. 아래 그림의 각 상자에는 그 지점을 정하는 설정 페이지를 적었습니다.

최소 설정 예시

로그인 기능이 이미 있는 Spring Boot 앱에 CONTEXA를 붙여 판정까지 실행하는 가장 작은 구성입니다. OpenAI 모델 하나와 pgvector 확장을 쓸 수 있는 PostgreSQL 하나를 사용합니다. 다른 모델(Anthropic · Ollama)은 AI 모델 연결을 참고합니다.

dependencies {
    implementation 'ai.ctxa:spring-boot-starter-contexa:0.1.1'
    implementation 'org.springframework.boot:spring-boot-starter-security'
    implementation platform('org.springframework.ai:spring-ai-bom:1.1.8')
    implementation 'org.springframework.ai:spring-ai-starter-model-openai'
    implementation 'org.springframework.ai:spring-ai-starter-vector-store-pgvector'
}
import io.contexa.contexacommon.annotation.EnableAISecurity;

@SpringBootApplication
@EnableAISecurity
public class MyApplication {
    public static void main(String[] args) {
        SpringApplication.run(MyApplication.class, args);
    }
}
contexa:
  datasource:
    url: jdbc:postgresql://localhost:5432/contexa
    username: contexa
    password: ${CONTEXA_DB_PASSWORD}
    isolation:
      contexa-owned-application: true   # 앱에 자기 DB가 없을 때만. 아래 상자 참고

spring:
  ai:
    openai:
      api-key: ${OPENAI_API_KEY}

이 구성으로 기동하면 다음과 같이 동작합니다.

  • 첫 기동에서 CONTEXA는 전용 DB에 CONTEXA의 표와 기본 데이터를 만듭니다(contexa.iam.seed.enabled, 기본 true). 같은 시점에 pgvector 확장과 벡터 표도 만듭니다(CONTEXA가 넣는 기본값 contexa.vectorstore.pgvector.initialize-schema=true).
  • 판정에는 OpenAI 채팅 모델을 씁니다. 임베딩 모델은 따로 적지 않았으므로 Spring AI 기본값인 OpenAI text-embedding-ada-002(1536차원)입니다. CONTEXA는 앱의 임베딩 모델을 따르며 따로 정하지 않습니다.
  • 운영 모드는 ENFORCE입니다. 판정을 저장하고 다음 요청부터 적용합니다. 인프라 모드는 단독이며, 판정과 학습 상태를 메모리에 둡니다.
  • 로그인은 앱이 맡습니다(HOST_OWNED). CONTEXA는 @Protectable을 붙인 메서드 호출을 분석합니다. 저장된 판정은 두 곳에서 적용합니다. 앱 보안 체인 바로 뒤에서 도는 필터가 모든 경로에 적용하고, @Protectable 메서드를 실행하기 전에 한 번 더 적용합니다. 무엇을 보호할지는 @Protectable에서 정합니다.
contexa-owned-application: true는 앱에 자기 DB가 없을 때만 넣습니다. 이 값을 켜면 앱의 기본 DataSource · JdbcTemplate까지 CONTEXA DB가 됩니다. Spring AI의 pgvector 자동설정은 앱의 기본 JdbcTemplate으로 벡터 저장소를 만듭니다. 따라서 새 앱에서는 이 줄로 벡터 표가 CONTEXA DB에 생깁니다. 자기 DB가 있는 앱은 이 줄을 넣지 않습니다. 그러면 벡터 저장소는 앱의 기본 DB를 사용하며, 그 DB가 pgvector를 쓸 수 있어야 합니다. 벡터 저장소를 CONTEXA DB에 두려면 contexaDataSource를 쓰는 VectorStore 빈을 직접 선언합니다. 그러면 Spring AI의 자동설정이 적용되지 않습니다. 자세한 내용은 전용 DB에 있습니다.
이 구성에는 앱의 SecurityFilterChain이나 앱 사용자가 있어야 합니다. 둘 다 없으면 기동이 거부되고, 해야 할 일이 함께 출력됩니다. 둘 중 하나를 선언하거나 @EnableAISecurity(mode = SecurityMode.FULL)을 사용합니다. 사용자는 있는데 체인이 없으면 Spring Boot 기본 보안이 켜져 모든 요청이 인증을 요구하고, 기동 로그에 WARN 한 줄이 남습니다. 기존 앱의 보안 설정과 함께 쓰는 방법은 Spring Boot 앱에 붙이기를 참고합니다.

값이 정해지는 순서

대부분의 설정은 application.yml에 적은 값이 그대로 적용됩니다. 아래 경우에는 다른 곳의 값이 우선합니다. 값을 바꿨는데 동작이 달라지지 않으면 먼저 이 표를 확인합니다.

경우우선하는 값
@EnableAISecurity를 붙였을 때앱 설정에 적은 contexa.ai.security.* 값이 어노테이션 속성(mode 등)보다 우선합니다. 어노테이션 속성은 설정을 적지 않았을 때의 기본값입니다. 인증 소유권 contexa.bridge.ownership과 contexa.datasource.isolation.contexa-owned-application은 직접 적지 않았을 때만 mode를 따릅니다(FULL이면 CONTEXA_OWNED · true). 직접 적은 소유권이 mode와 어긋나면 기동을 거부합니다.
단독 모드(기본)contexa.cache.type은 무엇을 적어도 LOCAL입니다.
관리 화면 시스템 설정(/contexa/admin/system-settings)에서 운영 모드를 저장했을 때저장한 모드가 contexa.security.zerotrust.mode보다 우선합니다. 저장하는 즉시 적용되고, 이후 기동할 때마다 다시 적용됩니다(운영 모드).
관리 화면 시스템 설정에 정책 판정 값이 저장되어 있을 때정책 결합 방법과 정책이 없는 메서드의 결정은 contexa.policy.*보다 저장된 값이 우선합니다. 정책이 없는 URL의 결정은 운영자가 저장한 뒤에야 저장된 값이 우선하며, 그 전에는 contexa.policy.no-matching-url-policy-decision이 적용됩니다(기본 AUTHENTICATED). 기본 시드(첫 기동에서 넣는 기본 데이터)가 이 설정 행을 처음부터 넣습니다(인가 정책).
옛 접두사로 적은 키읽히지 않습니다. 옛 접두사의 별칭이 없으므로 새 이름만 읽습니다(옛 접두사).
CONTEXA가 넣는 기본값pgvector 표 이름 · 차원 · 표 자동 생성(contexa.vectorstore.pgvector.*)과, 채팅 · 임베딩 공급자를 하나로 정했을 때 그 공급자를 고르는 Spring AI 기본값(spring.ai.model.chat · spring.ai.model.embedding)은 우선순위가 가장 낮습니다. 직접 적은 값이 있으면 그 값이 쓰입니다. 이 기본값 가운데 contexa.*가 아닌 것은 @EnableAISecurity로 CONTEXA가 켜져 있는 동안에만 설정 값으로 읽힙니다.

옮겨 간 키 · 없어진 키

옛 문서나 예제에서 본 설정 이름이 이 절의 표에 있으면 지금 이름으로 바꿔 적습니다. 이 절의 표 밖에서는 이 문서가 옛 이름을 쓰지 않습니다. 표는 네 가지입니다.

  1. 옛 접두사: 접두사가 바뀐 키입니다. 별칭이 없어 옛 이름은 읽히지 않습니다.
  2. 이름이 틀렸던 키: 옛 문서에 잘못 적혀 있던 이름입니다.
  3. 없어진 키: 코드에서 제거되었거나 코드에 없는 이름입니다.
  4. 효과가 없는 설정: 설정 클래스에는 있지만 코드가 값을 읽지 않는 키입니다.

옛 접두사(별칭 없음, 읽히지 않음)

이 표의 옛 이름(오른쪽 열)으로 적은 키는 효과가 없습니다. CONTEXA는 새 이름의 별칭을 만들지 않고, 기동 로그에도 알림을 남기지 않습니다. 옛 이름은 앱 자신의 설정이므로 CONTEXA는 이를 읽거나 옮기지 않습니다. 옛 이름을 쓰던 앱은 왼쪽 열의 새 이름으로 바꿔 적어야 합니다.
