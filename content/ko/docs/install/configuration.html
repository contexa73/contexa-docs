contexa-autoconfigure 설정

설정 길잡이

하려는 일에 맞는 설정 쪽을 찾고, 그대로 기동하는 최소 설정으로 시작합니다. 옛 문서 · 예제에서 본 설정 이름이 지금 무엇인지도 이 쪽 끝의 표에서 확인합니다.

할 일별로 찾기

Contexa 설정은 모두 Spring Boot가 읽는 곳(application.yml, 환경 변수 등)에 적습니다. 무엇을 바꾸려는지에 따라 아래 쪽을 보세요. 한 설정은 한 쪽에서만 자세히 설명하고, 다른 쪽은 그 쪽으로 링크합니다.

설정이 작용하는 자리

Contexa는 두 줄기로 일합니다. 요청이 들어오면 이미 저장된 판정을 적용하고(요청 시점), 응답이 나간 뒤에는 그 요청을 분석해 다음 요청에 쓸 판정을 만듭니다(비동기 판정). 두 줄기는 판정 저장소에서 만납니다. 상자마다 그 자리를 정하는 설정 쪽을 적었습니다.

그대로 기동하는 최소 설정

새 Spring Boot 앱에 Contexa를 붙여 판정까지 돌려 보는 가장 작은 구성입니다. OpenAI 모델 하나와, pgvector 확장을 쓸 수 있는 PostgreSQL 하나를 씁니다. 다른 모델(Anthropic · Ollama)은 AI 모델 연결을 보세요.

dependencies {
    implementation 'ai.ctxa:spring-boot-starter-contexa:0.1.0'
    implementation platform('org.springframework.ai:spring-ai-bom:1.1.8')
    implementation 'org.springframework.ai:spring-ai-starter-model-openai'
    implementation 'org.springframework.ai:spring-ai-starter-vector-store-pgvector'
}
import io.contexa.contexacommon.annotation.EnableAISecurity;

@SpringBootApplication
@EnableAISecurity
public class MyApplication {
    public static void main(String[] args) {
        SpringApplication.run(MyApplication.class, args);
    }
}
contexa:
  datasource:
    url: jdbc:postgresql://localhost:5432/contexa
    username: contexa
    password: ${CONTEXA_DB_PASSWORD}
    isolation:
      contexa-owned-application: true   # 앱에 자기 DB가 없을 때만. 아래 상자 참고

spring:
  ai:
    openai:
      api-key: ${OPENAI_API_KEY}

이 구성으로 기동하면 다음이 정해집니다.

  • 첫 기동에 Contexa 전용 DB에 Contexa의 표와 기본 데이터를 만들고(contexa.iam.seed.enabled, 기본 true), pgvector 확장 · 벡터 표를 만듭니다(Contexa가 넣는 기본값 spring.ai.vectorstore.pgvector.initialize-schema=true).
  • 판정 모델은 OpenAI 채팅 모델, 임베딩은 Contexa가 기본으로 정한 OpenAI text-embedding-3-small(1024차원)입니다.
  • 집행 모드는 ENFORCE(판정을 저장하고 다음 요청부터 적용), 인프라 모드는 단독(판정 · 학습 상태를 메모리에 둠)입니다.
  • 로그인은 앱이 맡습니다(HOST_OWNED). 그래서 판정은 @Protectable을 붙인 메서드에서 집행됩니다. 무엇을 보호할지는 @Protectable에서 정합니다.
contexa-owned-application: true는 앱에 자기 DB가 없을 때만 넣습니다. 이 값을 켜면 앱의 기본 DataSource · JdbcTemplate까지 Contexa DB가 됩니다. Spring AI의 pgvector 자동설정은 앱의 기본 JdbcTemplate으로 벡터 저장소를 만들기 때문에, 새 앱에서는 이 줄로 벡터 표가 Contexa DB에 생깁니다. 자기 DB가 있는 앱은 이 줄을 빼세요. 그러면 벡터 저장소는 앱의 기본 DB를 씁니다(그 DB가 pgvector를 쓸 수 있어야 함). 벡터 저장소를 Contexa DB에 두려면 contexaDataSource를 쓰는 VectorStore 빈을 직접 선언하세요. 그러면 Spring AI의 자동설정이 물러납니다. 자세한 내용은 전용 DB에 있습니다.
앱에 SecurityFilterChain이 없으면 Spring Boot 기본 보안이 켜져 모든 요청이 인증을 요구하고, 기동 로그에 ERROR 한 줄이 남습니다. 기존 앱의 보안 설정과 함께 쓰는 방법은 Spring Boot 앱에 붙이기를 보세요.

값이 정해지는 순서

대부분의 설정은 application.yml에 적은 값이 그대로 쓰입니다. 다만 아래 경우에는 다른 곳의 값이 이깁니다. 값을 바꿨는데 동작이 그대로라면 먼저 이 표를 보세요.

경우이기는 값
@EnableAISecurity를 붙였을 때어노테이션 속성(mode 등)이 contexa.ai.security.*를 늘 덮어씁니다. 인증 소유권 contexa.bridge.ownership과 contexa.datasource.isolation.contexa-owned-application은 직접 적지 않았을 때만 어노테이션 mode로 정해집니다(FULL이면 CONTEXA_OWNED · true).
단독 모드(기본)contexa.cache.type은 무엇을 적어도 LOCAL입니다.
관리 화면 시스템 설정(/contexa/admin/system-settings)에서 집행 모드를 저장했을 때저장한 모드가 contexa.security.zerotrust.mode를 이깁니다. 저장하는 즉시, 그리고 기동할 때마다 적용됩니다(집행 모드).
관리 화면 시스템 설정에 정책 판정 값이 저장되어 있을 때정책 결합 방법, 정책이 없는 URL · 메서드의 결정이 contexa.policy.*보다 우선합니다. 기본 시드가 이 행을 처음부터 넣습니다(인가 정책).
옛 접두사와 새 이름을 함께 적었을 때새 이름의 값이 이깁니다. 옛 접두사는 가장 낮은 우선순위의 별칭입니다(옛 접두사).
Contexa가 넣는 기본값pgvector 표 이름 · 차원 · 표 자동 생성, OpenAI 임베딩 모델 같은 Spring AI 기본값은 가장 낮은 우선순위입니다. 직접 적으면 그 값이 쓰입니다. 이 기본값은 @EnableAISecurity로 켜졌을 때만 보입니다.
