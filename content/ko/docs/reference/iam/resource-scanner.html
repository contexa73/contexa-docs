리소스 스캐너

앱의 컨트롤러 URL과 @Protectable 메서드를 찾아 관리 콘솔의 보호 대상 목록(리소스)으로 모으고, 권한과 정책을 붙이는 방법을 설명합니다. 스캔은 관리자가 "리소스 불러오기"를 누를 때만 돌고, 시스템 설정에 적은 패키지와 앱 자신의 패키지 안만 봅니다.

앱 자신의 패키지는 따로 적지 않아도 스캔됩니다. 스캔 패키지의 기본값은 io.contexa.contexaiam.(Contexa 관리 화면 자체)이고, 두 스캐너는 여기에 Spring Boot가 아는 앱의 패키지(@SpringBootApplication이 있는 패키지)를 항상 더합니다. 설정은 더하기만 하므로, 앱 패키지 밖의 클래스를 찾으려면 관리 콘솔의 "IAM → 시스템 설정 → 리소스 스캔 설정 → 컨트롤러 기본 패키지"에 그 패키지(예: com.example.shared)를 적으세요. 앱을 시작할 때 자동으로 스캔하는 기능은 없습니다.

한눈에 보기

리소스는 "보호할 수 있는 곳" 하나입니다. URL 리소스는 컨트롤러의 경로 하나, 메서드 리소스는 @Protectable이 붙은 서비스 메서드 하나입니다. 리소스에 권한을 정의하고 정책을 연결하면, 그 정책이 요청을 판정합니다.

스캔할 패키지 정하기

두 스캐너(URL · 메서드)는 같은 패키지 목록을 씁니다. 앱 자신의 패키지(Spring Boot가 아는 패키지)는 적지 않아도 늘 더해집니다. 그 밖의 패키지를 더하려면 관리 콘솔의 "IAM → 시스템 설정(/contexa/admin/system-settings) → 리소스 스캔 설정 → 컨트롤러 기본 패키지"에 적습니다.

com.example.shop
com.example.billing
  • 한 줄에 하나씩 적거나 쉼표로 나눕니다. 끝의 점(.)은 자동으로 붙습니다.
  • 적은 패키지 자체와 그 아래 패키지가 대상입니다. com.example.shop이면 com.example.shop.api도 들어갑니다.
  • 값은 Contexa DB의 system_settings 표에 저장됩니다. 기본 시드가 io.contexa.contexaiam.을 넣고, 비워 두면 이 기본값을 씁니다. Contexa 관리 화면의 컨트롤러도 계속 목록에 두려면 이 값을 함께 적습니다.
  • 바꾼 값은 다음 "리소스 불러오기"부터 쓰입니다.

스캔 실행

정책 센터(/contexa/admin/policy-center)의 "정책 생성" 탭에서 "리소스 불러오기"를 누릅니다(POST /contexa/admin/policy-center/refresh-resources). 앱을 배포하거나 새 엔드포인트를 더한 뒤에는 다시 누르세요. 옛 경로 POST /contexa/admin/workbench/resources/refresh도 스캔을 돌리지만, 아래 6번은 "정책 연결 완료 → 정책 연결 대상" 한쪽만 맞추고 7번은 하지 않습니다.

  1. 모든 스캐너가 리소스를 모읍니다.
  2. 같은 식별자가 여럿이면 처음 찾은 하나만 씁니다.
  3. 목록에 없던 리소스만 새로 등록합니다. 100개씩 AI에게 이름 · 설명을 받아 "정책 미 설정"(NEEDS_DEFINITION)으로 저장합니다(이름 붙이기). 이미 있는 리소스의 이름 · 설명은 바꾸지 않습니다.
  4. 코드에서 사라진 리소스는 지우지 않고 오류 로그에 개수와 예 하나만 남깁니다.
  5. contexa.iam.admin.condition-templates.enabled: true이면 조건 템플릿을 AI로 만듭니다(조건 템플릿).
  6. 리소스 상태를 정책과 맞춥니다. "정책 연결 완료"인데 그 리소스를 대상으로 하는 정책이 없으면 "정책 연결 대상"으로, "정책 연결 대상"인데 정책이 있으면 "정책 연결 완료"로 바꿉니다.
  7. 읽기 쉬운 설명이 비어 있는 정책에 설명을 채웁니다.

URL 리소스

Spring MVC의 RequestMappingHandlerMapping(빈 이름 requestMappingHandlerMapping)에 등록된 핸들러 메서드를 모두 봅니다. @GetMapping · @PostMapping 등 모든 매핑 애노테이션이 대상입니다.

  • 핸들러 클래스가 스캔 패키지 안에 있고 @Controller 또는 @RestController가 붙어 있어야 합니다. 보안 애노테이션은 필요 없습니다.
  • 매핑에 경로가 여러 개면 첫 경로, HTTP 메서드가 여러 개면 첫 메서드만 씁니다. 메서드가 없으면 ANY입니다.
  • 식별자는 URL 패턴만입니다. 그래서 같은 경로의 GET과 POST는 리소스 하나로 합쳐지고, 처음 찾은 쪽의 HTTP 메서드가 남습니다. 이 리소스로 만든 정책의 대상도 그 메서드 하나라서, 같은 경로의 다른 메서드는 그 정책에 맞지 않습니다. 다른 메서드까지 다루려면 "리소스 권한 설정하기"로 HTTP 메서드 ANY 대상을 넣거나, 수동 모드에서 대상을 더하세요.

메서드 리소스

앱 컨텍스트의 빈을 하나씩 꺼내 실제 클래스(프록시 안쪽, AopUtils.getTargetClass())를 봅니다.

  • 클래스가 스캔 패키지 안에 있어야 하고, @Controller · @RestController 클래스는 건너뜁니다(컨트롤러는 URL 리소스로 잡힘).
  • 그 클래스에 선언된 public 메서드 가운데 @Protectable이 붙은 메서드마다 리소스 하나를 만듭니다. 클래스에 @Protectable을 붙였다면 그 클래스의 public 정적이 아닌 메서드 모두가 리소스가 됩니다.

이름 붙이기

식별자만으로는 무슨 기능인지 알기 어려워서, 새로 등록하는 리소스에 AI가 읽기 쉬운 이름과 설명을 붙입니다. 예를 들면 아래와 같습니다.

식별자AI가 붙인 이름(예)
GET /api/usersList All Users
PUT /api/users/{id}Update User Profile
DELETE /admin/roles/{id}Delete Role
AccountService.updateAccount(Long,AccountDto)Update Account Details
  • 새 리소스만, 100개씩 한 번에 묻습니다. 식별자 · 서비스 소유자 · 유형 · HTTP 메서드 · 스캐너가 붙인 이름과 설명 · 파라미터 · 반환 타입 · API 문서 링크 · 소스 위치를 함께 보냅니다.
  • 요청은 AI 엔진의 ResourceNamingLab이 처리합니다(템플릿 · 진단 유형 이름 "ResourceNaming"). 별도의 이름 짓기 서비스가 있는 것은 아닙니다.
  • AI가 답하지 못한 리소스는 다시 묻지 않고 대체 값으로 저장합니다. 스캐너가 넣은 이름 · 설명이 있으면 그대로 두고(URL 리소스는 핸들러 메서드 이름), 이름이 비어 있으면 식별자 끝부분에 Feature를 붙인 이름, 설명이 비어 있으면 AI suggestion unavailable을 넣습니다.
  • AI 모델 연결이 필요합니다. 모델이 없거나 실패해도 스캔은 대체 값으로 끝납니다.

목록 보기와 거르기

"정책 생성" 탭의 리소스 목록은 서비스 소유자 · 상태 · 키워드(식별자 · 이름 · 설명)로 거릅니다. 리소스 유형(URL · METHOD)으로 거르는 칸은 없습니다. 상태를 고르지 않으면 "제외" 리소스는 숨깁니다.

상태(화면 이름)코드 값뜻

대시보드의 "정책 센터" 카드(정책 연결 대상 · 정책 연결 완료 · 정책 미완료)와 GET /contexa/admin/policy-center/api/stats(상태별 개수)로 전체 상황을 봅니다.

권한으로 정의하기

  1. 리소스 줄의 "권한 생성 & 정책 생성"을 누릅니다.
  2. Contexa가 리소스를 "정책 연결 대상"으로 바꾸고 자동 권한을 만듭니다(POST /contexa/admin/workbench/resources/{id}/define, 이름 · 설명을 함께 보냄).
  3. "정책 설정 방법 선택" 창에서 간편 모드나 AI 정책 마법사를 고릅니다(정책 연결).

자동 권한의 이름은 리소스 유형과 식별자로 만듭니다. 영문자 · 숫자가 아닌 글자는 _로 바꾸고 대문자로 씁니다.

/api/v1/invoices/{id}                             → URL_API_V1_INVOICES_ID
com.example.docs.DocumentService.getDocument(Long) → METHOD_DOCUMENTSERVICE_GETDOCUMENT
  • 자동 권한은 자동 생성 표시가 붙고, 동작 종류는 URL이면 HTTP 메서드, 메서드면 EXECUTE입니다.
  • 자동 권한은 리소스와 정책 대상을 잇는 데만 쓰이고, 정책 조건에는 들어가지 않습니다(간편 모드).
  • 여러 리소스를 체크해 한꺼번에 정의할 수 있습니다(POST /contexa/admin/workbench/resources/define-batch). 이미 권한이 있는 리소스는 건너뜁니다.

정책 연결

"정책 설정 방법 선택" 창에는 두 가지가 있습니다. 수동 모드는 이 창에서 들어가지 않고 "정책 생성" 탭의 카드로 엽니다.

  • 간편 모드: 역할 · 권한을 골라 ALLOW 또는 DENY 정책을 바로 만듭니다. 여러 리소스를 골랐으면 일괄 생성으로 만듭니다.
  • AI 정책 마법사: 리소스 하나만 받습니다. AI가 만든 초안은 승인 대기로 저장되고, 승인한 뒤 적용됩니다.

정책을 저장하면 리소스가 "정책 연결 완료"로 바뀌고, 정책이 바로 다시 읽혀 다음 요청부터 적용됩니다. URL 정책은 요청이 CustomDynamicAuthorizationManager를 지나야 평가되므로, 기본 HOST_OWNED에서는 앱 체인에 연결해야 합니다(준비하기). 모드별 자세한 동작은 정책 관리에 있습니다.

제외 · 복원 · 되돌리기

  • 제외: "정책 미 설정" 리소스만 제외할 수 있습니다(POST /contexa/admin/workbench/resources/{id}/exclude). "정책 연결 대상" 줄에도 제외 버튼이 보이지만 서버가 거부합니다.
  • 제외의 실제 뜻: 리소스 목록과 권한 목록에서 숨길 뿐, 인가 판정은 바뀌지 않습니다. 정책이 없는 URL은 "정책이 없을 때의 결정"(기본 PERMIT)을 따릅니다. 공개해야 할 경로(/actuator/health 같은)는 정책으로 열거나 앱 체인의 permitAll로 여세요.
  • 복원: 제외한 리소스를 "정책 미 설정"으로 되돌립니다(POST /contexa/admin/workbench/resources/{id}/restore).
  • 정책연결대상해제: 고른 리소스 가운데 "정책 연결 대상"인 것만 연결된 권한을 지우고 "정책 미 설정"으로 되돌립니다(POST /contexa/admin/policy-center/api/reset-policy-status).
  • 정책 삭제: 지운 정책의 대상인 리소스를 다른 정책이 쓰지 않으면 "정책 미 설정"으로 되돌리고 자동 권한을 지웁니다.

확장점

스캐너는 ResourceScanner 인터페이스 하나입니다. 이 타입의 빈을 더하면 리소스 불러오기 때 기본 스캐너와 함께 쓰입니다. 기본 스캐너를 바꾸려면 MvcResourceScanner · MethodResourceScanner 타입의 빈을 직접 선언합니다(자동 설정이 물러남). 직접 만든 스캐너에는 패키지 설정이 적용되지 않으니 스캐너 안에서 고르세요.

import io.contexa.contexacommon.entity.ManagedResource;
import io.contexa.contexaiam.resource.scanner.ResourceScanner;
import org.springframework.stereotype.Component;

import java.util.List;

@Component
public class ReportEndpointScanner implements ResourceScanner {

    @Override
    public List<ManagedResource> scan() {
        return List.of(ManagedResource.builder()
                .resourceIdentifier("/reports/export")
                .resourceType(ManagedResource.ResourceType.URL)
                .httpMethod(ManagedResource.HttpMethod.GET)
                .friendlyName("exportReport")
                .serviceOwner("ReportRouter")
                .status(ManagedResource.Status.NEEDS_DEFINITION)
                .build());
    }
}

리소스 엔티티 ManagedResource는 contexa-common 모듈(io.contexa.contexacommon.entity)에 있습니다. 필드는 식별자 · 유형 · HTTP 메서드 · 이름 · 설명 · 서비스 소유자 · 파라미터 타입 · 반환 타입 · API 문서 링크 · 소스 위치 · 쓸 수 있는 문맥 변수(availableContextVariables) · 상태 · 연결된 권한 · 만든 시각 · 고친 시각입니다. 이름은 비울 수 없습니다. 스캔 · 정의 · 제외를 묶는 ResourceRegistryService도 같은 타입의 빈을 선언하면 바꿀 수 있습니다.

옛 경로

/contexa/admin/workbench/resources는 옛 리소스 화면 경로입니다. 화면 파일이 없어 GET으로는 열리지 않지만, 정책 센터가 이 컨트롤러의 API를 그대로 씁니다: POST /refresh · /{id}/define · /define-batch · /{id}/exclude · /{id}/restore · /{id}/manage.
