모델 연결과 선택

Contexa가 쓸 AI 모델 공급자(OpenAI · Anthropic · Ollama 등)를 연결하고, 기본 모델과 층(1차 · 2차)별 모델을 정하는 방법을 설명합니다. 요청마다 어느 모델이 쓰였는지 확인하는 방법과 임베딩 모델 고르기도 다룹니다.

한눈에 보기

이 페이지에서 쓰는 말입니다.

  • 공급자(provider): 모델을 제공하는 곳. openai · anthropic · ollama 같은 이름으로 부릅니다.
  • 연결(바인딩): Spring 빈으로 만들어진 채팅 모델 · 임베딩 모델 하나와 그것을 찾는 이름들(빈 이름 · 런타임 ID · 모델 ID · 별칭). 연결 목록을 카탈로그(LlmRuntimeCatalog)라고 합니다.
  • 기본 채팅 모델: 다른 모델을 고르지 못했을 때 늘 쓰는 채팅 모델(빈 이름 primaryChatModel).
  • 층 모델: 1층 · 2층에 정한 모델. 보안 판정 엔진의 1차 · 2차 분석과 층을 지정한 호출이 씁니다.

공급자 연결하기

모델 연결은 Spring AI가 합니다. 공급자 스타터를 넣고 spring.ai.<공급자>.*를 설정하면 그 공급자의 모델 빈이 생기고, Contexa는 그 빈을 찾아 씁니다. Contexa에는 contexa.llm.openai.* 같은 공급자 키가 따로 없습니다.

# 의존성: org.springframework.ai:spring-ai-starter-model-openai
# 그 밖의 필수 설정(contexa.datasource.url 등)은 빠른 시작을 따릅니다.
spring:
  ai:
    openai:
      api-key: ${OPENAI_API_KEY}
      chat:
        options:
          model: gpt-4o-mini
  • 채팅 모델이 하나도 없으면 Contexa의 LLM 빈(기본 채팅 모델 · 오케스트레이터)이 만들어지지 않습니다.
  • contexa.llm.selection.chat.priority에 공급자를 하나만 적으면(openai · anthropic · ollama), Contexa가 spring.ai.model.chat을 그 공급자로 기본 설정해 Spring AI가 그 공급자의 채팅 모델만 만들게 합니다. contexa.llm.selection.embedding.priority의 첫 공급자(openai · ollama)는 spring.ai.model.embedding이 됩니다. 직접 적은 값이 늘 이깁니다.
  • contexa.llm.enabled=false면 Contexa의 LLM 자동 구성 전체가 꺼집니다.

Contexa 전용 Ollama 연결

Spring AI 스타터 설정 없이 Contexa 설정만으로 Ollama 채팅 모델을 만들 수 있습니다. 클래스패스에 Spring AI Ollama 라이브러리(OllamaChatModel)가 있어야 합니다.

contexa:
  llm:
    chat:
      ollama:
        base-url: http://localhost:11434   # 넣으면 켜짐
        model: qwen2.5:7b                  # 비우면 qwen3:8b
        keep-alive: 10m                    # 비우면 Ollama 기본
  • base-url을 넣는 것이 스위치입니다. 채팅 모델 빈 contexaOllamaChatModel과, 같은 서버를 쓰는 임베딩 모델 빈 contexaSharedOllamaEmbeddingModel이 함께 생깁니다.
  • 임베딩 모델 이름은 contexa.llm.embedding.ollama.model(비우면 mxbai-embed-large)입니다. 임베딩을 다른 서버에서 돌리려면 contexa.llm.embedding.ollama.dedicated-runtime-enabled=true와 contexa.llm.embedding.ollama.base-url을 넣습니다.
  • 주의: 이 빈의 연결 모델 ID는 contexa.llm.chat.ollama.model이 아니라 spring.ai.ollama.chat.options.model(없으면 빈 이름)에서 옵니다. 층 모델 이름으로 이 빈을 가리키려면 연결에 이름 붙이기로 모델 ID를 적어 주세요.

기본 채팅 모델 고르기

공급자를 여럿 넣었을 때 어느 모델을 기본 채팅 모델로 쓸지 contexa.llm.selection.chat.mode로 정합니다.

mode 값고르는 방법언제 쓰나
dynamic-priority(기본)priority(기본 openai,anthropic,ollama)의 순서대로, 빈이 준비된 첫 공급자의 모델. 목록의 공급자가 하나도 준비되지 않았으면 아무 연결이나 씁니다.여러 공급자를 두고 순서만 정할 때
fixedpriority에 적은 공급자 하나의 모델만. 둘 이상 적으면 시작하지 않고, 그 공급자가 준비되지 않았으면 다른 공급자로 바꾸지 않고 시작이 실패합니다.반드시 한 공급자만 써야 할 때
spring-primarySpring @Primary 표시가 된 연결. 연결이 하나뿐이면 그것. @Primary가 둘 이상이거나, 연결이 여럿인데 하나도 없으면 시작하지 않습니다.앱이 이미 @Primary 채팅 모델을 정해 두었을 때
값은 소문자와 하이픈으로 씁니다. 기본 채팅 모델 빈을 만드는 조건이 dynamic-priority · fixed · spring-primary 표기와 비교합니다. 대문자 열거형 이름(DYNAMIC_PRIORITY, SPRING_PRIMARY)으로 쓰면 설정은 받아들여지지만 조건이 맞지 않아 기본 채팅 모델 빈이 만들어지지 않습니다. 
contexa:
  llm:
    selection:
      chat:
        mode: fixed
        priority: anthropic

priority가 비어 있을 때만 옛 설정 contexa.llm.chat-model-priority를 읽습니다(폐기 예정).

연결에 이름 붙이기(bindings)

Contexa는 시작할 때 채팅 · 임베딩 모델 빈마다 연결을 하나씩 만듭니다. 설정이 없어도 아래처럼 알아냅니다.

  • 공급자: 빈 클래스와 빈 이름에 든 말로 정합니다. ollama → ollama, anthropic · claude → anthropic, openai · azureopenai → openai, gemini · vertex → gemini, mistral → mistral, bedrock → bedrock, huggingface · hf → huggingface, 그 밖은 spring.
  • 모델 ID: 채팅은 spring.ai.openai.chat.options.model(Azure는 spring.ai.azure.openai.chat.options.deployment-name · .model), spring.ai.anthropic.chat.options.model, spring.ai.ollama.chat.options.model. 임베딩은 spring.ai.openai.embedding.options.model(Azure 포함) · spring.ai.ollama.embedding.options.model. 값이 없으면 빈 이름입니다.
  • 연결은 빈 이름 · 런타임 ID · 모델 ID · 별칭 가운데 어느 것으로도 찾을 수 있습니다.

이름을 바꾸거나 더하려면 contexa.llm.bindings.chat.<ID>(임베딩은 .embedding.<ID>)를 씁니다. <ID>가 빈 이름과 같거나 bean-name이 빈 이름과 같으면 그 빈의 연결이 되고, <ID>가 런타임 ID가 됩니다.

contexa:
  llm:
    bindings:
      chat:
        contexaOllamaChatModel:        # 키 = 빈 이름
          model-id: qwen2.5:7b         # 이 이름으로 찾게 함
          aliases: [local-small]       # 더 붙일 이름
          # provider: ollama             # 비우면 위 규칙으로 정함
          # primary: true                # spring-primary 선택에서 이 연결을 고름
          # enabled: false               # 이 설정을 쓰지 않음
  • 같은 이름(선택자)이 두 연결에 걸리면 시작하지 않습니다(Duplicate chat runtime selector '…'). 빈 이름 · 런타임 ID · 모델 ID · 별칭을 겹치지 않게 두세요.
  • bean-name이 가리키는 빈이 없으면 WARN 로그를 남기고 그 설정을 건너뜁니다.

층(1차 · 2차) 모델 정하기

층 모델은 contexa.security.tiered.llm.layer1.model · layer2.model로 정하고, 비워 두면 기본 채팅 모델을 씁니다. 층마다 backup.model도 둘 수 있습니다. 보안 판정 엔진에서 쓰는 방법은 판정 엔진: 층마다 다른 모델 쓰기에 있고, 여기서는 이름이 실제 모델이 되는 규칙을 설명합니다.

공급자를 섞으려면 층 모델 이름을 각 연결의 모델 ID와 같게 둡니다. 아래는 1층은 Ollama, 2층과 기본 채팅 모델은 OpenAI로 두는 예입니다(스타터 spring-ai-starter-model-openai · spring-ai-starter-model-ollama를 함께 넣음).

spring:
  ai:
    openai:
      api-key: ${OPENAI_API_KEY}
      chat:
        options:
          model: gpt-4o-mini        # OpenAI 연결의 모델 ID
    ollama:
      base-url: http://localhost:11434
      chat:
        options:
          model: qwen2.5:7b         # Ollama 연결의 모델 ID
contexa:
  llm:
    selection:
      chat:
        priority: openai,ollama     # 기본 채팅 모델은 OpenAI
  security:
    tiered:
      llm:
        layer1:
          model: qwen2.5:7b         # Ollama 연결과 같은 이름 → Ollama
        layer2:
          model: gpt-4o-mini        # OpenAI 연결과 같은 이름 → OpenAI
  • 이름이 어느 연결과도 맞지 않으면 기본 채팅 모델의 복사본이 그 이름을 그대로 그 공급자에 보냅니다. 예를 들어 기본 채팅 모델이 OpenAI인데 층 모델을 qwen2.5:7b로 두고 맞는 연결이 없으면, OpenAI에 qwen2.5:7b를 요청하게 됩니다.
  • 시작할 때 검사합니다. 층 모델(layer1.model · layer2.model)을 만들 수 없으면 … cannot be used, so layer N runs on …: no chat runtime binding has this model id and the primary chat model cannot be copied with it …로 ERROR 로그를 한 줄 남깁니다. 시작은 멈추지 않고, 그 층은 백업 모델이 있으면 백업 모델로, 없으면 기본 채팅 모델로 돕니다. 백업 모델은 시작할 때 검사하지 않습니다.
  • contexa.security.tiered.llm.tiered.layer1.timeout-ms · layer2.timeout-ms는 stream()의 층 제한 시간에만 쓰입니다(LLM 호출하기). 보안 판정의 1차 · 2차 제한 시간은 다른 설정입니다(판정 엔진 설정).

요청마다 모델이 정해지는 순서

호출마다 모델 고르기 전략(DynamicModelSelectionStrategy)이 아래 순서로 정합니다.

  1. 명시한 모델: ExecutionContext.preferredModel, 없으면 메타데이터 requestedModelId → preferredModel → modelId. 메타데이터 runtimeModelId는 고르기 전에 지워지므로 입력으로 쓰이지 않습니다. 만들 수 없는 모델이면 실패를 기록하고 다음 단계로 내려갑니다.
  2. 층 모델: analysisLevel → securityTaskType → tier 순서로 층을 정합니다. 1 이하는 1층, 2 이상은 2층입니다. 그 층의 모델이 비어 있으면 4로 갑니다.
  3. 백업 모델: 층 모델을 만들 수 없을 때 그 층의 backup.model
  4. 기본 채팅 모델: 늘 마지막 후보. 아무 모델도 없으면 null을 돌려주고 호출은 오류로 끝납니다. 고르는 중 예외가 나면 ModelSelectionException입니다.
modelSelectionSource 값뜻
explicit_model명시한 모델
analysis_level:NORMAL 등analysisLevel로 정한 층 모델
security_task_type:FORENSIC_ANALYSIS 등작업 종류로 정한 층 모델
tier:2 등tier로 정한 층 모델
위 값 뒤에 :backup그 층의 백업 모델
primary_chat_model기본 채팅 모델

모델을 고르면 그 호출의 ExecutionContext 메타데이터에 결과가 남습니다(호출 결과 확인하기에는 호출 시간 · 토큰 수도 있습니다).

임베딩 모델 고르기

임베딩 모델은 문서를 벡터로 바꿀 때 씁니다(RAG). 벡터 저장소의 차원이 임베딩 모델 하나에 묶이므로, 임베딩은 공급자 하나로 고정합니다.

contexa.llm.selection.embedding.mode고르는 방법
fixed(기본)priority(기본 openai)에 적은 공급자 하나. 둘 이상 적으면 시작하지 않습니다. 그 공급자의 연결이 준비되지 않았으면 다른 임베딩 연결을 씁니다.
spring-primary@Primary 임베딩 연결(채팅과 같은 규칙)
dynamic-priority지원하지 않습니다. 고르면 시작할 때 실패합니다.

차원을 맞추는 방법과 시작할 때의 차원 검사는 RAG: 준비에 있습니다.

공급자별 기능 설정

모델마다 받는 옵션이 다릅니다. Contexa가 옵션을 맞출 때(공급자별 옵션) 쓰는 모델 목록을 바꿀 수 있습니다. 목록은 정규식을 쉼표로 이은 것이고, 모델 ID 전체가 맞아야 합니다.

  • contexa.llm.model-capabilities.openai.max-completion-token-patterns: max_completion_tokens로 출력 길이를 보낼 OpenAI 모델. 기본 gpt-5(?:[.-].*)?,o\d+(?:[.-].*)?.
  • contexa.llm.model-capabilities.openai.default-sampling-only-patterns: temperature · topP를 빼고 보낼 OpenAI 모델. 기본은 위와 같은 목록.
  • contexa.llm.model-capabilities.anthropic.default-sampling-only-patterns: 샘플링 값을 빼고 보낼 Claude 모델. 기본은 코드에 정해진 Claude 모델 목록입니다.
  • contexa.llm.model-capabilities.anthropic.thinking: Claude 모델별로 받는 생각(thinking) · effort 표. 적으면 기본 표를 대신합니다.
  • contexa.llm.model-capabilities.anthropic.system-prompt-cache(기본 true): 캐시 설정이 없을 때 시스템 프롬프트를 캐시할지.
  • contexa.llm.model-capabilities.ollama.disable-thinking-patterns: 생각을 끄고 보낼 Ollama 모델(기본 없음).

OpenAI · Ollama 목록과 Anthropic 샘플링 목록은 같은 이름의 JVM 시스템 속성이나 환경 변수(예: CONTEXA_LLM_MODEL_CAPABILITIES_OPENAI_MAX_COMPLETION_TOKEN_PATTERNS)가 있으면 그것을 먼저 씁니다.

확장점

빈직접 두면
ModelSelectionStrategy호출마다 모델을 고르는 규칙을 바꿉니다(기본 DynamicModelSelectionStrategy).

ModelDescriptor — 등록된 모델의 설명

@Data @Builder 클래스입니다. 설명용 값이며, 호출 옵션을 만들 때는 쓰이지 않습니다.

값뜻 · 기본값
modelId · displayName모델 ID와 표시 이름(등록할 때는 둘 다 정규 ID)
provider공급자
tier층 모델로 등록됐으면 1 또는 2, 아니면 null
version버전 글
capabilitiesModelCapabilities: streaming true, toolCalling · functionCalling · multiModal false, maxTokens · contextWindow · maxOutputTokens 4096
optionsModelOptions: temperature 0.7, topP 0.9, topK null, repetitionPenalty 1.0
statusAVAILABLE(기본) 또는 UNAVAILABLE(ModelStatus)

supportsAdvancedFeatures()는 도구 호출 · 함수 호출 · 멀티모달 가운데 하나라도 켜져 있으면 true입니다.

DynamicModelRegistry — 모델 등록과 캐시

시작할 때(@PostConstruct) 카탈로그의 채팅 연결을 모두 등록하고, 이어서 층 모델 · 백업 모델 이름을 그 층으로 등록합니다. 연결이 없는 층 모델 이름은 이름에 든 말로 공급자를 짐작해 적습니다(llama · qwen · gemma · mistral · phi · exaone · codellama · deepseek → ollama, claude → anthropic, gpt · o1 · davinci → openai, gemini · vertex → gemini, bedrock → bedrock, 그 밖 spring). 생성자로 받는 ApplicationContext는 쓰지 않고, 카탈로그는 없어도 됩니다.

메서드하는 일
getModel(modelId)이름에 맞는 연결의 모델(만든 것은 캐시). 연결이 없으면 기본 채팅 모델 복사본, 그것도 안 되면 ModelSelectionException
getAllModels()등록된 설명 전부(복사본)
getDescriptor(modelId)모델을 만들지 않고 설명만
getModelsByProvider(provider)그 공급자의 AVAILABLE 모델(대소문자 무시)
registerModel(descriptor)등록하거나 합칩니다. 이미 있는 층 · 공급자 값은 그대로 두고, 상태는 새 값으로 바꿉니다
refreshModels()설명 · 캐시 · 별칭을 지우고 다시 등록
updateModelStatus(modelId, status)상태 바꾸기
shutdown()종료할 때(@PreDestroy) 모두 지움
ModelSelectionStrategy — 모델 고르기 계약
메서드하는 일
selectModel(ExecutionContext)이 호출의 ChatModel. 없으면 null
getSupportedModels()등록된 모델 ID 집합
isModelAvailable(modelName)그 모델을 지금 만들 수 있는지

기본 구현 DynamicModelSelectionStrategy는 레지스트리 · TieredLLMProperties · 기본 채팅 모델 세 가지를 받고, getModelCapabilities(modelName)로 등록된 모델의 정보(modelId · provider · capabilities · contextWindow · maxTokens · streaming · tier · status)를 돌려줍니다. 등록되지 않은 모델이면 빈 맵입니다.
