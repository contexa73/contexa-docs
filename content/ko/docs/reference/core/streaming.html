스트리밍: AI 답을 화면에 실시간으로

AI 모델이 쓰는 글을 SSE(Server-Sent Events)로 브라우저에 문장 단위로 보내고, 마지막에 구조화된 JSON 결과를 보내는 방법을 설명합니다. 서버 코드, 실제로 오는 이벤트, 클라이언트 코드, 시간 제한, 문제 해결을 다룹니다.

보안 판정과는 관계가 없습니다. 스트리밍은 앱 기능이 부르는 범용 AI 엔진의 응답 방식입니다. 보안 판정(1차 · 2차 분석)은 스트리밍하지 않으며 판정 엔진이 따로 만듭니다.

무엇을 얻나

모델이 분석하는 동안 문장이 하나씩 화면에 나타나고, 분석이 끝나면 결과 JSON이 한 번에 옵니다. 서버는 StandardStreamingService가 돌려주는 Flux<ServerSentEvent<String>>를 컨트롤러에서 그대로 돌려주기만 하면 됩니다.

두 가지 길과 켜는 조건

길부르는 메서드필요한 것잠금 · 감사 로그
Strategy 경로streamingService.stream(request, aiProcessor)Strategy와 Lab 둘 다 supportsStreaming()이 true, Lab의 doProcessStream()이 스트리밍 구성으로 파이프라인을 부름, 스트리밍 템플릿있음(같은 요청의 동시 스트림 거절, 시작 로그 한 줄)
직접 파이프라인streamingService.stream(request, pipelineOrchestrator)스트리밍 템플릿(요청의 템플릿 타입 이름과 같은 빈). Strategy · Lab은 필요 없음없음
  • 두 길 모두 StandardStreamingService 빈(contexa.streaming.enabled, 기본 켜짐)과 Spring AI 채팅 모델이 있어야 합니다.
  • 두 길은 같은 스트리밍 파이프라인(검색 → 전처리 → 프롬프트 → 모델 호출)과 같은 이벤트 형식을 씁니다.
  • Lab의 processStream()이나 PipelineOrchestrator.executeStream()을 직접 부르면 SSE로 묶이지 않은 조각 흐름(Flux<String>)을 받습니다. 문장 묶기 · [DONE] · 5분 제한은 StandardStreamingService가 하는 일입니다.

서버 코드

컨트롤러(Strategy 경로)

요청을 만들 때 스트리밍 템플릿의 이름을 템플릿 타입으로 씁니다. 전체 예(문맥 · 응답 타입 · 템플릿 · Lab · Strategy)는 커스텀 AI 기능 만들기에 있습니다.

@PostMapping(value = "/api/recommend/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public Flux<ServerSentEvent<String>> recommendStream(@RequestBody RecommendInput body) {
    AIRequest<ProductContext> request = new AIRequest<>(
            new ProductContext(body.productId(), body.category(), body.preferences()),
            new TemplateType("PRODUCT_RECOMMENDATION_STREAMING"),
            new DiagnosisType("PRODUCT_RECOMMENDATION"));
    return streamingService.stream(request, aiProcessor);   // aiProcessor: AICoreOperations<ProductContext>
}

직접 파이프라인

Strategy · Lab 없이 템플릿 하나로 끝나는 기능입니다. 기본 스트리밍 구성(4단계)으로 돕니다. 진단 타입은 쓰이지 않지만 AIRequest가 null을 받지 않으므로 아무 이름이나 넣습니다.

@PostMapping(value = "/api/chat/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public Flux<ServerSentEvent<String>> chatStream(@RequestBody ChatInput body) {
    AIRequest<ChatContext> request = new AIRequest<>(
            new ChatContext(body.message()),
            new TemplateType("CHAT_STREAMING"),   // 이 이름의 스트리밍 템플릿 빈이 있어야 합니다
            new DiagnosisType("CHAT"));           // 쓰이지 않지만 null이면 안 됩니다
    request.withParameter("naturalLanguageQuery", body.message());
    return streamingService.stream(request, pipelineOrchestrator);
}

Lab의 스트리밍

Strategy 경로에서는 Lab이 스트리밍을 켜고 스트리밍 구성으로 파이프라인을 불러야 합니다. supportsStreaming()을 재정의하지 않으면 processStream()이 바로 오류를 냅니다.

@Override
public boolean supportsStreaming() {
    return true;
}

@Override
protected Flux<String> doProcessStream(AIRequest<ProductContext> request) {
    return orchestrator.executeStream(request, PipelineConfiguration.createStreamPipelineConfig());
}

Strategy에서도 supportsStreaming()을 true로, processLabExecutionStream()이 Lab의 processStream()을 부르도록 재정의합니다(Strategy 만들기).

입력 오류를 바로 알리기

파이프라인을 부르기 전에 입력이 틀렸으면 오류 이벤트 하나로 된 스트림을 돌려줄 수 있습니다.

if (body.category() == null) {
    return streamingService.errorStream("VALIDATION_ERROR", "category is required");
}

브라우저는 ERROR: {"error":{"code":"VALIDATION_ERROR","message":"category is required"}} 이벤트 하나를 받고, 뒤에 [DONE]은 오지 않습니다.

실제로 오는 이벤트

상품 추천 예의 스트림을 그대로 받으면 이렇게 옵니다(이벤트 사이에 빈 줄).

data:사용자는 가볍고 배터리가 오래가는 노트북을 찾고 있습니다.

data:무게와 배터리 시간을 기준으로 노트북 후보를 비교했습니다.

data:###GENERATING_RESULT###

data:###FINAL_RESPONSE###{ "recommendations": [ { "productName": "…", "reason": "…", "score": 0.92 } ], "confidence": 0.88, "reasoning": "…" }

data:[DONE]
데이터뜻클라이언트가 할 일
표지 없는 글모델의 분석 서술. 문장 단위로 묶여 옵니다화면에 이어 붙입니다
###GENERATING_RESULT###서술이 끝나고 모델이 결과 JSON을 쓰기 시작함"결과 만드는 중" 표시
###FINAL_RESPONSE### + JSON최종 결과. 모델 스트림이 끝난 뒤 한 번에 옵니다표지를 떼고 JSON으로 읽습니다
[DONE]정상 끝화면을 마무리합니다
ERROR:로 시작오류(형식은 문제 해결)오류를 보여 주고 멈춥니다
  • 데이터 안의 줄바꿈은 공백으로 바뀝니다. 그래서 이벤트 하나는 늘 data: 한 줄입니다. 최종 JSON의 줄바꿈도 공백이 되지만 JSON으로 읽는 데 문제는 없습니다.
  • 서술은 한국어입니다. 스트리밍 템플릿이 모델에게 서술을 한국어로만 쓰라고 시킵니다(스트리밍 템플릿).
  • 모델이 ===JSON_END=== 없이 끝나면 모인 JSON의 괄호를 맞춰 고친 뒤 최종 결과로 보냅니다.
  • 최종 결과 표지가 나온 뒤의 글은 보내지 않습니다. 버퍼에 남은 서술도 함께 버려집니다.

표지(marker) 다섯 개

표지는 StreamingProtocol의 상수입니다. 셋은 서버 안에서만 쓰이고 브라우저에는 가지 않습니다.

상수값쓰이는 곳브라우저에
JSON_START_MARKER===JSON_START===모델이 결과 JSON 앞에 씁니다(템플릿이 시킴)가지 않음
JSON_END_MARKER===JSON_END===모델이 결과 JSON 뒤에 씁니다가지 않음
STREAMING_MARKER###STREAMING###서버 안에서 서술 조각에 붙였다가 보내기 전에 떼어 냅니다가지 않음
GENERATING_RESULT_MARKER###GENERATING_RESULT###모델 글에서 ===JSON_START===를 찾으면 냅니다감
FINAL_RESPONSE_MARKER###FINAL_RESPONSE###최종 JSON 앞에 붙습니다감

클라이언트 코드

POST로 스트림을 받으려면 브라우저의 fetch로 응답 본문을 읽습니다. 표지 없는 데이터가 본문 문장이라는 점이 핵심입니다. 판별 순서는 [DONE] → ERROR: → 최종 결과 → 결과 생성 알림 → 문장입니다.

스트림 읽기

const FINAL = '###FINAL_RESPONSE###';
const GENERATING = '###GENERATING_RESULT###';

async function streamRequest(url, body, callbacks) {
  const response = await fetch(url, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', 'Accept': 'text/event-stream' },
    body: JSON.stringify(body)
  });
  if (!response.ok) {
    callbacks.onError?.('HTTP ' + response.status);
    return;
  }
  const reader = response.body.getReader();
  const decoder = new TextDecoder();
  let buffer = '';
  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });
    const lines = buffer.split('\n');
    buffer = lines.pop();                      // 마지막 줄은 아직 덜 왔을 수 있습니다
    for (const line of lines) {
      if (!line.startsWith('data:')) continue;
      const data = line.substring(5).trim();
      if (data && handleEvent(data, callbacks)) return;   // [DONE]이나 오류면 끝
    }
  }
  callbacks.onComplete?.();
}

// 스트림이 끝났으면 true를 돌려줍니다
function handleEvent(data, callbacks) {
  if (data === '[DONE]') {
    callbacks.onComplete?.();
    return true;
  }
  if (data.startsWith('ERROR:')) {
    callbacks.onError?.(data.substring(6).trim());
    return true;
  }
  if (data.startsWith(FINAL)) {
    callbacks.onFinalResponse?.(data.substring(FINAL.length));
    return false;
  }
  if (data === GENERATING) {
    callbacks.onGenerating?.();
    return false;
  }
  callbacks.onChunk?.(data);                   // 표지 없는 데이터 = 본문 문장
  return false;
}

화면에 붙이기

const output = document.getElementById('output');
let text = '';

streamRequest('/api/recommend/stream',
  { productId: 'P-100', category: 'laptop', preferences: ['light', 'long battery'] },
  {
    onChunk: (sentence) => { text += sentence + ' '; output.textContent = text; },
    onGenerating: () => { output.textContent = text + '\n결과를 만드는 중…'; },
    onFinalResponse: (json) => {
      try { renderResult(JSON.parse(json)); }    // renderResult는 화면 코드(예시)
      catch (e) { output.textContent = text; }   // JSON이 깨졌으면 서술만 남깁니다
    },
    onComplete: () => setBusy(false),           // setBusy는 화면 코드(예시)
    onError: (message) => { output.textContent = '오류: ' + message; setBusy(false); }
  });
OSS 코어는 브라우저용 스트리밍 클라이언트를 주지 않습니다. 위 코드처럼 앱 화면에서 직접 읽습니다. Contexa IAM 관리 화면에는 자기 화면용 클라이언트(contexa-llm.bundle.js)가 들어 있지만 공개 API가 아닙니다. 이 클라이언트도 표지 없는 데이터를 본문으로 처리합니다.

안쪽 흐름

모델 호출에는 등록된 어드바이저(BaseAdvisor 빈)가 붙습니다. 스트리밍에서는 어드바이저가 모델 호출 전에 차단 오류를 내도 막지 못하고 그 어드바이저만 건너뜁니다(어드바이저 오류 처리).

문장 묶기(SentenceBuffer)의 규칙입니다.

  • 줄 끝이 마침표 · 느낌표 · 물음표나 한국어 어미(습니다. · 입니다. · 다. · 요. 등)면 한 문장으로 보냅니다.
  • 문장 끝을 못 찾은 채 200자를 넘으면 그때까지를 보냅니다. 스트림 끝에 남은 글도 보냅니다.
  • JSON처럼 보이는 조각(```json, ===JSON이 들어 있거나 {"로 시작)은 보내지 않습니다.
  • # 기호(마크다운 제목)와 제어 문자는 지우고, 3자보다 짧거나 문장부호만 있는 조각은 버립니다.

시간 제한

  • 이벤트 사이 5분: StandardStreamingService는 브라우저로 나가는 이벤트가 앞 이벤트(첫 이벤트는 시작) 뒤 5분 안에 오지 않으면 스트림을 끝내고 ERROR: {"error":{"code":"TIMEOUT","message":"Request timed out"}}를 보냅니다. 서술이 끝난 뒤 결과 JSON을 다 쓰는 데 5분이 넘어도 걸립니다.
  • 설정으로 바꿀 수 없습니다. 이 5분은 코드에 정해진 상수입니다(contexa.streaming.timeout은 읽히지 않음).
  • 모델 스트림 자체에는 제한과 재시도가 없습니다. 표준 호출의 호출 한 번 60초 제한과 최대 4번 재시도(재시도)는 스트리밍에 쓰이지 않습니다. 직접 executeStream()을 부르면 5분 제한도 없습니다.

확인과 문제 해결

버퍼링 없이 이벤트를 보려면 curl -N을 씁니다(주소는 앱에 맞게).

curl -N -X POST http://localhost:8080/api/recommend/stream \
  -H "Content-Type: application/json" \
  -d '{"productId":"P-100","category":"laptop","preferences":["light","long battery"]}'
보이는 것원인할 일
ERROR: {"error":{"code":"AI_OPERATION_ERROR","message":"Streaming strategic operation failed: …"}}, [DONE] 없음Strategy 경로에서 파이프라인 밖의 오류: Strategy를 못 찾음, Strategy · Lab의 supportsStreaming()이 false, 입력 검사 실패 등서버 로그에서 원인을 봅니다
ERROR: {"error":{"code":"AI_OPERATION_ERROR","message":"Strategic streaming operation conflict: …"}}똑같은 요청이 이미 스트리밍 중(Strategy 경로의 잠금)문맥에 사용자 · 세션을 채우거나, 앞 스트림이 끝난 뒤 다시 보냅니다
ERROR: Template matching failed 뒤에 [DONE]파이프라인 안의 오류는 ERROR: 원인 글로 오고 [DONE]이 뒤따릅니다. 이 예는 템플릿 타입 이름과 같은 스트리밍 템플릿 빈이 없다는 뜻템플릿의 getSupportedType() 이름을 맞춥니다
ERROR: {"error":{"code":"TIMEOUT","message":"Request timed out"}}이벤트 사이가 5분을 넘음모델 속도 · 결과 JSON 크기를 줄입니다
문장만 오고 최종 결과가 없음모델이 JSON 표지를 쓰지 않음스트리밍 템플릿의 JSON 예와 모델을 확인합니다
요청에 넣은 모델 · 온도가 적용되지 않음스트리밍은 요청 파라미터를 쓰지 않고 기본 채팅 모델을 씁니다모델을 골라야 하면 표준 호출을 씁니다

오류 코드는 원인 예외로 정해집니다: AI_OPERATION_ERROR(AI 처리 오류), TIMEOUT(시간 초과), INVALID_REQUEST(잘못된 인자), 그 밖은 INTERNAL_ERROR(메시지 "An unexpected error occurred"). 브라우저가 연결을 끊으면 서버의 파이프라인 구독도 취소됩니다.

직접 바꾸기

  • 스트리밍 서비스 바꾸기: StandardStreamingService 빈을 직접 두면 기본 구현 대신 쓰입니다.
  • 자기 SSE 만들기: 주입받은 StreamingProperties로 StreamingContext를 만들고, 조각을 appendChunk()로 모으며, isFinalResponseStarted() · getSentenceBuffer() · extractJsonPart()를 써서 기본 서비스와 같은 처리를 직접 할 수 있습니다.
