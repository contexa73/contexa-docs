개념: 어떻게 동작하나

Contexa는 어떻게 동작하나

요청마다 무엇을 묻고 판정을 언제 만들어 언제 적용하는지, 소유 방식에 따라 동작하는 것, 모듈 구성을 한 화면에 봅니다.

요청 하나의 일생

요청이 저장된 판정을 적용받고, 실행 · 분석되어, 그 판정이 다음 요청에 적용되기까지를 차례로 따라갑니다.

판정 엔진

어떤 요청이 분석되는지, 1차 · 2차 분석, 모델의 답이 바뀌는 경우, 판정의 저장과 학습을 설명합니다.

요청 시점 집행(Zero Trust 필터)

저장된 판정을 요청이 들어올 때 적용하는 필터와 판정별 응답입니다. 두 소유 방식 모두에 해당합니다.

판정 프롬프트와 묶음

AI 모델에 보내는 판정 프롬프트의 재료, 빌드에 든 프롬프트 묶음 세 개, 모델 답의 형식과 검사를 다룹니다.

프롬프트 거버넌스와 검수

프롬프트 묶음의 버전 · 릴리스 게이트 · 롤백과, 봉인된 프롬프트를 사실과 대조하는 검수를 설명합니다.

봉인 증거와 공식 검증

판정 때 보낸 그대로의 프롬프트와 사실을 봉인하고, 바뀌지 않았는지 확인하고, 검증 · 재생하는 방법입니다.

에이전트 보안

에이전트를 보안 주체로

에이전트의 요청을 사람의 요청과 구분하는 방법, 등록, 판정이 저장되는 곳, 요청 흐름, 도구 호출(MCP) 보호를 설명합니다.

위임과 업무 목표 계약

사람이 맡긴 일의 범위를 알려 주고, 실제 요청과 비교한 사실을 판정에 건네는 방법입니다. 판정은 모델이 합니다.

정지 · 확인 · 제한

에이전트 정지, 책임자 확인, 호출 상한, 범위 축소와 에이전트가 받는 응답입니다.

인증 연동

기존 로그인과 연결하기

앱의 로그인 · 권한 · 위임 정보를 요청마다 읽어 판정 사실로 쓰는 인증 브리지, MFA 알리기, 게이트웨이 헤더(기본 꺼짐), 직접 넘기기입니다.

인가

인가 개요

접근 규칙을 DB의 정책으로 두고 URL 요청과 @Protectable 호출에 적용하는 구조, 두 적용 지점이 켜지는 조건입니다.

URL 접근 정책

URL 요청의 허용 · 거부를 DB에 저장한 정책으로 정하고, 바꾼 정책을 반영하는 방법입니다.

@Protectable: 메서드 보호

붙이는 법, 정책 연결, 호출 하나의 처리 순서, 즉시 판정(sync), 소유자 확인, 속성 9개입니다.

AI 보안 표현식

정책 조건에서 저장된 판정(#ai)과 에이전트 · 위임 사실을 읽는 식입니다. 쓸 수 있는 곳은 소유 방식에 따라 다릅니다.

권한 평가기

hasPermission(...)이 무엇을 보고 참 · 거짓을 내는지, 도메인 평가기를 더하는 방법입니다.

정책 관리

정책 센터에서 URL · 메서드 정책을 만들고, AI가 쓴 초안을 승인하고, 반영을 확인합니다.

리소스 스캐너

앱의 컨트롤러 URL과 @Protectable 메서드를 찾아 보호 대상 목록으로 모읍니다.

관리 콘솔

보안 모니터링, 정책 센터, 접근 센터, 차단 사용자 등 운영 화면입니다.

동적 인가 전체 흐름

자원 찾기부터 정책 작성, 런타임 집행까지를 한 흐름으로 따라갑니다.

AI 엔진

커스텀 AI 기능 만들기

입력 · 출력 타입, 프롬프트 템플릿, Lab, Strategy, 컨트롤러를 차례로 만드는 따라 하기입니다.

파이프라인과 RAG

파이프라인이 요청을 처리하는 단계, RAG 검색 붙이기, 단계 바꾸기와 실패 다루기입니다.

스트리밍

AI 응답을 Server-Sent Events로 실시간 보내는 방법과 클라이언트 처리입니다.

LLM 호출하기

모든 모델 호출이 지나는 오케스트레이터, 앱 코드에서 직접 부르기, 제한 시간 · 재시도입니다.

모델 연결과 선택

모델 공급자를 연결하고 기본 모델과 층(1차 · 2차)별 모델, 임베딩 모델을 정합니다.

어드바이저

모델 호출 앞뒤에서 실행되는 부품, 기본 보안 문맥 어드바이저, 내 어드바이저 등록입니다.

RAG: 문서 저장과 검색

벡터 저장소에 문서를 저장하고 비슷한 문서를 찾아 모델에 함께 보내는 방법입니다.
