공통 계약: 앱 코드에 쓰는 Contexa 타입

앱 코드에 직접 쓰는 Contexa의 어노테이션 · 판정 값 · 모드 열거형 · 확장 인터페이스를 모았습니다. 하려는 일에 맞는 타입을 찾고, 언제 쓰는지와 OSS에서 실제로 무엇이 일어나는지 확인할 수 있습니다.

한눈에 보기

아래 타입은 모두 contexa-common 모듈에 있습니다(집행 모드 열거형만 contexa-core). 스타터(spring-boot-starter-contexa) 하나를 넣으면 함께 들어옵니다.

하려는 일쓰는 타입자세한 페이지
Contexa 켜기@EnableAISecurity아래, Contexa 켜기와 보안 모드 고르기
분석 · 집행할 메서드 정하기@Protectable아래, @Protectable
판정 결과 읽기ZeroTrustAction아래, 요청 시점 집행
로그인을 누가 맡을지, 판정을 집행할지 고르기SecurityMode(둘), SecurityOwnershipMode아래
앱의 로그인 정보를 Contexa에 알리기AuthBridge, ContexaAuthBridge기존 로그인과 연결하기
기동 진단에 내 검사 더하기 · 캐시 바꾸기CapabilityContributor, ContexaCacheService아래
자동 대응(SOAR) · 도구 승인 계약 보기@SoarTool, SecurityActionEventSOAR 확장점

Contexa 켜기: @EnableAISecurity

메인 클래스에 붙이는 스위치입니다(패키지 io.contexa.contexacommon.annotation). 이 어노테이션은 선택기 AiSecurityImportSelector를 가져오고(@Import), 선택기가 Contexa 구성을 불러옵니다. 속성 없이 쓰면 보안 모드는 SANDBOX(앱이 로그인을 맡음)입니다.

@EnableAISecurity
@SpringBootApplication
public class Application {
    public static void main(String[] args) {
        SpringApplication.run(Application.class, args);
    }
}
  • 켜졌다는 표지입니다. 이 어노테이션이 설정 키들을 담은 속성 소스 contexaAiSecurityAnnotation을 넣고, Contexa는 그 속성 소스가 있을 때만 켜진 것으로 봅니다(앱 설정에 같은 키를 적어도 켜지지 않음). 어노테이션이 없으면 스타터를 넣었어도 Contexa 자동설정이 모두 빠집니다.
  • 전용 DB가 필요합니다. contexa.datasource.url이 비어 있으면 기동이 멈춥니다.
  • 속성(mode · authObjectLocation · authObjectAttribute · authObjectType)과 켜면 일어나는 일은 Contexa 켜기와 보안 모드 고르기에 있습니다.

분석 · 집행할 메서드 정하기: @Protectable

이 어노테이션이 붙은 메서드를 부르면 Contexa가 호출을 가로채(AuthorizationManagerMethodInterceptor) 메서드 인가 정책을 평가하고(ProtectableMethodAuthorizationManager), 판정 엔진이 그 호출을 분석합니다. 판정의 대상이 되는 단위가 이 보호 메서드입니다.

  • 붙이는 곳: Spring 빈의 메서드 또는 클래스. 클래스에 붙이면 그 클래스의 메서드 모두가 대상입니다. 컨트롤러가 아니어도 됩니다.
  • 로그인이 필요합니다(SHADOW · ENFORCE, 기본은 ENFORCE): 호출 시점에 SecurityContext에 인증된 Authentication이 없거나 익명이면 호출이 거부됩니다. DISABLED · OBSERVE에서는 거부하지 않고 앱이 만든 그대로 진행합니다.
  • 분석은 집행 모드가 SHADOW · ENFORCE일 때만: DISABLED · OBSERVE에서는 인가 정책만 평가하고 분석 · 사건 발행을 하지 않습니다.

판정 기록이 없는 에이전트 요청은 기본 메서드에서도 그 자리에서 판정합니다(에이전트 보안). 판정이 만들어지는 과정은 판정 엔진에 있습니다.

import io.contexa.contexacommon.annotation.Protectable;
import io.contexa.contexacommon.annotation.ResourceImportance;
import org.springframework.stereotype.Service;

@Service
public class ReportService {

    @Protectable(category = "REPORT", actions = {"EXPORT"},
                 importance = ResourceImportance.SENSITIVE, sync = true)
    public String exportMonthlyReport(String month) {
        return "report-" + month;
    }
}

판정 값: ZeroTrustAction

판정 엔진이 만들어 저장하는 값입니다. 값마다 HTTP 상태 · 유지 시간 · 붙는 권한이 코드에 정해져 있습니다.

값쉬운 말HTTP 상태 값유지 시간붙는 권한
ALLOW허용20015분없음
CHALLENGE추가 인증4011,800초(30분)ROLE_MFA_REQUIRED
ESCALATE검토 보류(분석 미완료)423300초(5분)ROLE_REVIEW_REQUIRED
BLOCK차단403기한 없음(해제할 때까지)ROLE_BLOCKED
PENDING_ANALYSIS분석 대기(저장된 판정 없음)5030ROLE_PENDING_ANALYSIS

문자열에서 값을 읽을 때(ZeroTrustAction.fromString)는 대소문자를 가리지 않고 한 글자 약자(A · B · C · E)도 받습니다. 값이 없으면 분석 대기, 알 수 없는 문자열은 검토 보류로 읽습니다. 저장된 판정이 다음 요청에서 어떻게 적용되는지는 요청 시점 집행, 어디에 저장되는지는 판정 엔진에 있습니다.

이름이 비슷한 모드 셋

SecurityMode라는 이름의 열거형이 두 패키지에 따로 있습니다. import할 때 패키지를 확인하십시오.

쉬운 말타입(패키지)값정하는 곳
보안 모드SecurityMode
(io.contexa.contexacommon.security.bridge)		SANDBOX(기본) · FULL@EnableAISecurity(mode = ...)
인증 소유권SecurityOwnershipMode
(io.contexa.contexacommon.security.bridge)		HOST_OWNED · CONTEXA_OWNEDcontexa.bridge.ownership(적지 않으면 SANDBOX → HOST_OWNED, FULL → CONTEXA_OWNED)
집행 모드SecurityZeroTrustProperties.SecurityMode
(io.contexa.contexacore.properties)		DISABLED · OBSERVE · SHADOW · ENFORCE(기본)contexa.security.zerotrust.mode 또는 관리 화면 시스템 설정

HOST_OWNED에서는 Contexa가 인증 체인을 만들지 않으므로 앱이 자기 Spring Security 설정을 선언해야 기존 동작이 유지됩니다. 선언이 없으면 Spring Boot 기본 보안(모든 요청에 인증 필요)이 걸립니다. 세 모드가 각각 무엇을 바꾸는지와 고르는 방법은 Contexa 켜기와 보안 모드 고르기에 있습니다. 인증 객체 위치 힌트 AuthObjectLocation(AUTO · SESSION · REQUEST_ATTRIBUTE · HEADER)도 같은 io.contexa.contexacommon.security.bridge 패키지에 있습니다.

확장 인터페이스

아래 인터페이스의 빈을 앱이 선언하면 Contexa의 기본 구현이 물러나거나, 기본 구현에 더해집니다.

인터페이스언제 구현하나빈을 두면
AuthBridge앱만의 방법으로 요청에서 로그인 사용자를 꺼낼 때기본 복합 브리지(세션 · 요청 속성 · 헤더)를 대신합니다(인증 브리지 확장점).
ContexaAuthBridge(정적 메서드 handoff)로그인 코드에서 사용자를 Contexa에 직접 알릴 때구현하지 않고 부릅니다. Contexa가 켜져 있지 않으면 IllegalStateException(직접 넘기기).
CapabilityContributor기동 기능 진단에 앱의 검사를 더할 때기본 검사기와 함께 모든 기여자의 결과가 모입니다(기동 진단).
ContexaCacheServiceContexa 내부 캐시 구현을 바꿀 때기본 구현(단독 모드는 메모리, 분산 모드는 Redis)이 물러납니다.

판정 저장소 · 사건 발행 · 데이터 빈처럼 자동설정이 만드는 빈을 바꾸는 방법은 자동설정: 빈 바꿔 끼우기에 있습니다.

모듈 경계

  • @EnableAISecurity가 가져오는 기본 구성(io.contexa.autoconfigure.ai.AiSecurityConfiguration)은 클래스 이름 문자열로 지정되어 있어, contexa-common은 구현 모듈을 컴파일 시점에 알지 못합니다.
  • contexa-common에는 SOAR 계약(@SoarTool, SecurityActionEvent, 도구 정책 인터페이스)과 MCP 도구 호출 계약도 있습니다. OSS에는 이 계약을 실행하는 구현이 없습니다. SOAR는 SOAR 확장점, MCP는 에이전트 보안을 보십시오.
