ASEP 보안 예외 처리

ASEP는 보안 필터 체인 안에서 생긴 예외를 앱이 만든 처리기 메서드(@SecurityExceptionHandler)로 처리하게 하려는 Contexa 기능의 이름입니다. 현재 버전에서는 동작하지 않습니다. 이 페이지는 무엇이 동작하지 않는지와, 코드에 들어 있는 어노테이션 · 설정을 참고로 정리합니다.

현재 버전에서 ASEP는 동작하지 않습니다. ASEP 구성자(AsepConfigurer)는 흐름마다 ASEP 필터(ASEPFilter)를 만들기만 하고 보안 체인에 넣지 않습니다. 그래서 @SecurityControllerAdvice 클래스의 @SecurityExceptionHandler 메서드는 불리지 않고, 처리기 파라미터 어노테이션과 흐름 옵션 asep(...)도 효과가 없습니다. 보안 예외는 Contexa와 Spring Security의 기본 응답으로 처리됩니다.
ASEP는 Contexa가 로그인을 맡을 때(CONTEXA_OWNED) 만드는 체인을 대상으로 한 기능입니다. 기본값 HOST_OWNED에서는 앱의 체인과 예외 처리가 그대로 쓰입니다. 앱의 기존 로그인을 쓰는 방법은 기존 로그인과 연결하기에 있습니다.

지금 동작하지 않는 것

  • @SecurityControllerAdvice · @SecurityExceptionHandler로 만든 처리기
  • 처리기 파라미터 어노테이션(@SecurityPrincipal, @AuthenticationObject 등)과 반환 처리(@SecurityResponseBody 등)
  • 모든 인증 방법과 .mfa()의 흐름 옵션 asep(...)
  • 처리기가 없을 때 쓰려던 ASEP 기본 오류 응답

ASEP 자동 구성 자체는 서블릿 웹 앱에서 PlatformConfig 빈이 있으면 켜지고(IdentityAsepAutoConfiguration), 처리기 레지스트리 · 기본 리졸버 · 반환 처리기 빈을 만듭니다. 이 빈들은 있지만 필터가 없어 쓰이지 않습니다.

코드에 들어 있는 설계(참고)

아래는 코드에 정의된 내용입니다. 현재 버전에서는 호출되지 않으며, ASEP 필터가 체인에 들어갈 때 이렇게 동작하도록 만들어져 있습니다.

  • 필터 다음 단계에서 예외가 나면, 응답이 이미 나가기 시작했으면 처리하지 않고 예외를 다시 던집니다.
  • 아니면 등록된 처리기 가운데 예외 타입이 가장 가까운 메서드를 고르고, 같으면 priority가 작은 것을 고릅니다.
  • 맞는 처리기가 없으면 기본 오류 응답을 씁니다: 인증 예외 401 UNAUTHENTICATED, 접근 거부 403 ACCESS_DENIED, 그 밖 500 INTERNAL_SERVER_ERROR. 본문은 timestamp, status, error, message, path입니다.

어드바이스와 처리기

어노테이션 · 속성붙는 곳뜻
@SecurityControllerAdvice클래스처리기를 모은 클래스 표시. 어노테이션이 빈을 만들지는 않으므로 @Component 등으로 빈이 되어 있어야 레지스트리가 찾습니다
value · basePackages · basePackageClasses · assignableTypes위 어노테이션의 속성선언만 있고 읽는 코드가 없습니다
@SecurityExceptionHandler메서드예외 처리기 표시
value위 어노테이션의 속성처리할 예외 타입. 비면 메서드 파라미터의 예외 타입, 그것도 없으면 Throwable
priority위 어노테이션의 속성기본 Ordered.LOWEST_PRECEDENCE. 작을수록 먼저
produces위 어노테이션의 속성응답 미디어 타입

처리기 파라미터

파라미터받는 것속성(기본값)
@CaughtException잡힌 예외 객체없음
@SecurityPrincipal현재 Authentication의 principal(파라미터 타입과 맞을 때)없음

@SecurityCookieValue쿠키 값value · name(""), required(true), defaultValue(없음)

@SecuritySessionAttribute세션 속성value · name(""), required(true)
@SecurityRequestBody요청 본문(메시지 변환기로 읽음)required(true)
HttpServletRequest · HttpServletResponse요청 · 응답어노테이션 없이 타입으로

흐름 옵션 asep(...)

흐름마다 파라미터 리졸버와 반환 처리기를 더하는 설정입니다. 같은 클래스의 기본 리졸버 · 처리기는 더한 것으로 바뀝니다. 메서드는 exceptionArgumentResolver(...), exceptionArgumentResolvers(List), exceptionReturnValueHandler(...), exceptionReturnValueHandlers(List)입니다. 속성 클래스는 방법마다 FormAsepAttributes, RestAsepAttributes, OttAsepAttributes, PasskeyAsepAttributes, MfaAsepAttributes이고, MfaOttAsepAttributes · MfaPasskeyAsepAttributes는 쓰는 곳이 없습니다.

정의 예(현재 호출되지 않음)

// 현재 버전에서는 이 처리기가 호출되지 않습니다(ASEP 필터가 체인에 없음).
@Component
@SecurityControllerAdvice
public class SecurityErrorAdvice {

    @SecurityExceptionHandler(value = AccessDeniedException.class, priority = 10)
    @SecurityResponseBody
    public Map<String, Object> handleAccessDenied(@CaughtException AccessDeniedException ex,
                                                  @SecurityPrincipal Object principal,
                                                  @SecurityRequestHeader(value = "X-Request-Id", required = false) String requestId) {
        return Map.of("error", "ACCESS_DENIED", "requestId", String.valueOf(requestId));
    }
}
