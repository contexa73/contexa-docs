@SoarTool과 도구 승인 등급

@SoarTool은 AI가 부르는 대응 도구에 이름 · 승인 요구 · 실행 제한 같은 정보를 붙이는 어노테이션입니다. 이 페이지는 각 속성의 뜻, 승인 등급이 정해지는 규칙, 어디에 붙여야 읽히는지, 나머지 속성을 직접 적용하는 방법을 설명합니다.

OSS에서 읽히는 속성은 approval 하나입니다. 그것도 Spring AI ToolCallback 구현 클래스에 클래스 수준으로 붙였을 때만 읽히고, 읽는 평가기(RiskAssessment)를 주입받는 OSS 코드가 없습니다. @SoarTool이 붙은 도구를 찾아 등록하거나 실행하는 코드도 OSS에 없습니다. 나머지 속성의 효과는 직접 구현하거나 엔터프라이즈 SOAR 모듈이 필요합니다(SOAR 확장점).

속성

패키지 io.contexa.contexacommon.annotation, 붙이는 곳은 클래스 · 메서드(@Target({TYPE, METHOD})), 실행 중에도 남는 어노테이션(RUNTIME)입니다.

속성타입기본값OSS가 읽나직접 구현할 때의 뜻
nameString""아니요도구 이름
descriptionString""아니요도구 설명(모델이 도구를 고를 때 볼 글)
approvalApprovalRequirementAUTO예(ToolCallback 구현 클래스 수준만)승인 요구 수준(아래)
requiredPermissionsString[]{}아니요실행에 필요한 권한
allowedEnvironmentsString[]{"dev", "staging", "prod"}아니요실행을 허용할 환경
maxExecutionsPerHourint100아니요시간당 최대 실행 횟수
auditRequiredbooleantrue아니요실행을 감사 기록에 남길지
retryablebooleantrue아니요실패 때 다시 시도할지
maxRetriesint3아니요최대 재시도 횟수
timeoutMslong30000아니요실행 시간 제한(ms)

승인 등급이 정해지는 규칙

ApprovalRequirement와 ApprovalType

어노테이션에는 승인 요구 수준(SoarTool.ApprovalRequirement, 5개)을 적고, 평가기는 이를 승인 유형(ApprovalRequest.ApprovalType, 6개)으로 바꿉니다. 승인이 필요하다고 보는(requiresApproval이 참인) 유형은 MANUAL · MULTI뿐입니다.

ApprovalRequirement바뀌는 ApprovalType승인 필요
NONEAUTO아니요
AUTO(기본)AUTO아니요
NOTIFICATIONSINGLE아니요
REQUIREDMANUAL예
MULTI_APPROVALMULTI예

이 표는 등급을 바꾸는 규칙일 뿐입니다. 알림을 보내거나, 기다렸다 진행하거나, 여러 승인자의 승인을 세는 코드는 OSS에 없습니다.

평가기 RiskAssessment

평가규칙
어노테이션ToolCallback 구현 클래스의 @SoarTool(approval)을 위 표대로 바꿈. 없으면 AUTO, 읽다가 오류가 나면 MANUAL(안전한 쪽으로)
도구 이름setToolApprovalType(이름, 유형)으로 지정한 값이 있으면 그 값. 없으면 이름(소문자)을 보고 차례로: system · kernel · root · admin · production · critical 중 하나와 위험 낱말이 함께 있으면 MULTI → 위험 낱말(delete · remove · kill · terminate · shutdown · destroy · format · wipe · purge · quarantine · isolate)이 있으면 MANUAL → scan · analysis · detect가 있으면 SINGLE → read · list · get · view가 있으면 AUTO → 그 밖은 SINGLE
문맥productionEnvironment가 true, target에 production · critical이 들어 있음, userId가 admin 가운데 하나면 MANUAL. 아니면(문맥이 없어도) AUTO
시각서버 현지 시각 22시 이후 또는 6시 이전이면 SINGLE, 그 밖은 AUTO

RiskAssessment는 빈으로 등록되고 같은 타입의 빈을 두면 바꿀 수 있지만(@ConditionalOnMissingBean), OSS에서 주입받아 쓰는 곳은 없습니다. 직접 만든 실행 흐름에서 주입받아 assess(...) 또는 assessWithDetails(...)(등급 · 승인 필요 여부 · 평가 근거)를 부릅니다.

어디에 붙여야 읽히나

평가기는 넘겨받은 도구 객체의 클래스에서 클래스 수준 @SoarTool만 읽습니다. 그래서 아래처럼 ToolCallback을 구현한 클래스에 붙여야 합니다. 메서드에 붙인 값, 앱의 서비스 빈 클래스에 붙인 값은 읽히지 않습니다(클래스 · 메서드 값을 합치는 코드도 없음).

import io.contexa.contexacommon.annotation.SoarTool;
import org.springframework.ai.tool.ToolCallback;
import org.springframework.ai.tool.definition.ToolDefinition;

@SoarTool(name = "session_termination",
          description = "Terminates every session of the given user",
          approval = SoarTool.ApprovalRequirement.REQUIRED)
public class SessionTerminationTool implements ToolCallback {

    private final ToolDefinition definition = ToolDefinition.builder()
            .name("session_termination")
            .description("Terminates every session of the given user")
            .inputSchema("{\"type\":\"object\",\"properties\":{\"userId\":{\"type\":\"string\"}}}")
            .build();

    @Override
    public ToolDefinition getToolDefinition() {
        return definition;
    }

    @Override
    public String call(String toolInput) {
        // 실제 세션 종료는 앱이 구현합니다.
        return "{\"terminated\":true}";
    }
}
ApprovalRequest.ApprovalType type = riskAssessment.assess(
        new SessionTerminationTool(), Map.of("target", "production-db"));
// 어노테이션 REQUIRED → MANUAL, 문맥 target에 production → MANUAL
// 결과 MANUAL, riskAssessment.requiresApproval(type) == true

걸러진 도구 기록ToolExecutionMetrics(recordFiltered) 인터페이스. 구현 · 호출 없음지표 구현

OSS에는 이 실행을 집행 모드(섀도 · 집행)로 제어하는 코드도 없습니다. 섀도로 지켜보는 동작이 필요하면 직접 만든 실행 흐름에서 집행 모드를 읽어 처리합니다.
