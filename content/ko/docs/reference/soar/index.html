SOAR 확장점: OSS에 있는 것과 직접 만들어야 하는 것

SOAR(보안 오케스트레이션 · 자동 대응)를 위해 OSS에 들어 있는 인터페이스 · 데이터 형식과 연결점을 정리합니다. 무엇이 이미 있고, 무엇을 직접 만들거나 엔터프라이즈 모듈로 채워야 하며, OSS가 어디서 이 연결점을 부르는지 알 수 있습니다.

OSS에는 SOAR 실행 · 승인 구현이 없습니다. OSS만으로는 도구 실행 같은 자동 대응도, 사람 승인으로 대응을 멈췄다 이어 가는 흐름도 일어나지 않습니다. 이 기능을 쓰려면 엔터프라이즈 SOAR 모듈이 필요합니다. Contexa 기동 진단도 이 기능을 엔터프라이즈 기능(ENTERPRISE_SOAR)으로 보고 "엔터프라이즈 모드를 켜고 엔터프라이즈 SOAR 모듈을 실행 클래스패스에 넣으라"고 안내합니다. OSS가 주는 것은 인터페이스 · 어노테이션 · 데이터 형식(과 비어 있는 DB 표)이며, 이를 직접 구현해 끼울 수도 있습니다.

무엇이 있고 무엇이 없나

엔터프라이즈 SOAR는 기동 진단에서 contexa.enterprise.enabled=true이고 엔터프라이즈 모듈이 SOAR 문맥 빈(soarContextRetriever)을 등록했을 때 켜진 것으로 봅니다. 엔터프라이즈 모듈의 동작은 이 문서의 범위 밖입니다.

연결점이 불리는 곳

OSS 코드에서 SOAR 연결점을 부르는 곳은 아래가 전부입니다. "지금 OSS에서" 칸은 OSS 모듈만 있을 때 실제로 일어나는 일입니다.

연결점OSS가 부르는 곳과 조건지금 OSS에서
2차 분석의 플레이북 기록contexa.security.tiered.layer2.enable-soar=true이고 2차 분석 판정이 차단(BLOCK)일 때판정의 플레이북 값(soarPlaybook)을 채우는 코드가 없어 바로 돌아갑니다. 값이 있어도 하는 일은 BLOCK_IP · INVESTIGATE_IOC · NOTIFY_SOC 설명 목록을 데이터 저장소에 남기는 것뿐이며, 실제 차단 · 알림은 없습니다.
ApprovalService 빈2차 분석 판정에 "승인 필요" 표시가 있고 빈이 있으면 SOAR_CRITICAL_RESPONSE 승인을 요청"승인 필요" 표시는 2차 분석의 기술 실패 대체 판정에만 붙는데, 그 판정은 이 호출 전에 돌아가므로 도달하지 않습니다. 요청하더라도 결과를 기다리지 않습니다(자세히).
이름이 pipelineSoarToolExecutionStep인 PipelineStep 빈범용 AI 파이프라인에서 요청 문맥이 SoarContext이면 LLM 실행 단계 대신 이 단계를 실행이 빈과 SoarLab 구현이 OSS에 없어 일어나지 않습니다.
SoarApprovalNotifier 빈분산 모드의 Redis 구성이 켜졌을 때 Redis 채널 soar:approval:requests 메시지를 이 빈에 전달이 채널에 메시지를 보내는 OSS 코드가 없습니다(자세히).
SecurityActionEvent 수신자차단된 사용자가 차단 해제 MFA에 실패하면 발행발행은 됩니다. 받는 쪽은 앱이 만듭니다(아래 예).
RiskAssessment 빈(도구 승인 등급 평가)빈으로 등록됨주입받는 곳이 없습니다(@SoarTool과 도구 승인 등급).

데이터 형식

요청과 문맥

타입담는 것알아 둘 점
SoarLab
(io.contexa.contexacore.soar)		인터페이스 하나: Mono<?> processAsync(SoarRequest request). 분석 · 도구 선택 · 승인 · 실행은 구현자가 정합니다.다른 인터페이스를 상속하지 않습니다(범용 AI Lab 인터페이스와 별개). OSS 구현 없음.
SoarRequestAIRequest<SoarContext>를 확장. incidentId · threatType · description · initialQuery · approvalId · metadatagetIncidentId()는 incidentId 필드가 아니라 metadata의 "incidentId"를 읽고, 없으면 soar-inc-<현재 밀리초>를 돌려줍니다. 만들 때 templateType · diagnosisType이 비면 예외가 납니다.
SoarContextDomainContext를 확장. 사건(incidentId · threatType · severity · description · affectedAssets · currentStatus · organizationId), 진행(sessionState · executionMode · threatLevel · riskScore · conversationHistory), 승인(approvalRequests · approvedTools · humanApprovalNeeded)값을 담는 객체이며 스스로 상태를 바꾸지 않습니다. riskScore는 Double(비어 있을 수 있음), executionMode 기본은 AUTO, emergencyMode는 읽는 코드가 없습니다.
SoarResponseAIResponse를 확장. 분석 결과 · 세션 상태 · 실행한 도구 · 권고 · 요약 · 사건 ID · 위협 수준—

SoarContext의 메서드는 값만 바꿉니다: transitionTo(상태)는 sessionState를 바꾸고(검사 없음), approveTool(이름)은 승인된 도구 집합에 이름을 넣고, addToolExecutionResult(이름, 결과)는 문맥의 추출 값 맵에 tool_result_<이름>으로 넣습니다(감사 기록이 아님). threatLevel 값은 CRITICAL · HIGH · MEDIUM · LOW · INFO · UNKNOWN입니다.

SoarContext context = new SoarContext();
context.setIncidentId("INC-2024-001");
context.setThreatLevel(SoarContext.ThreatLevel.HIGH);

SoarRequest request = SoarRequest.builder()
        .context(context)
        .templateType(new TemplateType("SOAR"))
        .diagnosisType(new DiagnosisType("SOAR"))
        .incidentId("INC-2024-001")
        .threatType("UNAUTHORIZED_ACCESS")
        .description("Unusual export from the finance report API")
        .metadata(new HashMap<>(Map.of("incidentId", "INC-2024-001")))   // getIncidentId()가 읽는 곳
        .build();

실행 모드와 세션 상태

열거형값알아 둘 점
SoarExecutionModeSYNC(코드 sync, 승인까지 기다리는 처리) · ASYNC(async, 저장해 두고 나중에 처리) · AUTO(auto, 문맥에 따라 고름)열거형의 설명일 뿐 이 동작을 하는 구현은 없습니다. 모드를 정하는 OSS 코드는 소비처가 없는 SoarContextProviderImpl뿐으로, 긴급 문맥은 SYNC, 그 밖은 ASYNC 또는 설정값을 넣습니다.
SessionStateNEW · INITIALIZED · ACTIVE · ANALYZING · INVESTIGATING · WAITING_APPROVAL · AWAITING_APPROVAL · CONFIRMED · APPROVED · EXECUTING · COMPLETED · FAILED · ERROR승인 대기 값이 둘(WAITING_APPROVAL · AWAITING_APPROVAL)이며 어느 쪽을 쓸지 정한 코드는 없습니다.

사건과 보안 조치 이벤트

타입값 · 내용
SoarIncident(도메인, io.contexa.contexacore.domain)IncidentStatus 10개: NEW · INVESTIGATING · IN_PROGRESS · CONTAINED · MITIGATED · ERADICATED · RECOVERED · RESOLVED · CLOSED · FALSE_POSITIVE
IncidentSeverity 5개: CRITICAL · HIGH · MEDIUM · LOW · INFO
IncidentType 10개: MALWARE · RANSOMWARE · PHISHING · DATA_BREACH · UNAUTHORIZED_ACCESS · DOS_ATTACK · INSIDER_THREAT · VULNERABILITY · COMPLIANCE_VIOLATION · OTHER
SoarIncident(JPA 엔티티, io.contexa.contexacore.domain.entity)이름은 같지만 다른 클래스입니다. 표 ctxa_soar_incidents, 상태 열거형 SoarIncidentStatus 11개(NEW · TRIAGE · INVESTIGATION · PLANNING · PENDING_APPROVAL · EXECUTION · REPORTING · COMPLETED · AUTO_CLOSED · FAILED · CLOSED_BY_ADMIN)
SecurityActionEvent(contexa-common)모듈 사이에 보내는 보안 조치 이벤트. ActionType: IP_BLOCK · IP_UNBLOCK · SESSION_TERMINATE · SESSION_TERMINATE_ALL · THREAT_INTEL_ALERT · SOAR_AUTO_RESPONSE

OSS 스키마는 SOAR 표 7개(ctxa_soar_incidents, ctxa_soar_approval_policies, ctxa_soar_approval_requests, ctxa_soar_approval_steps, ctxa_soar_approval_assignments, ctxa_soar_approval_votes, ctxa_approval_notifications)를 만들고 엔티티 · 저장소도 있지만, 이 표에 쓰거나 읽는 OSS 코드는 없습니다.

설정

설정기본값OSS에서의 효과언제 바꾸나
contexa.security.tiered.layer2.enable-soarfalse켜도 효과가 없습니다. 2차 분석이 플레이북 기록을 시도하지만 플레이북 값이 늘 비어 있습니다.OSS만 쓸 때는 바꿀 필요가 없습니다.
contexa.security.plane.agent.execution-modeASYNC소비처가 없는 SoarContextProviderImpl만 읽습니다.OSS만 쓸 때는 바꿀 필요가 없습니다.

이 밖에 이름에 soar가 들어간 설정(어드바이저 · 라우터 임계값 · Kafka 토픽 이름 · 캐시 도메인)은 읽는 코드가 없거나 그 값을 쓰는 호출이 없어, 바꿔도 OSS의 동작이 달라지지 않습니다.

직접 만들 때

  1. 대응 실행: SoarLab을 구현하고, 범용 AI 파이프라인으로 도구를 실행하려면 이름이 pipelineSoarToolExecutionStep인 PipelineStep 빈을 둡니다.
  2. 도구 승인 등급: 도구에 @SoarTool을 붙이고 RiskAssessment로 등급을 매깁니다(@SoarTool과 도구 승인 등급).
  3. 사람 승인: ApprovalService를 구현합니다(사람 승인 연결하기).
  4. 차단 사용자 자동 대응: OSS가 이미 발행하는 SecurityActionEvent를 받아 앱의 대응을 실행합니다.
import io.contexa.contexacommon.soar.event.SecurityActionEvent;
import org.springframework.context.event.EventListener;
import org.springframework.stereotype.Component;

@Component
public class SecurityActionListener {

    @EventListener
    public void onSecurityAction(SecurityActionEvent event) {
        if (event.getActionType() == SecurityActionEvent.ActionType.SOAR_AUTO_RESPONSE) {
            // 앱의 대응(세션 종료, 담당자 알림 등)을 여기서 실행합니다.
            // event.getUserId(), event.getSourceIp(), event.getMetadata()를 쓸 수 있습니다.
        }
    }
}
