자동설정: 무엇이 켜지고 어떻게 끄나

Contexa가 애플리케이션 기동 때 무엇을 켜고 무엇을 빼는지 설명합니다. Contexa가 켜졌는지 확인하고, 기능을 끄거나 기본 빈을 내 빈으로 바꾸는 방법을 찾을 수 있습니다.

한눈에 보기: 기동 순서

contexa.*가 아닌 기본값(Spring AI · Actuator)은 Contexa가 켜졌을 때만 보입니다. 예를 들어 spring.ai.vectorstore.pgvector.initialize-schema의 기본값이 true가 되어 첫 기동 때 벡터 표를 만듭니다. 앱 설정에 같은 키가 있으면 앱 값이 이깁니다.

켜졌나, 꺼졌나

상태무엇이 일어나나
스타터만 넣음(@EnableAISecurity 없음)Contexa 자동설정 71개가 모두 빠집니다. 예외는 앱 기본 DataSource를 Contexa DB로 만드는 자동설정 하나로, contexa.datasource.url과 contexa.datasource.isolation.contexa-owned-application=true가 둘 다 있을 때만 남습니다. Spring Boot의 DataSource · JPA 자동설정은 spring.datasource.url이 있거나 내장 DB가 클래스패스에 있을 때만 남습니다. 그 밖의 자동설정은 그대로입니다.
@EnableAISecurity 있음켜짐. 아래 목록의 자동설정이 각자의 조건대로 켜집니다.
contexa.enabled가 false어노테이션이 있어도 아무것도 가져오지 않고 "켜짐" 표지도 넣지 않으므로, 스타터만 넣은 상태와 같습니다.
스타터는 Spring Security를 함께 가져옵니다. Contexa가 꺼져 있어도 Spring Boot의 보안 자동설정은 빠지지 않으므로, Spring Security를 쓰지 않던 앱은 자기 SecurityFilterChain이 없으면 Spring Boot 기본 보안(모든 요청에 인증 필요)이 걸립니다. 앱 체인을 선언해 두십시오(앱이 할 일).

조건켜지는 것

영역별 자동설정 목록(71개)

등록 파일 네 개(contexa-autoconfigure 66개 · contexa-common 2개 · contexa-core 1개 · contexa-identity 2개)에 있는 전부입니다. 모두 Contexa가 켜졌을 때만 남고, 그다음 아래 "조건"을 따집니다. "조건"은 클래스 머리의 조건이며, 안쪽 빈마다 조건이 더 있습니다. "끄는 키"를 false로 두면 그 자동설정이 빠집니다(적지 않으면 켜짐). @EnableAISecurity가 가져오는 AiSecurityConfiguration은 이 목록 밖입니다.

기동 진단 확인하기

Contexa는 기동이 끝날 때 기능마다 필요한 빈이 만들어졌는지 검사합니다. 기능을 켜는 스위치가 아니라, 빠진 것을 알리거나 기동을 멈추는 장치입니다.

contexa.capability.mode하는 일
AUTO(기본)Contexa 소유 앱이면 FAIL_FAST, 아니면 WARN. Contexa 소유 앱은 contexa.datasource.isolation.contexa-owned-application=true이거나 spring.application.name이 contexa-로 시작하는 앱입니다.
WARN필수 기능의 문제를 ERROR 로그로 알리고 기동은 계속합니다.
FAIL_FAST필수 기능이 빠지거나 실패하면 IllegalStateException으로 기동을 멈춥니다.
STRICTFAIL_FAST처럼 멈추고, 필수가 아닌 기능의 문제도 로그에 남깁니다.
OFF검사하지 않습니다.
  • 검사하는 기능 여섯: LLM_RUNTIME(채팅 모델) · EMBEDDING_RUNTIME(임베딩 모델) · RAG_VECTOR(벡터 저장소) · SECURITY_LEARNING(학습) · AUTONOMOUS_DECISION(판정 엔진) · BRIDGE(인증 브리지). 기능마다 켜짐 · 필수 여부는 환경에 따라 정해지고, contexa.capability.required.<기능>(예: rag-vector)로 바꿀 수 있습니다.
  • 엔터프라이즈 기능 넷(PQA_ENGINE · ENTERPRISE_SOAR · ENTERPRISE_MCP · ENTERPRISE_DASHBOARD)은 이름과 켜짐 규칙만 있고 OSS에는 검사기가 없습니다. 예를 들어 SOAR는 contexa.enterprise.enabled=true이고 엔터프라이즈 SOAR 모듈이 있어야 켜집니다(SOAR 확장점).
  • 로그: 문제가 있으면 [ContexaCapability] <기능> ... 줄이 ERROR로 나옵니다. 앱에 CapabilityContributor 빈을 두면 그 검사도 함께 돕니다.
  • Actuator: 엔드포인트 contexacapabilities가 실효 모드와 문제 목록을 보여 줍니다. 웹으로 보이게 할지는 Spring Boot Actuator 노출 설정을 따릅니다.

빈 바꿔 끼우기

아래 빈은 같은 타입(또는 같은 이름)의 빈을 앱이 선언하면 Contexa 기본 구현이 물러납니다.

앱이 선언하는 빈쓰는 때
PlatformConfig보안 모드의 기본 인증 구성 대신 내 구성을 쓸 때(CONTEXA_OWNED에서만 체인이 됨, Identity DSL)
ZeroTrustActionRepository · BaselineDataStore · SecurityContextDataStore · ProtectableRapidReentryRepository판정 · 기준선 · 문맥 · 재진입 기록을 다른 곳에 둘 때. 단독 모드에서도 영속 저장을 쓸 수 있고, 학습 저장소를 주면 단독 모드 WARN이 사라집니다.
SecurityEventCollector · SecurityEventPublisher · BlockingSignalBroadcaster사건 · 차단 신호를 다른 전송 수단으로 보낼 때
MfaSessionRepositoryMFA 세션 저장소를 바꿀 때
ContexaCacheServiceContexa 캐시 구현을 바꿀 때
이름이 정해진 데이터 빈 다섯contexaDataSource · contexaEntityManagerFactory · contexaTransactionManager · contexaTransactionTemplate · contexaJdbcTemplate. Contexa 데이터 연결을 직접 만들 때. contexaDataSource를 직접 주면 contexa.datasource.url 검사를 거치지 않습니다.
ContexaJpaManagedPackageProviderContexa 전용 영속 단위에 엔티티 패키지를 더할 때
LockProviderShedLock 락 제공자를 바꿀 때
AuthBridge인증 브리지가 사용자를 꺼내는 방법을 바꿀 때(인증 브리지)
CapabilityContributor기동 진단에 검사를 더할 때(기본 검사기와 함께 돎)
