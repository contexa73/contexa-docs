Spring Boot용 오픈소스 인증 이후 런타임 보안

로그인 이후의 위협을 요청 단위로 탐지하고 대응합니다

계정 탈취와 내부자의 권한 남용은 로그인과 권한 검사를 그대로 통과합니다. CONTEXA는 보호 대상 요청마다 AI가 사용자별 행위 기준선(학습한 일하는 시간 · 단말 · 접근 대상)과 업무 컨텍스트(결재 · 티켓 같은 업무 기록)를 분석해 허용, 추가 인증, 검토 보류, 차단 중 하나로 대응합니다.

  • Spring Boot 앱에 붙이는 라이브러리
  • 사람과 AI 에이전트 모두

CONTEXA가 다른 점

로그인은 신원을, 권한 검사는 접근 범위를 확인합니다. CONTEXA는 그다음 단계에서 지금의 요청이 계정 소유자의 정상 업무인지 요청마다 판정합니다.

기존 앱에 그대로 붙입니다

기본 방식에서는 앱이 로그인을 계속 담당하므로 앱의 로그인과 Spring Security 설정이 바뀌지 않습니다. 도입할 때는 관찰 모드(SHADOW)로 판정을 확인한 뒤 적용 모드(ENFORCE)로 전환하는 순서를 권장합니다.

  1. 의존성 spring-boot-starter-contexa 추가
  2. 전용 DB와 AI 모델 연결
  3. @EnableAISecurity로 활성화하고 @Protectable로 보호 대상 메서드 지정
시작하기
Java 
@SpringBootApplication
@EnableAISecurity
public class MyApplication { ... }

@Service
public class ReportService {

    @Protectable
    public Report export(Long customerId) { ... }
